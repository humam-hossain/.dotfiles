## 2. Core Architectural Patterns

### Pattern 1: Declarative Polling Timer & History Allocation Gating
**Target:** `restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml`  
**Analog:** `HardwareTelemetry.qml:17-23`  
**Decisions Addressed:** D-02, D-03

#### Problem Description
In `ResourceUsage.qml:74-113`, the timer was initialized to `interval: 1` and imperatively reset to `3000` inside `onTriggered`. In QtQuick's QJSEngine event loop, modifying `interval` on an already active repeating timer does not immediately reconfigure the kernel timer, resulting in continuous rapid firing at 60–100Hz (~3,120 read syscalls/s). Additionally, `updateHistories()` allocated new arrays via `[...history, val]` on every tick regardless of whether any chart or inspector was visible, generating continuous V8 heap churn and GC pauses.

#### Target Architecture
1. Declare a top-level property: `property bool isInspectorActive: false`.
2. Initialize `Timer.interval` declaratively to `root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)`.
3. Eliminate the imperative `interval = ...` reassignment inside `onTriggered`.
4. Trigger the initial metric sample synchronously via `Component.onCompleted: root.pollMetrics()`.
5. Gate `root.updateHistories()` behind `if (root.isInspectorActive)`.

#### Concrete Code Excerpt

##### Before (`restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml:74-113`)
```qml
    Timer {
        interval: 1
        running: true 
        repeat: true
        onTriggered: {
            // Reload virtual files
            fileMeminfo.reload();
            fileStat.reload();

            // Parse memory and swap usage (D-15 extended fields)
            const textMeminfo = fileMeminfo.text();
            memoryTotal = Number(textMeminfo.match(/MemTotal:\s*(\d+)/)?.[1] ?? 1);
            // ... parsing meminfo ...

            // Parse CPU usage
            const textStat = fileStat.text();
            // ... parsing /proc/stat ...

            root.updateHistories();
            interval = Config?.options?.resources?.updateInterval ?? 3000;
        }
    }
```

##### Target Pattern (`restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml`)
```qml
    property bool isInspectorActive: false

    function pollMetrics() {
        // Reload virtual files
        fileMeminfo.reload();
        fileStat.reload();

        // Parse memory and swap usage
        const textMeminfo = fileMeminfo.text();
        memoryTotal = Number(textMeminfo.match(/MemTotal:\s*(\d+)/)?.[1] ?? 1);
        memoryAvailable = Number(textMeminfo.match(/MemAvailable:\s*(\d+)/)?.[1] ?? 0);
        memoryFree = memoryAvailable;
        memoryBuffers = Number(textMeminfo.match(/Buffers:\s*(\d+)/)?.[1] ?? 0);
        memoryCached = Number(textMeminfo.match(/^Cached:\s*(\d+)/m)?.[1] ?? 0);
        swapTotal = Number(textMeminfo.match(/SwapTotal:\s*(\d+)/)?.[1] ?? 1);
        swapFree = Number(textMeminfo.match(/SwapFree:\s*(\d+)/)?.[1] ?? 0);

        // Parse CPU usage
        const textStat = fileStat.text();
        const cpuLine = textStat.match(/^cpu\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)/);
        if (cpuLine) {
            const stats = cpuLine.slice(1).map(Number);
            const total = stats.reduce((a, b) => a + b, 0);
            const idle = stats[3];

            if (previousCpuStats) {
                const totalDiff = total - previousCpuStats.total;
                const idleDiff = idle - previousCpuStats.idle;
                cpuUsage = totalDiff > 0 ? (1 - idleDiff / totalDiff) : 0;
            }

            previousCpuStats = { total, idle };
        }

        // Gate history allocations to eliminate idle GC heap churn (D-03)
        if (root.isInspectorActive) {
            root.updateHistories();
        }
    }

    Timer {
        id: pollTimer
        interval: root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)
        running: true
        repeat: true
        onTriggered: root.pollMetrics()
    }

    Component.onCompleted: {
        root.pollMetrics();
    }
```

### Pattern 2: Two-Tier Demand-Gated Sweeping & Zero-Latency First Frame
**Target:** `restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml`  
**Analog:** Existing `fastPollingRequests` counter in `HardwareTelemetry.qml:14-16`  
**Decisions Addressed:** D-05, D-06, D-07, D-08

#### Problem Description
`HardwareTelemetry.qml` maintains 31 `FileView` instances. In idle state, the status bar pill only displays `overallCpuLoad` (from `/proc/stat`), `packageTemp` (from `temp1_input`), and `gpuLoad` (from `rc6_residency_ms`). Sweeping all 31 files on every tick (including 14 coretemp files, 6 motherboard files, 2 NVMe files, and running a 20-thread regex loop across `/proc/cpuinfo`) wastes CPU cycles, context switches, and memory bandwidth. However, if Tier 2 polling simply waits for the next timer tick when the user opens the inspector popup, the UI exhibits a noticeable visual lag (up to 1000ms delay) showing stale or empty `0` metrics on frame 0.

#### Target Architecture
1. **Tier 1 (`pollTier1()`):** Sweeps strictly the 3 files necessary for the status bar pill:
   - `fileProcStat.reload()` $\rightarrow$ parses aggregate `"cpu "` line $\rightarrow$ `overallCpuLoad`.
   - `filePackageTemp.reload()` $\rightarrow$ parses `temp1_input` $\rightarrow$ `packageTemp`.
   - `fileGpuRc6.reload()` $\rightarrow$ parses `rc6_residency_ms` $\rightarrow$ `gpuLoad`.
2. **Tier 2 (`pollTier2()`):** Sweeps the remaining 28 files strictly when `fastPollingRequests > 0`:
   - `fileCpuInfo.reload()` $\rightarrow$ parses cluster frequencies (`pCoreFrequencyMhz`, `eCoreFrequencyMhz`).
   - `fileEpp.reload()`, `fileGov.reload()` $\rightarrow$ scaling governor & EPP.
   - `fileGpuFreq.reload()`, `fileGpuCurFreq.reload()`, `fileGpuThrottle.reload()` $\rightarrow$ GPU clock & throttle.
   - Coretemp core inputs $\rightarrow$ `pCoreTempAvg`, `eCoreTempAvg`.
   - NVMe inputs $\rightarrow$ `nvme1Temp`, `nvme2Temp`.
   - Motherboard inputs $\rightarrow$ platform sensor temps.
3. **Zero-Latency First Frame (D-06):** In `onFastPollingRequestsChanged`, when `fastPollingRequests === 1`, immediately execute `root.pollTier2()` synchronously. Frame 0 is rendered with instant, fresh data with 0ms visual delay.

#### Concrete Code Excerpt

##### Before (`restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml:481-489`)
```javascript
    function pollAll() {
        try { updateCpuLoad(); } catch (e) { console.warn("updateCpuLoad error:", e); }
        try { updateFrequencies(); } catch (e) { console.warn("updateFrequencies error:", e); }
        try { updateGovernors(); } catch (e) { console.warn("updateGovernors error:", e); }
        try { updateGpuMetrics(); } catch (e) { console.warn("updateGpuMetrics error:", e); }
        try { updateThermals(); } catch (e) { console.warn("updateThermals error:", e); }
    }
```

##### Target Pattern (`restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml`)
```qml
    property int fastPollingRequests: 0
    readonly property bool fastPolling: fastPollingRequests > 0 || overallCpuLoad > 0.50

    onFastPollingRequestsChanged: {
        if (fastPollingRequests === 1) {
            // Immediate synchronous Tier 2 sweep for zero-latency frame 0 (D-06)
            root.pollTier2();
        }
    }

    Timer {
        id: pollTimer
        interval: root.fastPolling ? 1000 : 3000
        repeat: true
        running: true
        onTriggered: root.pollAll()
    }

    function pollAll() {
        pollTier1();
        if (root.fastPollingRequests > 0) {
            pollTier2();
        }
    }

    function pollTier1() {
        try { updateCpuLoadTier1(); } catch (e) { console.warn("updateCpuLoadTier1 error:", e); }
        try { updateGpuRc6Tier1(); } catch (e) { console.warn("updateGpuRc6Tier1 error:", e); }
        try { updatePackageTempTier1(); } catch (e) { console.warn("updatePackageTempTier1 error:", e); }
    }

    function pollTier2() {
        try { updateCpuLoadTier2(); } catch (e) { console.warn("updateCpuLoadTier2 error:", e); }
        try { updateFrequencies(); } catch (e) { console.warn("updateFrequencies error:", e); }
        try { updateGovernors(); } catch (e) { console.warn("updateGovernors error:", e); }
        try { updateGpuMetricsTier2(); } catch (e) { console.warn("updateGpuMetricsTier2 error:", e); }
        try { updateThermalsTier2(); } catch (e) { console.warn("updateThermalsTier2 error:", e); }
    }

    // Tier 1 CPU parser: Only parses aggregate line 1 ("cpu ") from /proc/stat
    function updateCpuLoadTier1() {
        fileProcStat.reload();
        const text = fileProcStat.text();
        if (!text) return;
        const line = text.slice(0, text.indexOf("\n")).trim();
        if (!line.startsWith("cpu ")) return;
        const parts = line.split(/\s+/);
        const total = parts.slice(1, 9).reduce((acc, val) => acc + (parseFloat(val) || 0), 0);
        const idle = (parseFloat(parts[4]) || 0) + (parseFloat(parts[5]) || 0);
        const active = total - idle;

        const prev = prevCpuTicks["cpu"];
        if (prev) {
            const dTotal = total - prev.total;
            const dActive = active - prev.active;
            overallCpuLoad = dTotal > 0 ? Math.max(0.0, Math.min(1.0, dActive / dTotal)) : 0.0;
        }
        prevCpuTicks["cpu"] = { total: total, active: active };
    }

    // Tier 1 GPU RC6: Only parses rc6_residency_ms for load estimation
    function updateGpuRc6Tier1() {
        fileGpuRc6.reload();
        const now = Date.now();
        const rc6 = parseFloat(fileGpuRc6.text().trim());
        if (!isNaN(rc6) && lastGpuSampleTime > 0 && lastRc6Ms > 0) {
            const dt = now - lastGpuSampleTime;
            const dRc6 = rc6 - lastRc6Ms;
            if (dt > 100) {
                const idleRatio = Math.max(0.0, Math.min(1.0, dRc6 / dt));
                const instantLoad = Math.max(0.0, Math.min(1.0, 1.0 - idleRatio));
                gpuLoad = (gpuLoad === 0.0) ? instantLoad : (0.4 * instantLoad + 0.6 * gpuLoad);
            }
        }
        lastGpuSampleTime = now;
        lastRc6Ms = rc6;
    }

    // Tier 1 Package Temp: Only parses temp1_input
    function updatePackageTempTier1() {
        filePackageTemp.reload();
        const pkgRaw = parseInt(filePackageTemp.text().trim(), 10);
        packageTemp = isNaN(pkgRaw) ? 0 : Math.round(pkgRaw / 1000.0);
    }
```

### Pattern 4: Cluster Summary Layout in `CpuGpuPopup.qml`
**Target:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml`  
**Analog:** `MetricProgressRow` reusable component  
**Decisions Addressed:** D-09

#### Problem Description
`CpuGpuPopup.qml:243-278` instantiates 20 individual `ThreadMeter` items (12 P-threads, 8 E-threads) via `Repeater`. Each meter contained 4 `StyledText` items and 2 `Rectangle` items. Updating 20 meters every 1000ms caused:
- 20 progress bar width re-evaluations
- 20 load percentage string allocations
- 20 frequency string allocations
- 14 core temperature string allocations
- A 20-thread regex loop across `/proc/cpuinfo` in `HardwareTelemetry.qml`
This pushed Intel UHD 770 iGPU load from 12.00% to 26.41% (+14.41% GPU rendering load).

#### Target Architecture
Replace the 20 individual `ThreadMeter` items with 3 clean, high-level cluster summary meters:
1. **Overall CPU:** Utilization %, Combined Average Frequency (MHz), Package Temp (°C).
2. **P-Core Performance Cluster:** Aggregate P-core utilization (8 P-cores / 16 threads), Average P-Core Frequency (MHz), Average P-Core Temp (°C).
3. **E-Core Efficiency Cluster:** Aggregate E-core utilization (4 E-cores / 4 threads), Average E-Core Frequency (MHz), Average E-Core Temp (°C).
*Scenegraph reduction:* Slashes item count from 120+ down to ~15, eliminates the 20-thread regex loop, and provides superior human legibility for the Alder Lake hybrid architecture.

### Pattern 5: Strict Critical Pulse Animation Gating
**Target:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml` & `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPill.qml`  
**Analog:** Animation controllers in `CpuGpuPill.qml:83-107`  
**Decisions Addressed:** D-10

#### Problem Description
In `CpuGpuPopup.qml:187-207`, `popupCriticalPulse` declared:
`running: (HardwareTelemetry.overallCpuLoad || 0.0) >= 0.90 || (HardwareTelemetry.packageTemp || 0) >= 80 || (HardwareTelemetry.gpuLoad || 0.0) >= 0.90`
It was **not** gated on `root.active`. If system telemetry exceeded critical thresholds while the popup was closed, the 60 FPS animation ticker fired continuously in the background, waking the GPU and driving up compositor wakeups.

#### Target Architecture
- In `CpuGpuPopup.qml`: Enforce `running: root.active && root.isCritical`.
- In both components: Guarantee that when the animation stops (`onRunningChanged: if (!running)`), opacity resets to `1.0`.

### Pattern 6: 1% Integer Deadband Quantization & Inactivity Binding Guards
**Target:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPill.qml` & `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml`  
**Analog:** Progress value binding expressions in `CpuGpuPill.qml:56, 150`  
**Decisions Addressed:** D-11, D-12

#### Problem Description
Unquantized fractional values (e.g. `0.231948`) cause the QtQuick scenegraph renderer to continuously compute floating-point vertex buffer deltas and re-tesselate OpenGL/Vulkan primitives on every timer tick. In `CpuGpuPopup.qml`, properties bound directly to `HardwareTelemetry` evaluate even when the popup is hidden (`root.active === false`).

#### Target Architecture
1. Apply 1% integer deadband quantization to progress meter widths and values: `Math.round(val * 100) / 100`.
2. Guard inner bindings and string evaluations in `CpuGpuPopup.qml` on `root.active ? <expr> : <default>`.

## 3. Pitfalls and Mitigations Checklist

| # | Pitfall | Mechanism | Prevention / Mitigation |
|---|---|---|---|
| 1 | **Breaking Assertion Suite** | `scripts/phase43-cpu-gpu-assert.sh` checks for `ThreadMeter` and specific title strings. | Update `scripts/phase43-cpu-gpu-assert.sh` to validate the refined cluster summary layout and retain title compatibility (`P-Cores (12T)`, `E-Cores (8T)`). |
| 2 | **Refcount Leak in `fastPollingRequests`** | Missing decrement on rapid popup close or window destroy locks telemetry in active 1000ms mode. | Ensure `CpuGpuPopup.qml` retains both `onActiveChanged` paired increment/decrement and `Component.onDestruction: if (active) HardwareTelemetry.fastPollingRequests--;`. |
| 3 | **Sub-tick Stale UI (Frame 0 Stutter)** | Opening popup while Tier 2 sensors are idle shows 0% / empty values until the next timer tick. | In `HardwareTelemetry.qml`, observe `fastPollingRequestsChanged`: when `fastPollingRequests === 1`, immediately execute `pollTier2()` synchronously (D-06). |
| 4 | **Sub-pixel GPU Re-Tessellation Churn** | Unquantized floats (`0.2341258`) force OpenGL/Vulkan vertex re-evaluations on every tick. | Apply 1% integer deadband quantization (`Math.round(val * 100) / 100`) across all progress bar bindings (D-11). |
| 5 | **Dirty Git Working Tree** | Profiling script overwrites benchmark files or leaves unstowed files behind. | Run `./arch/dots-hyprland.sh verify --strict` and inspect `git status --porcelain`. Profile harness cleans up temporary files in signal trap. |
| 6 | **Wayland Socket Collisions** | Restarting Quickshell too quickly before old process exits leaves Unix socket locked. | Use `wait_for_pid_exit` and poll socket release before launching a new Quickshell instance (handled by `profile-quickshell.sh`). |
