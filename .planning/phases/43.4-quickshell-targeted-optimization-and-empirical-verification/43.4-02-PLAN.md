# Plan 43.4-02: UI & Popup Scenegraph Optimization & Assertion Alignment

<objective>
Drastically reduce active Intel UHD 770 iGPU rendering overhead and eliminate background GPU animation wakeups by refactoring `CpuGpuPopup.qml` to use a 3-Cluster Summary Layout (Overall CPU, P-Core cluster, E-Core cluster) in place of 20 individual `ThreadMeter` items, enforcing strict condition gating (`running: root.active && root.isCritical`) on alert pulse animations, applying 1% integer deadband quantization (`Math.round(val * 100) / 100`) to progress bar bindings, guarding all popup property evaluations on `root.active`, and updating `scripts/phase43-cpu-gpu-assert.sh` to validate the optimized scenegraph architecture.
</objective>

<threat_model>
### ASVS L1 Threat Model Evaluation

- **Denial of Service via GPU Rendering Overload & Compositor Stutter:** In Phase 43.2 baseline profiling, opening the hardware popup increased Intel UHD 770 iGPU load from 12.00% to 26.41% (+14.41%), driven by 120+ scenegraph items across 20 individual thread bars and sub-pixel retessellation. Collapsing the scenegraph to 3 cluster summary meters and quantizing progress bar widths bounds GPU load within acceptable margins (<15% active delta).
- **Background CPU/GPU Wakeups from Continuous 60 FPS Tickers:** The popup's critical pulse animation previously lacked an active visibility guard (`running: root.isCritical`), meaning elevated temperatures or loads while the popup was closed would trigger a perpetual 60 FPS animation ticker in the background. Enforcing `running: root.active && root.isCritical` guarantees zero animation tickers when the popup is dormant.
- **Visual Jitter & State Bleed on Popup Close:** Failing to reset item opacity when animations terminate can leave UI elements stuck in a semi-transparent state (e.g. 0.4 opacity). Adding explicit `onRunningChanged: if (!running) root.criticalPulseOpacity = 1.0;` ensures clean, predictable visual resets.
- **Floating-Point Precision Vulnerabilities & Sub-pixel Geometry Thrash:** Microscopic floating-point changes in telemetry readings (e.g. 0.231948 -> 0.232115) trigger constant vertex geometry recomputations in the QtQuick scenegraph. 1% deadband quantization restricts geometry updates strictly to meaningful 1% steps.
</threat_model>
