# Plan 43.4-01: Service Layer Optimizations & Bar Layout Cleanup

<objective>
Eliminate idle CPU and I/O syscall churn in Quickshell's background telemetry singletons by replacing the 1ms timer anomaly in `ResourceUsage.qml` with a declarative 3000ms idle timer, gating history array spread-copying on inspector visibility, implementing Two-Tier Demand-Gated Sweeping with zero-latency frame 0 synchronization in `HardwareTelemetry.qml`, and retiring the redundant legacy `Resources` pill from horizontal and vertical status bar layouts to clear the Left Zone for Phase 44.
</objective>

<threat_model>
### ASVS L1 Threat Model Evaluation

- **Denial of Service via Unbounded File I/O & Event Loop Starvation:** Prior to this change, `ResourceUsage.qml` scheduled virtual file reloads at 1ms intervals, generating ~3,120 read syscalls/s and consuming 3-4% idle CPU. The declarative timer fixes the interval to 3000ms idle (or 1000ms active), capping virtual file reads to <= 1 read/s during idle.
- **Memory Exhaustion via V8 Heap Churn:** Spreading array contents on every polling tick (`[...history, val]`) triggered relentless JavaScript garbage collection passes. Gating array allocations behind `root.isInspectorActive` ensures zero heap churn during idle shell operation.
- **Reference Count Leak & Permanent Active Polling:** In `HardwareTelemetry.qml`, the fast-polling state is governed by `fastPollingRequests`. If unbalanced increments occur or error handlers fail to decrement the counter, the telemetry service would permanently poll 28 files at 1000ms. Defensive guards ensure `fastPollingRequests` cannot drop below zero and that popups decrement on destruction.
- **Unprivileged Procfs/Sysfs Access & Fail-Safe Fallbacks:** All procfs/sysfs readers (`/proc/stat`, `/proc/meminfo`, DRM sysfs, hwmon coretemp) run strictly unprivileged. Missing or unreadable files fail gracefully with warning logs rather than crashing the QML runtime or dropping the status bar window.
</threat_model>
