  <decision>How is criterion 2's "no working-directory-relative path" satisfied for the script's two directory changes?</decision>
  <context>
    The research run found a second defect in `arch/hyprland.sh` that neither the phase context
    nor the roadmap records, and it blocks criterion 2 independently of the deletion this plan
    performs.

    The script changes directory into the stow tree twice, at two separate stanzas, using the
    same expression both times. The expression is evaluated from whatever the current directory
    is at that moment — and by the second stanza the first change has already moved it. So the
    second change is resolved against the wrong base and fails whenever the script was invoked
    by a relative path. With the script's error-exit setting, that aborts it non-zero.

    Four invocation forms were probed. Two of them survive the second directory change and two
    do not. The two that survive are exactly the two where the line this plan deletes has
    nothing to match — so today the script cannot complete in **any** invocation form. Deleting
    the copy makes the two surviving forms work. The other two stay broken.

    Criterion 2's wording — the file must contain no working-directory-relative path — arguably
    already reaches this expression, since it is relative whenever the invocation path is. But
    the locked decision D-01 says the directory-change idiom is kept verbatim at every site, and
    that decision predates this finding. This is yours to rule on.
  </context>
