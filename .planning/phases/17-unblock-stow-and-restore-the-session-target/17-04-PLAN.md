<objective>
Install the secret scanner from the one legitimate source, pin its sub-command spellings
against the installed binary rather than against memory, run it over both git history and
the working tree, triage every finding individually, and record both invocations in the
assert harness so the scan is re-runnable rather than a one-off observation.

Purpose: a secret scan that reports zero findings for the wrong reason is worse than no
scan. The repo demonstrably contains a tracked `.env`, so a green result that does not
account for it is a misconfiguration, not a clean bill of health.
Output: one installed package, up to one conditional config file, two new assert sections.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| package registry → local system | a new executable enters the machine and is then trusted to make a security judgement about the repo |
| git history → scan surface | history is a durable surface a working-tree-only scan does not see |
| scan output → durable record | matched values can escape into stdout, a config file, or a commit message |
