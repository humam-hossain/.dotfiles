# Plan 42-01: Hardware & Storage Telemetry Singletons

<threat_model>
- **Spoofing**: Unprivileged sysfs files could theoretically be mocked, but not securely spoofable across user spaces without root. Mitigated by using standard read-only `/proc` and `/sys` mounts.
- **Tampering**: Modifying telemetry scripts. Mitigated by restrictive directory permissions for the user account.
- **Repudiation**: Non-issue for read-only hardware telemetry.
- **Information Disclosure**: Hardware states (e.g., temperatures) might leak workload activity. Mitigated by single-user local shell context constraint.
- **Denial of Service**: High-frequency polling freezing the UI. Mitigated by asynchronous `FileView` and `Process` usage, plus D-01 adaptive polling cadence and D-08 pure I/O-driven `df` polling.
- **Elevation of Privilege**: Reading sensors might historically require root. Mitigated by D-05 (Zero Root / Wattage Omission), explicitly relying on unprivileged `/proc` and `/sys` nodes with zero `udev` rules.
</threat_model>

## Objective

Create singleton services in Quickshell for non-blocking hardware metrics and dynamic multi-mount storage usage. Implements decisions D-01 through D-11.

## Tasks

1.  **Tracer Slice: Singletons Skeleton**:
    - **Action**: Create empty `HardwareTelemetry.qml` and `StorageUsage.qml` stubs in `restow/quickshell/.config/quickshell/ii/services/`.
    - **Objective**: Scaffold the singletons with basic QML `pragma Singleton` imports.
    - **Tags**: `tracer`

2.  **HardwareTelemetry.qml Singleton Creation (D-01..D-07)**:
    - **Action**: Implement `HardwareTelemetry.qml`.
    - **Objective**: Parse `/proc/stat` to expose `pCoreLoad` (CPUs 0-11) and `eCoreLoad` (CPUs 12-19) per D-02. Expose `energyPerformancePreference` and `scalingGovernor` per D-03. Parse iGPU load from `rc6_residency_ms` per D-04. Calculate `packageTemp` and `peakSystemTemperature` per D-06 & D-07. Implement adaptive 1000ms/3000ms polling per D-01. Omit wattage per D-05.
    - **Tags**: `D-01`, `D-02`, `D-03`, `D-04`, `D-05`, `D-06`, `D-07`

3.  **StorageUsage.qml Singleton Creation (D-08..D-11)**:
    - **Action**: Implement `StorageUsage.qml`.
    - **Objective**: Implement continuous `/proc/diskstats` tracking for `diskIoPercentage` per D-09, dynamically exposing `activeDisk` per D-10. Implement pure I/O-driven `df` polling (spawning asynchronous process only on write/delete/on-demand) per D-08. Filter physical partitions and cloud FUSE mounts per D-11.
    - **Tags**: `D-08`, `D-09`, `D-10`, `D-11`
