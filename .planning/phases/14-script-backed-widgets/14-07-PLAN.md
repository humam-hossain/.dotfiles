    ```qml
            onStreamFinished: {
                const line = this.text.trim()
                if (line) {
                    // nmcli -t output: active:ssid:signal:type
                    // SSID may contain colons — use last 2 fields for signal and type
                    // First field is 'yes', last field is type, second-to-last is signal
                    // Everything between is the SSID (may contain colons)
                    const lastColon = line.lastIndexOf(":")
                    if (lastColon < 0) { root.ssid = "WiFi"; root.connected = true; return }
                    const typeEnd = line.lastIndexOf(":", lastColon - 1)
                    if (typeEnd < 0) { root.ssid = "WiFi"; root.connected = true; return }

                    const signalStr = line.substring(typeEnd + 1, lastColon)
                    const sig = parseInt(signalStr, 10) || 0
                    // SSID is everything between the first colon (after 'yes') and typeEnd
                    const firstColon = line.indexOf(":")
                    const ssid = line.substring(firstColon + 1, typeEnd) || "WiFi"

                    root.ssid      = ssid
                    root.connected = true
                    root.iconText  = sig <= 20  ? "󰤯"
                                 : sig <= 40  ? "󰤟"
                                 : sig <= 60  ? "󰤢"
                                 : sig <= 80  ? "󰤥"
                                 :               "󰤨"
                    root.tooltipText = "SSID: " + ssid + " (" + sig + "%)"
                } else {
                    ethProc.running = true
                }
            }
    ```
    This parses from the END of the line backwards: last field = type, second-to-last = signal,
    everything after the first colon = SSID (may contain colons).

  <action>
    Fix the Volume OSD popup that doesn't appear on volume change.

    **Root cause:** QS 0.2.1 has a binding propagation bug (upstream #807) where Pipewire
    readonly bindings return stale/cached values. The existing 500ms Timer reads
    `Pipewire.defaultAudioSink.audio.volume` which is a readonly binding — it always
    returns the same stale value. So `root.volume` never actually changes, volumePercentChanged
    never fires on VolumeOsd, and the popup never shows.

    **Fix:** Replace the Pipewire API polling Timer with a Process that runs `wpctl get-volume`
    every 500ms. `wpctl` is a subprocess that queries the real Pipewire daemon directly,
    bypassing QS's broken binding system.

    **Implementation steps for AudioService.qml:**

    Step 1 — Keep the Pipewire `defaultSink` readonly property AND setVolume/bumpVolume/toggleMute
    functions unchanged. These handle VOLUME WRITES to Pipewire, which work fine.
    Only READBACK is broken.

    Step 2 — Replace the existing polling Timer (lines 29-45, commenting "QS 0.2.1 workaround...")
    with a new Timer + Process that runs wpctl:

    REMOVE the existing Timer block (lines 29-45):
    ```qml
        // QS 0.2.1 workaround: Pipewire readonly binding propagation broken (issue #807)
        // Polling Timer reads Pipewire API directly and updates writable properties.
        // This triggers volumePercentChanged() downstream → VolumeOsd.show()
        Timer {
            interval: 500
            running: true
            repeat: true
            triggeredOnStart: true
            onTriggered: {
                const sink = Pipewire.defaultAudioSink
                if (!sink || !sink.audio) return
                root.volume = sink.audio.volume
                root.muted = sink.audio.muted
                root.volumePercent = Math.round(sink.audio.volume * 100)
                root.sinkName = sink.description || sink.name || "Audio"
            }
        }
    ```

    REPLACE with:
    ```qml
        // QS 0.2.1 workaround: Pipewire readonly binding propagation broken (issue #807)
        // Poll via wpctl subprocess instead of reading Pipewire API directly.
        // wpctl returns real daemon state, bypassing QS binding cache.
        Timer {
            interval: 500
            running: true
            repeat: true
            triggeredOnStart: true
            onTriggered: {
                wpctlProc.running = true
            }
        }

        Process {
            id: wpctlProc
            command: ["bash", "-c", "wpctl get-volume @DEFAULT_AUDIO_SINK@"]
            running: false
            stdout: StdioCollector {
                onStreamFinished: {
                    const out = this.text.trim()
                    const match = out.match(/Volume:\s*([\d.]+)/)
                    if (!match) return
                    const vol = parseFloat(match[1])
                    if (isNaN(vol)) return

                    const rounded = Math.round(vol * 100) / 100
                    root.muted = out.includes("[MUTED]")

                    // Detect real volume change to trigger VolumeOsd
                    if (Math.abs(root.volume - rounded) > 0.001) {
                        root.volume = rounded
                        root.volumePercent = Math.round(rounded * 100)
                        root.sinkName = "Default Audio Sink"
                    }
                }
            }
        }
    ```

    Step 3 — Keep the existing `property real volume: 0.0`, `property bool muted: false`,
    `property int volumePercent: 0`, `property string sinkName: ""` as-is (already writable
    from the 14-05 fix). No changes needed to property declarations.

    Step 4 — Keep `PwObjectTracker` as-is (needed for Pipewire object lifecycle).

    **VolumeOsd.qml check:**
    No changes should be needed — it already has:
    ```qml
    property int volumePercent: AudioService.volumePercent
    onVolumePercentChanged: show()
    ```
    When wpctl detects a REAL volume change and updates `AudioService.volumePercent`,
    the VolumeOsd binding re-evaluates, `onVolumePercentChanged` fires, and `show()`
    displays the popup.

    However, apply the IN-01 cleanup from the 14-05 code review (non-functional but correct):
    Change line 35 from:
      width: parent.width * (AudioService.volume / 1.0)
    To:
      width: parent.width * AudioService.volume

    (AudioService.volume is already a 0.0-1.0 real value — dividing by 1.0 is a no-op.)

    **Note on first startup:** The Timer has `triggeredOnStart: true`, so the first wpctl
    poll fires immediately on component creation. This will set volume from default 0.0 to
    the actual hardware value. If the hardware volume differs from 0 (nearly always), the
    change will briefly trigger VolumeOsd.show() on startup. This is acceptable — it's a
    one-time flash when Quickshell starts (rare occurrence).
  </action>
