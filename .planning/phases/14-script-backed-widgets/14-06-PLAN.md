    Investigate root cause of CPU widget showing "err" despite correct-looking awk /proc/stat command.

    **Phase 1 — Investigation (empirical):**

    Step 1a: Run the awk command standalone to verify it produces output:
    ```
    awk '/^cpu / {print $5, $2+$3+$4+$5}' /proc/stat
    ```
    Expected output format: "12345678 98765432" (two space-separated integers).
    If this fails or produces unexpected output, that IS the root cause — fix the awk command.

    Step 1b: Add debug console.warn() logging at each decision point in CpuService.qml's onStreamFinished.
    Insert these lines BEFORE the try block (around line 27):
    ```
            onStreamFinished: {
                console.warn("CPU: stdout text:", JSON.stringify(this.text.trim()))
                console.warn("CPU: text.length:", this.text.trim().length)
                try {
                    const parts = this.text.trim().split(/\s+/)
                    console.warn("CPU: parts:", JSON.stringify(parts), "length:", parts.length)
    ```
    And at the error branches:
    ```
                    if (parts.length < 2) { root.cpuPercentFormatted = "err"; console.warn("CPU: parts < 2"); return }
                    ...
                    if (isNaN(idle) || isNaN(total)) { root.cpuPercentFormatted = "err"; console.warn("CPU: NaN: idle=", idle, "total=", total); return }
    ```
    And in the catch block:
    ```
                } catch (e) {
                    root.cpuPercentFormatted = "err"
                    console.warn("CPU: exception:", e)
                }
    ```

    Step 1c: If the awk command produces correct output but the process returns empty text,
    the issue is in QS 0.2.1 Process/StdioCollector integration. Try a minimal test:
    - Change command temporarily to ["bash", "-c", "echo test 42 99"]
    - If this works (shows test data), the awk command specifically fails
    - If this also shows "err", the Process/StdioCollector pattern itself is broken

    **Phase 2 — Fix (based on investigation results):**

    Apply the fix deterministically based on what the investigation reveals:

    CASE A — StdioCollector.onStreamFinished fires before process completes:
    - The process hasn't produced output yet when onStreamFinished fires
    - Fix: Add a `__pending` flag. Set `__pending = true` when starting process.
      In onStreamFinished, check `if (!root.__pending) return`.
      Set `__pending = false` when output is received.
      Then start the process manually from the Timer handler instead of using triggeredOnStart.

    CASE B — Awk command produces no output in QS environment:
    - Shell command doesn't produce stdout through StdioCollector
    - Fix: Wrap in an explicit echo or cat pipe to force stdout capture:
      Change to: ["bash", "-c", "awk '/^cpu / {print $5, $2+$3+$4+$5}' /proc/stat || echo '0 0'"]
      This ensures the process always outputs something, even if awk fails.

    CASE C — Parsing logic fails on actual output format:
    - Awk output has unexpected format (extra whitespace, different delimiter, etc.)
    - Fix: Adjust parsing logic to handle the actual format. Use more robust regex:
      Change `this.text.trim().split(/\s+/)` to `this.text.trim().match(/\d+/g)`
      Then check `if (!parts || parts.length < 2)`

    CASE D — TriggeredOnStart race condition:
    - Timer with triggeredOnStart fires before Process is fully initialized
    - Fix: Change `onTriggered: proc.running = true` to check if Process is ready:
      Or add a Component.onCompleted that starts the timer after a short delay

    **After applying the fix, REMOVE the debug console.warn() lines added in Phase 1.**
    (Keep only functional changes. Do not leave debug logging in production code.)

    Verify the fix by re-running the standalone awk command and confirming the expected output.

    Investigate root cause of Disk widget showing "err" despite df -h command (no Qt.getenv dependency).

    **Pre-identified probable bug:** Line 29 checks `parts.length === 3` but the awk printf outputs
    only 2 pipe-delimited fields (e.g., "1.5G/100G|15"). Split by "|" produces 2 elements, which !== 3,
    so the else branch sets root.text = "err". This is the primary hypothesis.

    **Phase 1 — Investigation:**

    Step 1a: Run the df command standalone to verify output format:
    ```
    df -h / | awk 'NR==2 {printf "%s/%s|%d", $3, $2, $5}'
    ```
    Expected output: e.g., "1.5G/100G|15" (2 pipe-delimited fields).
    Count the number of fields separated by "|". If it's 2, the hypothesis is confirmed.

    Step 1b: If the command produces different output (e.g., 3+ pipe-delimited fields),
    the bug is somewhere else. Add debug logging similar to Task 2:
    ```
            onStreamFinished: {
                console.warn("DISK: stdout text:", JSON.stringify(this.text.trim()))
                try {
                    const parts = this.text.trim().split("|")
                    console.warn("DISK: parts:", JSON.stringify(parts), "length:", parts.length)
    ```

    Step 1c: Run `df -h /` alone and check the actual output format (column positions):
    ```
    df -h /
    ```
    Confirm columns: $2 (total), $3 (used), $4 (avail), $5 (use%).
    If column numbering differs (e.g., different locale output format), adjust the awk command.

    **Phase 2 — Fix:**

    The fix depends on the investigation outcome:

    CASE A — Confirmed: awk outputs 2 pipe-delimited fields (probable):
    Change the parsing from `parts.length === 3` to `parts.length >= 2`:
    ```qml
                    const parts = this.text.trim().split("|")
                    if (parts.length >= 2) {
                        root.text    = parts[0]
                        root.percent = parseInt(parts[1], 10) || 0
                        root.tooltip = "Disk: " + root.text + " (" + root.percent + "%)"
                    } else {
                        root.text = "err"
                    }
    ```
    (parts[0] already contains "used/total" format from awk printf "%s/%s|%d")

    CASE B — Awk output has unexpected column positions:
    Fix the awk column references to match actual df output.
    For locale-independent output, add `LANG=C` or `LC_ALL=C` prefix:
    Change command to: ["bash", "-c", "LC_ALL=C df -h / | awk 'NR==2 {printf \"%s/%s|%d\", $3, $2, $5}'"]

    CASE C — Process never completes / StdioCollector empty:
    Same approach as CPU Task 2 Case A/B. Add fallback output or fix timing.
