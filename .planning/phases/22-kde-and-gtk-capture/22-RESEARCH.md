## Summary

Phase 22 captures the remaining personal GUI configurations for KDE (Dolphin/KIO) and GTK (GTK3/GTK4), resolves the five long-standing open research questions (Q6, Q7, Q8, Q10, Q11), and formalizes the theme exclusion boundary via a machine-readable data contract (`guard-paths.tsv`) enforced by `arch/dots-hyprland.sh verify`.

The primary technical discoveries and resolutions in this phase are:
1. **KConfig Symlink Write-Through & File Modes (Q10, Q11):** Tested in scratch with `/usr/bin/kwriteconfig6`. KConfig resolves symlinks and writes directly through to the target without breaking symlinks. Git ignores changes between file mode `0644` and `0600` because git's index records only the executable bit (`100644`). KConfig's internal `setPermissions` maintains `0600` on disk without creating git diffs, rendering bootstrap chmod scripts unnecessary.
2. **Theming Pipeline Activity & `kdeglobals` Disposition (Q7, Q8):** Verified that `kde-material-you-colors` is installed in `/home/pera/.local/state/quickshell/.venv/bin/kde-material-you-colors` and called by `switchwall.sh:58` via `kde-material-you-colors-wrapper.sh` whenever wallpaper changes. This caused constant churn in `restow/kdeglobals/.config/kdeglobals`. Retiring `kdeglobals` to `docs/archive/kdeglobals` and converting `~/.config/kdeglobals` to a regular unmanaged local file permanently stops repo churn. For GTK4, `~/.config/gtk-4.0/gtk.css` is a symlink to `/usr/share/themes/catppuccin-mocha-teal-standard+default/gtk-4.0/gtk.css` owned by `root:root (0644)`. Both `gtk.css` paths are excluded from the repository.
3. **GTK Link Severance Risk (Q6) & Granular Stow Layout:** Demonstrated via Python GLib `GLib.file_set_contents` that atomic file replacement severs symlinks. GTK files (`settings.ini`, `bookmarks`) are managed strictly per-file using `stow/gtk/` with `--no-folding`. If a GTK file chooser severs `bookmarks`, `arch/dots-hyprland.sh verify` detects it as a broken symlink, recoverable via a re-stow.
4. **Cp-Through Restow Packaging (KDE-03):** `chrome-flags.conf` is packaged into `restow/chrome-flags/.config/chrome-flags.conf`. Because upstream's `3.files.sh` uses `cp -f`, running `install-files` writes through the symlink into the repo. Regenerating `restow/README.md` via `scripts/gen-collision-map.sh --restow-table` records the exact `git checkout` recovery command.

**Primary recommendation:** Implement Phase 22 across four focused plans: (1) scaffold `scripts/phase22-kde-and-gtk-capture-assert.sh`, (2) adopt `stow/kde` and `stow/gtk` per-file with `--no-folding` and SAFE-01, (3) package `restow/chrome-flags`, regenerate `restow/README.md`, and execute the live cp-through drill, and (4) retire `kdeglobals` to `docs/archive/`, establish `guard-paths.tsv`, wire GUARD assertions into `verify`, and pass the phase gate.

### Pattern 1: SAFE-01 Live Adoption Protocol with Inode Identity Assertion
**What:** Adopt live configuration files into GNU Stow packages without data loss or race conditions.  
**When to use:** Stowing existing unmanaged live files for the first time.  
**Example:**
```bash
# 1. Take timestamped backup of live file
EPOCH="$(date +%s)"
cp -a "$HOME/.config/kiorc" "$HOME/.config/kiorc.bak.$EPOCH"

# 2. Copy live file into repo stow tree
mkdir -p "$REPO_ROOT/stow/kde/.config"
cp -a "$HOME/.config/kiorc" "$REPO_ROOT/stow/kde/.config/kiorc"

# 3. Dry run stow
stow -n --no-folding -d "$REPO_ROOT/stow" -t "$HOME" kde

# 4. Remove live file and link
rm "$HOME/.config/kiorc"
stow --verbose=5 --no-folding -d "$REPO_ROOT/stow" -t "$HOME" kde

# 5. Assert inode identity
test "$(stat -c %i "$HOME/.config/kiorc")" -eq "$(stat -c %i "$REPO_ROOT/stow/kde/.config/kiorc")"
test -L "$HOME/.config/kiorc"
```

### Pattern 2: Guarded Paths TSV Verification Gate in Link-Aware Verify
**What:** Reading `guard-paths.tsv` in `run_verify()` to assert that excluded theme files are neither in repo trees nor symlinked from the live system into the repo.  
**When to use:** In `arch/dots-hyprland.sh run_verify()` before or during tree walks.  
**Example:**
```bash
# Verify GUARD paths
local guard_file="$main_root/guard-paths.tsv"
if [[ -f "$guard_file" ]]; then
  local g_path g_cat g_gen g_reason expanded live_target
  while IFS=$'\t' read -r g_path g_cat g_gen g_reason || [[ -n "$g_path" ]]; do
    [[ -n "$g_path" && "$g_path" != \#* ]] || continue
    expanded="${g_path//\$XDG_CONFIG_HOME/$HOME\/.config}"
    expanded="${expanded//\$HOME/$HOME}"
    
    # Assert not in stow/, restow/, or capture/
    local rel_sub="${expanded#"$HOME"/}"
    for tree in stow restow capture; do
      if [[ -d "$main_root/$tree" ]]; then
        for pkg_dir in "$main_root/$tree"/*; do
          [[ -d "$pkg_dir" ]] || continue
          if [[ -e "$pkg_dir/$rel_sub" ]]; then
            fail "guard path tracked in $tree: $pkg_dir/$rel_sub"
          fi
        done
      fi
    done
    
    # Assert live path is not a symlink into repo
    if [[ -L "$expanded" ]]; then
      live_target="$(readlink -f -- "$expanded" 2>/dev/null || true)"
      if [[ "$live_target" == "$main_root_real"/* ]]; then
        fail "guard path live counterpart symlinks into repo: $expanded -> $live_target"
      fi
    fi
    pass "guard path excluded: $g_path"
  done < "$guard_file"
fi
```

## Common Pitfalls

### Pitfall 1: Directory Folding Destroying Live Files
**What goes wrong:** GNU Stow defaults to directory folding: if a directory in a stow package does not exist on the target, Stow replaces the entire directory with a symlink to the package folder.  
**Why it happens:** Omission of `--no-folding`. If `~/.config/gtk-3.0` were folded, matugen writing `gtk.css` would write straight into `stow/gtk/`.  
**How to avoid:** Always pass `--no-folding` to `stow`. Enforce through assertion: `test -d "$HOME/.config/gtk-3.0" && test ! -L "$HOME/.config/gtk-3.0"`.  
**Warning signs:** `ls -ld ~/.config/gtk-3.0` shows a symlink (`lrwxrwxrwx`).

### Pitfall 2: Link Severance by GTK `g_file_set_contents`
**What goes wrong:** When GTK's file chooser updates bookmarks, it calls `g_file_set_contents`, which writes to a temporary file and atomically renames over the target, unlinking the symlink and replacing it with a regular file.  
**Why it happens:** Atomic file replacement semantics in GLib.  
**How to avoid:** Manage GTK files as declarative dotfiles. Use `arch/dots-hyprland.sh verify` as the watchdog; if a link is severed, `verify` fails naming the recovery stow command.  
**Warning signs:** `verify` emits `[FAIL] not a symlink: /home/pera/.config/gtk-3.0/bookmarks`.

### Pitfall 3: Git Ignore on Tracked Files (Index-Aware Behavior)
**What goes wrong:** Adding a file pattern to `.gitignore` does not untrack a file that is already committed in git history.  
**Why it happens:** Git ignore rules govern untracked files only.  
**How to avoid:** When retiring `kdeglobals`, explicitly remove it from git tracking via `git rm` or `git mv` to `docs/archive/`.  
**Warning signs:** `git status` continues showing modifications to an ignored path.

### Pitfall 4: Process Lifecycle Race Conditions
**What goes wrong:** Stowing or unlinking configuration files while Dolphin GUI or settings dialogs are running causes Dolphin to overwrite the newly created symlinks with cached in-memory state upon closing.  
**Why it happens:** Qt applications flush cached configuration to disk on exit via `QSaveFile`.  
**How to avoid:** Assert Dolphin is not running (`pgrep -x dolphin || true`) before stowing or running drills.  
**Warning signs:** Newly created symlinks replaced with regular files immediately after closing Dolphin.

### Pitfall 5: Script Proliferation Breaking `PAIR_COUNT == 18`
**What goes wrong:** Adding helper scripts like `arch/kde.sh` or `arch/gtk.sh` holding stow invocations causes closed assert `scripts/phase17-unblock-assert.sh:90` to fail.  
**Why it happens:** `phase17-unblock-assert.sh` counts occurrences of `--verbose=5 --no-folding` across `arch/*.sh` and strictly asserts `PAIR_COUNT == 18`.  
**How to avoid:** Do not create `arch/kde.sh` or `arch/gtk.sh`. Run Stow directly during Phase 22 deployment. Full desktop orchestration is reserved for Phase 23.  
**Warning signs:** `./scripts/phase17-unblock-assert.sh` reports `1b expected 15 arch/ sites... counted 19`.
