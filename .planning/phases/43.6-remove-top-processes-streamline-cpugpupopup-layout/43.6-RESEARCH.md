## Summary

Phase 43.6 simplifies `CpuGpuPopup.qml` by removing the top CPU and GPU process attribution trees (eliminating background process polling timers, JSON stream collectors, and subprocess script execution) and restructuring the popup into a clean, balanced two-column layout:
- **Left Column (320px)**: Hosts the CPU telemetry card on top, a subtle 1px divider, and the GPU telemetry card on the bottom.
- **Right Column (320px)**: Hosts the Platform & Motherboard telemetry unified in a single column (Platform header, VRM temp, Platform Avg temp, 1px divider, and all 6 platform sensors).

In Phase 43.5, hierarchical process attribution trees and an expandable platform bottom drawer were added to `CpuGpuPopup.qml`. However, live usage demonstrated that embedding multi-process attribution trees inside a top-bar hover popup introduced unnecessary complexity:
1. **Polling & Script Complexity**: Running an external process scanner (`process_tree.py` / `process_tree.sh`) via `Quickshell.Io.Process` and `Timer` every 2.5s while active consumed background CPU and memory to parse `/proc` statistics and DRM fdinfo.
2. **Layout Height Inflation**: The process tree view with top 5 roots and child branches inflated popup height to > 550px, crowding the viewport and requiring a separate wide bottom drawer for motherboard telemetry.
3. **Ergonomic Mismatch**: Quick status bar popups are intended for rapid glances at hardware vitals (loads, clocks, temperatures, throttling). Deep process hierarchy analysis is better suited for dedicated system monitors (like `btop` on `special:btop`).

By removing the process trees and consolidating Platform/Motherboard telemetry into the right column, Phase 43.6 achieves:
- **Zero background subprocesses or timers** in `CpuGpuPopup.qml`.
- **~40% reduction in vertical footprint** (from ~550px down to ~330px), eliminating any risk of screen overflow.
- **Perfect column symmetry**: 11 visual elements in the Left column and 11 visual elements in the Right column.
- **Strict preservation of CPUGPU-05 and CPUGPU-06**: Dynamic hardware naming and hybrid topology gating remain 100% intact.

## Architecture Patterns

### 1. Two-Column Symmetric Layout
- The top-level `contentItem` of `StyledPopup` is a single `RowLayout` (`popupContent`) with `anchors.centerIn: parent` and `spacing: 16`.
- Two `ColumnLayout`s of identical preferred width (`Layout.preferredWidth: 320`) are separated by a 1px vertical divider (`Rectangle { Layout.fillHeight: true; implicitWidth: 1; color: Appearance.colors.colLayer0Border }`).
- **Left Column**: CPU Card (Header + 5 metric rows) + 1px horizontal divider + GPU Card (Header + 3 metric rows). Total: 11 layout items.
- **Right Column**: Platform Header + 2 summary temp rows + 1px horizontal divider + Subtitle label + 6 `PlatformSensorRow`s + vertical spacer `Item { Layout.fillHeight: true }`. Total: 11 layout items.
- Visual symmetry is balanced, avoiding awkward asymmetric white space.

### 2. Pure Declarative Telemetry Binding (Zero Background Processes)
- `CpuGpuPopup.qml` no longer contains any `Timer` or `Process` instances.
- Telemetry values are purely bound to `HardwareTelemetry` singleton properties.
- Fast polling cadence (1000ms active / 3000ms idle) is driven automatically by `HardwareTelemetry.fastPollingRequests++` on `active: true` and `--` on `active: false`.
- Zero file I/O or JSON parsing occurs inside `CpuGpuPopup.qml`.

### 3. Sub-Component Encapsulation
- Preserve `MetricProgressRow` (`ColumnLayout` with title, optional clock/subtitle, percentage, temperature, and `StyledProgressBar`).
- Preserve `PlatformSensorRow` (`RowLayout` with label, flexible spacer, and formatted `°C` badge colored via `root.getTempColor()`).
- Reuse upstream `StyledPopupHeaderRow` (`icon` + `label`) and `StyledPopupValueRow` (`icon` + `label` + right-aligned `value`).

## Common Pitfalls & Edge Cases

### Pitfall 1: Fast-Polling Reference Count Leak
- **Risk:** If `HardwareTelemetry.fastPollingRequests++` is called on popup open without a guaranteed matching decrement on close or destruction, `fastPollingRequests` remains > 0 indefinitely, locking `HardwareTelemetry` into 1000ms fast polling forever.
- **Mitigation:** Retain both `onActiveChanged` (+1 on active, -1 on inactive) AND `Component.onDestruction` (`if (active) HardwareTelemetry.fastPollingRequests--;`) as established in Phase 43/43.5.

### Pitfall 2: Layout Height Mismatch & Bottom Stretching
- **Risk:** In a `RowLayout`, child `ColumnLayout`s default to expanding their items if `Layout.fillHeight` is applied indiscriminately to all children, creating strange gaps between rows.
- **Mitigation:** In the Right column, place a trailing `Item { Layout.fillHeight: true }` at the very bottom. This absorbs any excess vertical space cleanly without stretching the metric rows or sensor items.

### Pitfall 3: Broken References to Removed Properties
- **Risk:** Lingering references to `root.topCpuProcesses`, `processTreeProc`, or `procScanTimer` in signal handlers or assertion scripts will cause QML runtime warnings or test failures.
- **Mitigation:** Grep the entire repository for references to `topCpuProcesses`, `topGpuProcesses`, and `processTreeProc`. Ensure `CpuGpuPopup.qml` contains zero lingering references.

### Pitfall 4: Window Sizing and Screen Boundary Overflow
- **Risk:** If popup width or height exceeds available screen space, popup windows can be clipped by display edges or Wayland layer-shell margins.
- **Mitigation:**
  - Total inner width: Left Column (320px) + Spacing (16px) + Separator (1px) + Spacing (16px) + Right Column (320px) = 673px.
  - Total window width with margins: 673 + 20 = 693px.
  - Total height: ~330px inner + 20px margins = ~350px.
  - `StyledPopup.qml` lines 85–116 enforce dynamic horizontal screen boundary clamping against `root.QsWindow?.screen?.width` and `Appearance.sizes.hyprlandGapsOut`. At 693px wide, it fits easily on any display from 1080p to 4K with zero overflow.

### Pitfall 5: Non-Hybrid CPU Representation (CPUGPU-06)
- **Risk:** If P-Core and E-Core rows are statically displayed on a uniform CPU (e.g., AMD Ryzen or standard Intel non-hybrid), they will display 0% / 0T and clutter the CPU card.
- **Mitigation:** Keep `visible: HardwareTelemetry.isHybridArchitecture` on both P-Core and E-Core `MetricProgressRow`s. When `isHybridArchitecture` is false, QtQuick Layouts automatically collapses their implicit height to 0, presenting a clean CPU card with Overall CPU, Governor, and Power Draw.

### Pitfall 6: Stow Symlink Drift
- **Risk:** Modifying files in `restow/` without running stow sync can cause discrepancies between repo files and live `~/.config/quickshell/` files.
- **Mitigation:** Always verify with `./arch/dots-hyprland.sh verify --strict` to ensure stow leaf symlinks match repo sources with zero findings.

pragma ComponentBehavior: Bound

import qs.modules.common
import qs.modules.common.widgets
import qs.services
import QtQuick
import QtQuick.Layouts
import Quickshell

StyledPopup {
    id: root

    // Reactive fast-polling lifecycle boost (1000ms active / 3000ms idle)
    // Guarantees zero reference count leaks
    onActiveChanged: {
        if (active) {
            HardwareTelemetry.fastPollingRequests++;
        } else {
            HardwareTelemetry.fastPollingRequests--;
        }
    }

    Component.onDestruction: {
        if (active) {
            HardwareTelemetry.fastPollingRequests--;
        }
    }

    // Alert threshold color mappings with dots-hyprland amber warning color fallback
    readonly property color warningColor: Appearance.colors.colWarning !== undefined ? Appearance.colors.colWarning : "#FFA000"

    function getLoadColor(val) {
        if (val >= 0.90) return Appearance.colors.colError;
        if (val >= 0.70) return root.warningColor;
        return Appearance.colors.colPrimary;
    }

    function getTempColor(temp) {
        if (temp >= 80) return Appearance.colors.colError;
        if (temp >= 65) return root.warningColor;
        return Appearance.colors.colOnLayer1;
    }

    readonly property color cpuLoadColor: getLoadColor(HardwareTelemetry.overallCpuLoad || 0.0)
    readonly property color gpuLoadColor: getLoadColor(HardwareTelemetry.gpuLoad || 0.0)

    readonly property bool isCritical: (HardwareTelemetry.overallCpuLoad || 0.0) >= 0.90 || (HardwareTelemetry.packageTemp || 0) >= 80 || (HardwareTelemetry.gpuLoad || 0.0) >= 0.90
    property real criticalPulseOpacity: 1.0

    // Reusable progress meter row sub-component
    component MetricProgressRow: ColumnLayout {
        id: meterRow
        property string title: ""
        property string mhzText: ""
        property string subtitle: mhzText
        property real value: 0.0
        property string tempText: ""
        property color barColor: Appearance.colors.colPrimary
        property color tempColor: Appearance.colors.colOnLayer1
        property bool isCritical: false
        spacing: 2
        Layout.fillWidth: true

        RowLayout {
            Layout.fillWidth: true
            spacing: 6
            StyledText {
                text: meterRow.title
                font.pixelSize: Appearance.font.pixelSize.smaller
                color: Appearance.colors.colOnSurfaceVariant
            }
            Item { Layout.fillWidth: true }
            StyledText {
                visible: (meterRow.mhzText.length > 0 || meterRow.subtitle.length > 0)
                text: meterRow.mhzText.length > 0 ? meterRow.mhzText : meterRow.subtitle
                font.pixelSize: Appearance.font.pixelSize.smaller
                color: Appearance.colors.colSubtext
            }
            StyledText {
                text: `${Math.round((meterRow.value || 0.0) * 100)}%`
                font.pixelSize: Appearance.font.pixelSize.smaller
                font.weight: Font.DemiBold
                color: meterRow.barColor
                opacity: meterRow.isCritical ? root.criticalPulseOpacity : 1.0
            }
            StyledText {
                visible: meterRow.tempText.length > 0
                text: meterRow.tempText
                font.pixelSize: Appearance.font.pixelSize.smaller
                font.weight: Font.DemiBold
                color: meterRow.tempColor
                opacity: meterRow.isCritical ? root.criticalPulseOpacity : 1.0
            }
        }

        StyledProgressBar {
            Layout.fillWidth: true
            value: Math.max(0.0, Math.min(1.0, Math.round((meterRow.value || 0.0) * 100) / 100))
            highlightColor: meterRow.barColor
            opacity: meterRow.isCritical ? root.criticalPulseOpacity : 1.0
        }
    }

    component PlatformSensorRow: RowLayout {
        id: psRow
        property string label: ""
        property int temp: 0
        spacing: 4
        Layout.fillWidth: true

        StyledText {
            text: psRow.label
            font.pixelSize: Appearance.font.pixelSize.smaller
            color: Appearance.colors.colOnSurfaceVariant
        }

        Item { Layout.fillWidth: true }

        StyledText {
            text: root.active ? `${psRow.temp}°C` : ""
            font.pixelSize: Appearance.font.pixelSize.smaller
            font.weight: Font.Medium
            color: root.getTempColor(psRow.temp)
            opacity: psRow.temp >= 80 ? root.criticalPulseOpacity : 1.0
        }
    }

    SequentialAnimation {
        id: popupCriticalPulse
        running: root.active && root.isCritical
        loops: Animation.Infinite
        onRunningChanged: {
            if (!running) root.criticalPulseOpacity = 1.0;
        }
        NumberAnimation {
            target: root
            property: "criticalPulseOpacity"
            to: 0.4
            duration: 600
            easing.type: Easing.InOutSine
        }
        NumberAnimation {
            target: root
            property: "criticalPulseOpacity"
            to: 1.0
            duration: 600
            easing.type: Easing.InOutSine
        }
    }

    // =========================================================================
    // Two-Column Streamlined Layout: Left (CPU + GPU) & Right (Platform)
    // =========================================================================
    RowLayout {
        id: popupContent
        anchors.centerIn: parent
        spacing: 16

        // =====================================================================
        // Left Column: CPU Card (Top) + GPU Card (Bottom)
        // =====================================================================
        ColumnLayout {
            Layout.preferredWidth: 320
            spacing: 8

            // --- CPU Section (Top) ---
            StyledPopupHeaderRow {
                icon: "planner_review"
                label: `CPU (${HardwareTelemetry.cpuModelName})`
            }

            MetricProgressRow {
                title: "Overall CPU"
                mhzText: root.active ? `${Math.round((HardwareTelemetry.pCoreFrequencyMhz || 0) * 0.6 + (HardwareTelemetry.eCoreFrequencyMhz || 0) * 0.4)} MHz` : ""
                value: root.active ? (Math.round((HardwareTelemetry.overallCpuLoad || 0.0) * 100) / 100) : 0.0
                tempText: root.active ? `${HardwareTelemetry.packageTemp || 0}°C` : ""
                barColor: root.cpuLoadColor
                tempColor: root.getTempColor(HardwareTelemetry.packageTemp || 0)
                isCritical: (HardwareTelemetry.overallCpuLoad || 0.0) >= 0.90 || (HardwareTelemetry.packageTemp || 0) >= 80
            }

            MetricProgressRow {
                visible: HardwareTelemetry.isHybridArchitecture
                title: `P-Cores (${HardwareTelemetry.pCoreThreadCount}T)`
                mhzText: root.active ? `${Math.round(HardwareTelemetry.pCoreFrequencyMhz || 0)} MHz` : ""
                value: root.active ? (Math.round((HardwareTelemetry.pCoreLoad || 0.0) * 100) / 100) : 0.0
                tempText: root.active ? `${HardwareTelemetry.pCoreTempAvg || 0}°C` : ""
                barColor: root.getLoadColor(HardwareTelemetry.pCoreLoad || 0.0)
                tempColor: root.getTempColor(HardwareTelemetry.pCoreTempAvg || 0)
                isCritical: (HardwareTelemetry.pCoreLoad || 0.0) >= 0.90 || (HardwareTelemetry.pCoreTempAvg || 0) >= 80
            }

            MetricProgressRow {
                visible: HardwareTelemetry.isHybridArchitecture
                title: `E-Cores (${HardwareTelemetry.eCoreThreadCount}T)`
                mhzText: root.active ? `${Math.round(HardwareTelemetry.eCoreFrequencyMhz || 0)} MHz` : ""
                value: root.active ? (Math.round((HardwareTelemetry.eCoreLoad || 0.0) * 100) / 100) : 0.0
                tempText: root.active ? `${HardwareTelemetry.eCoreTempAvg || 0}°C` : ""
                barColor: root.getLoadColor(HardwareTelemetry.eCoreLoad || 0.0)
                tempColor: root.getTempColor(HardwareTelemetry.eCoreTempAvg || 0)
                isCritical: (HardwareTelemetry.eCoreLoad || 0.0) >= 0.90 || (HardwareTelemetry.eCoreTempAvg || 0) >= 80
            }

            StyledPopupValueRow {
                Layout.fillWidth: true
                icon: "tune"
                label: "Governor:"
                value: root.active ? (HardwareTelemetry.scalingGovernor || "") : ""
            }

A specific area to investigate is `restow/quickshell/.config/quickshell/ii/scripts/resource-usage/process_tree.py` (and `process_tree.sh`).

### Current Status
- `process_tree.py`: 14-line launcher script delegating to `process_tree.sh`.
- `process_tree.sh`: 236-line shell+awk scanner calculating CPU ticks and DRM engine-render utilization percentage.
- **Current consumers**: Previously invoked by `CpuGpuPopup.qml` and tested by `scripts/phase43.5-dynamic-telemetry-assert.sh` Section 4.

### Disposition Options

| Option | Actions | Pros | Cons / Risks |
|--------|---------|------|--------------|
| **Option A: Purge completely** | Delete `process_tree.py` and `process_tree.sh` from `restow/quickshell/.../scripts/resource-usage/`. | Cleanest codebase state; zero dead code; eliminates unused scripts from the stow package. | Running historical `phase43.5-dynamic-telemetry-assert.sh` will fail on Section 4 unless that test script is updated or skipped. |
| **Option B: Deprecate & keep as standalone CLI tool** | Remove invocation from `CpuGpuPopup.qml`, but keep `process_tree.sh` and `process_tree.py` in the repo (with header docstring noting deprecation from Quickshell). | 100% backward compatible with `phase43.5-dynamic-telemetry-assert.sh`; available as a handy standalone terminal tool (`python3 process_tree.py \| jq`). | Retains ~250 lines of unused script code in `restow/quickshell/`. |

### Recommendation
**Deprecate from Quickshell UI and keep files in repo (Option B) OR remove them cleanly along with updating the assert harness.**
If the user prefers zero dead code, Option A is recommended, with `phase43.5-dynamic-telemetry-assert.sh` updated to skip Section 4 or mark it as superseded. If preserving regression test reproducibility is prioritized, Option B keeps the standalone scripts intact while ensuring `CpuGpuPopup.qml` does not invoke them.
