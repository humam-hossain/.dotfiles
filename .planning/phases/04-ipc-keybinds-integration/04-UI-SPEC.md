## Visibility Contract (IPC-01)

> Expected **visual outcomes** of stock IPC — not new UI.

| Action | CLI (prescriptive) | Expected visual outcome |
|--------|--------------------|-------------------------|
| Close | `qs ipc call bar close` | **All** bar windows hide (every monitor that had a bar). No residual bar exclusive zone / bar chrome on DP-1 or HDMI-A-2 (or any active screen in `bar.screenList`). |
| Open | `qs ipc call bar open` | **All** bars reappear on the same monitors, with Phase 2–3 module layout intact (workspaces, clock, tray, network, resources, volume as previously configured). |
| Toggle | `qs ipc call bar toggle` | Flips global visibility once; second toggle restores prior open/closed visual state for that flip sequence. |

### Visibility rules (locked)

| Rule | Source | Contract |
|------|--------|----------|
| All monitors together | D-08 | Single flag `GlobalStates.barOpen` — **no** per-monitor show/hide UI or state |
| Mechanism | D-04/D-05 | Stock `IpcHandler` target `bar` only (`toggle` / `open` / `close` in `Bar.qml`) |
| No new IPC chrome | D-04 | No on-screen toast, badge, or status line acknowledging IPC calls |
| Screen lock interaction | existing | When `GlobalStates.screenLocked` is true, bar remains inactive even if `barOpen` is true — **do not change** this gating |
| Dual Waybar | D-01 / deferred cutover | Waybar may still be visible; UAT judges **Quickshell** bar only |

### Post-condition after hide

- Quickshell bar layers gone from all monitors.
- No new placeholder / “bar hidden” indicator (stock LazyLoader deactivation only).
- Other shell surfaces (if any open) are out of scope; do not invent hide-side-effects UI.

### Post-condition after show

- Bar usable: modules update (clock ticks; resources move when system load changes).
- Tray icons present and clickable on the **Quickshell** bar (when tray apps are running).

## Reload UX Contract (IPC-03)

> Expected **visual / interaction outcomes** of stock soft reload — not new UI.

| Concern | Contract |
|---------|----------|
| Trigger | Stock Quickshell **file-watch soft reload** (content change on watched QML) or equivalent stock soft path. **There is no `qs reload` CLI on 0.3.0** (04-RESEARCH). Do not invent reload CLI wrappers or reload IPC (D-07). |
| Process | Same PID preferred (graceful soft reload, not kill+relaunch) |
| Popup | **Silent** — `//@ pragma Env QS_NO_RELOAD_POPUP=1` remains in `shell.qml`. **Do not** enable or style ReloadPopup for success/fail this pass (D-10). |
| Visible flash | **None** — no top-of-screen green/red reload banner, no custom toast |
| Bar after reload | Must be **usable**: modules visible and updating (D-11). If soft reload resets `barOpen` to default `true`, bar showing is acceptable; UAT may call `qs ipc call bar open` to re-assert open. **Hide state need not survive reload** (research A1). |
| Tray after reload | Must be **usable**: icons reconnect or remain interactive on QS bar (D-11). Dual-host SNI noise with Waybar is acceptable until cutover; failure = QS tray unusable only. |
| Failed reload | No auto-relaunch UI/daemon (D-12). Recovery is **manual**: fix QML + relaunch `qs`. Silent mode means user checks instance log for `reloadFailed` / errors — no on-screen error chrome this pass. |
| Hard restart | Out of scope as product UX; manual only. No hard-restart keybind UI. |

### Soft-reload visual acceptance checklist

1. Trigger soft reload (content-change probe on watched QML; restore after).
2. Confirm **no** ReloadPopup / reload banner appears.
3. Confirm process still running (same PID when soft path succeeds).
4. Confirm bar modules update (clock / resources).
5. Confirm tray icon click opens expected menu on **Quickshell** bar.
6. Confirm `qs ipc call bar open|close|toggle` still works after reload.

## Explicit Non-Goals (UI)

1. **No new visual components** — panels, popups, banners, CTAs, settings rows, keybind pickers.
2. **Do not enable ReloadPopup** — keep silent reload (D-10).
3. **No keybind UI** and no Hyprland bind work that implies new feedback chrome (IPC-02 deferred).
4. **No layout changes** — bar geometry, module order, padding, exclusive zone untouched unless a verified bug forces a minimal fix.
5. **No custom reload IPC target** and no on-screen “Reloading…” affordance (D-07).
6. **No per-monitor visibility UI** (D-08).
7. **No Waybar cutover UI** or dual-bar “migration” messaging.
8. **No auto-relaunch / crash-recovery UI** (D-12).

### Additional interaction truths (lift candidates for planner `must_haves.truths`)

1. `qs ipc call bar close` hides the Quickshell bar on **all** active bar monitors; `open` restores it on all (D-08).
2. Soft reload produces **no** ReloadPopup / reload banner (`QS_NO_RELOAD_POPUP=1` retained).
3. After successful soft reload, bar modules remain usable and tray remains interactive (D-11).
4. No new visual components or layout/token changes ship in this pass unless verification proves stock IPC/reload/tray broken (D-13).
5. Hide-state survival across reload is **not** required; post-reload usability is required (research A1).
