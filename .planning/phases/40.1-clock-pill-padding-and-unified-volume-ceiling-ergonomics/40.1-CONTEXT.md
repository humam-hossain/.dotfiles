# Phase 40.1: Clock Pill Padding and Unified Volume Ceiling Ergonomics - Context

**Gathered:** 2026-09-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 40.1 delivers visual and ergonomic polish to the status bar and desktop audio controls:
1. Status bar clock/date pill horizontal padding adjustment to match adjacent pills (~10px horizontal breathing room) while retaining custom second precision and full date string formatting.
2. Single source of truth for the desktop-wide 150% (1.5) volume ceiling defined in `config.json` under `"audio": {"volumeCeiling": 1.5}`, consumed by Quickshell (`Audio.maxVolume`) and Hyprland keybinds (Lua evaluation at startup/reload in `keybinds.lua`).
3. Right sidebar volume slider (`QuickSliders.qml`) dynamically bound to `to: Audio.maxVolume` with a visual stop indicator at 100% (`stopIndicatorValues: [1.0 / Audio.maxVolume]`).
4. Mouse scroll volume increment (`incrementVolume()`) clamping dynamically to `Audio.maxVolume` (1.5) with auto-unmute on volume increase and 2% step granularity.

</domain>

<decisions>
## Implementation Decisions

### Clock Pill Padding & Visual Alignment
- **D-01:** Set 10px horizontal padding on the Clock pill inside `ClockWidget.qml` (via `rowLayout` left/right margins or `implicitWidth` calculation) so horizontal breathing room is guaranteed matching the 10px sidebar button and ~9px Resources pill, without altering `BarGroup` vertical height or centering. — **Reversibility:** reversible
- **D-02:** Retain the 8px non-glyph spacer between the time string and the date string per Phase 32 COMP-03 / D-08 decision. — **Reversibility:** reversible

### Single Source of Truth for Volume Ceiling (150% / 1.5)
- **D-03:** Store `volumeCeiling: 1.5` in `capture/ii/.config/illogical-impulse/config.json` under `"audio": { "volumeCeiling": 1.5 }` as the single canonical source of truth for the desktop environment. — **Reversibility:** costly — dependent systems (Quickshell and Hyprland keybinds) consume this schema path.
- **D-04:** In `stow/hypr/.config/hypr/custom/keybinds.lua`, parse `config.json` once via Lua at Hyprland startup/reload to resolve `volumeCeiling` (fallback to 1.5) and bind `XF86AudioRaiseVolume` using `wpctl set-volume @DEFAULT_AUDIO_SINK@ 2%+ -l <CEILING>`, ensuring zero jq/subshell overhead during key repeats. — **Reversibility:** reversible
- **D-05:** In Quickshell, expose `readonly property real maxVolume: Config.options?.audio?.volumeCeiling ?? 1.5` on the `Audio.qml` singleton (`restow/quickshell/.config/quickshell/ii/services/Audio.qml`) as the central property used across all Quickshell UI controls and services. — **Reversibility:** costly — standardizes volume ceiling contract across Quickshell QML components.

### Sidebar Volume Slider Ergonomics (QuickSliders.qml)
- **D-06:** In `QuickSliders.qml`, dynamically bind the volume slider's upper limit `to: Audio.maxVolume` so the slider automatically spans 0.0 to 1.5 based on the single source of truth. — **Reversibility:** reversible
- **D-07:** Add a visual stop indicator at 100% (1.0) volume on the slider via `stopIndicatorValues: [1.0 / Audio.maxVolume]`, giving the user a clear tactile/visual boundary at normal max volume before entering software amplification. — **Reversibility:** reversible
- **D-08:** Keep default slider behavior without tooltip customization in the amplified range. — **Reversibility:** reversible

### Mouse Scroll Volume Increment & OSD Behavior
- **D-09:** In `Audio.qml` `incrementVolume()`, clamp the upper ceiling dynamically with `Math.min(root.maxVolume, Audio.sink.audio.volume + step)`, allowing mouse scrolling on status bar widgets to smoothly reach 150%. — **Reversibility:** reversible
- **D-10:** Automatically unmute audio (`Audio.sink.audio.muted = false`) whenever volume is incremented, preserving Phase 03 audio parity. — **Reversibility:** reversible
- **D-11:** Retain 2% step size (1% below 10% volume) for mouse scroll volume adjustments, maintaining parity with Hyprland's 2% keybind step. — **Reversibility:** reversible

### the agent's Discretion
None — all four gray areas were thoroughly explored with explicit choices captured.

</decisions>
