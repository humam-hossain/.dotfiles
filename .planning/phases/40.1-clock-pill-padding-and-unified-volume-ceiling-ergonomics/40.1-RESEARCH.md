## 3. Architecture Patterns & Code Examples

### Pattern 1: Pure Lua Startup Configuration Parser (Zero-Subprocess Keybind Loop)
To satisfy D-04 and prevent shell/jq subprocess spawns on every key repeat tick:

```lua
-- stow/hypr/.config/hypr/custom/keybinds.lua

-- Resolve desktop volume ceiling once at startup/reload (D-04, VOL-01)
local function get_volume_ceiling()
    local default_ceiling = "1.5"
    local config_path = HOME .. "/.config/illogical-impulse/config.json"
    local f = io.open(config_path, "r")
    if not f then return default_ceiling end
    local content = f:read("*a")
    f:close()
    if not content then return default_ceiling end
    local ceiling = content:match('"volumeCeiling"%s*:%s*([%d%.]+)')
    if ceiling and tonumber(ceiling) and tonumber(ceiling) > 0 then
        return ceiling
    end
    return default_ceiling
end
local volume_ceiling = get_volume_ceiling()

-- Upstream unbinds
hl.unbind("XF86AudioRaiseVolume")

-- Audio controls with dynamic ceiling
hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("wpctl set-volume @DEFAULT_AUDIO_SINK@ 2%+ -l " .. volume_ceiling),
    { locked = true, repeating = true, description = "Audio: Raise volume" })
```

Quickshell's `JsonAdapter` requires explicit QML property declarations to deserialize JSON fields [VERIFIED: headless QML test scratch run].

In `restow/quickshell/.config/quickshell/ii/modules/common/Config.qml`:

In `restow/quickshell/.config/quickshell/ii/services/Audio.qml`:
```qml
    // Centralized single source of truth for volume ceiling (D-05, VOL-01)
    readonly property real maxVolume: Config.options?.audio?.volumeCeiling ?? 1.5

    function incrementVolume() {
        if (Audio.sink?.audio) {
            Audio.sink.audio.muted = false; // Auto-unmute on increment (D-10)
            const currentVolume = Audio.value;
            const step = currentVolume < 0.1 ? 0.01 : 0.02; // 2% step size (D-11)
            Audio.sink.audio.volume = Math.min(root.maxVolume, Audio.sink.audio.volume + step); // Dynamic clamp (D-09)
        }
    }

    function decrementVolume() {
        if (Audio.sink?.audio) {
            const currentVolume = Audio.value;
            const step = currentVolume < 0.1 ? 0.01 : 0.02;
            Audio.sink.audio.volume = Math.max(0, Audio.sink.audio.volume - step);
        }
    }
```

## 4. Don't Hand-Roll & Common Pitfalls

### Pitfall 1: Double Normalization in `stopIndicatorValues` [HIGH IMPORTANCE]
**Discovered via codebase inspection of `StyledSlider.qml` line 79 & 194.**  
`TrackDot` calculates:
```qml
property real normalizedValue: (value - root.from) / (root.to - root.from)
```
When `root.from = 0` and `root.to = Audio.maxVolume` (1.5):
- If `stopIndicatorValues: [1.0]` is passed: `normalizedValue = (1.0 - 0) / (1.5 - 0) = 0.6667`. The stop notch appears at exactly 100% volume (66.7% across the slider track), aligning perfectly with the slider handle at 100% volume.
- If `stopIndicatorValues: [1.0 / Audio.maxVolume]` (i.e. `[0.6667]`) were passed: `TrackDot` would normalize again: `(0.6667 - 0) / 1.5 = 0.4444`. The notch would appear at 44.4% of the track (volume 0.67)!  
**Rule:** Always supply raw boundary values (e.g. `[1.0]`) to `stopIndicatorValues` because `TrackDot` performs the `(value - from) / (to - from)` division internally.

### Pitfall 2: StyledSlider Tooltip Percentage Normalization
**Discovered via codebase inspection of `StyledSlider.qml` line 52.**  
`StyledSlider` defines:
```qml
property string tooltipContent: usePercentTooltip ? `${Math.round(((value - from) / (to - from)) * 100)}%` : `${Math.round(value)}`
```
When `to = 1.5`, `((value - 0) / 1.5) * 100` computes percentage of the ceiling, not volume percentage:
- Volume 1.0 would display tooltip "67%".
- Volume 1.5 would display tooltip "100%".  
**Rule:** Explicitly bind `tooltipContent: `${Math.round(value * 100)}%`` on the volume slider so tooltips report actual volume (0% to 150%) instead of fraction-of-ceiling.

### Pitfall 3: JsonAdapter Undeclared Key Invisibility
**Discovered via headless QML execution of `Quickshell.Io.JsonAdapter`.**  
Quickshell's `JsonAdapter` does NOT create arbitrary dynamic properties for unrecognized JSON keys. If `"volumeCeiling": 1.5` is added to `config.json`, but `Config.qml` does not declare `property real volumeCeiling` under `JsonObject audio`, `Config.options.audio.volumeCeiling` evaluates to `undefined`.  
**Rule:** `restow/quickshell/.config/quickshell/ii/modules/common/Config.qml` must be deployed with `property real volumeCeiling: 1.5` inside `property JsonObject audio`.

### Pitfall 4: Subprocess Fork Latency in Hyprland Keybinds
**Discovered via `custom/keybinds.lua` inspection.**  
If `wpctl` or `jq` were called in a subshell on every key repeat to find the ceiling, key repeats would stutter and consume excessive CPU.  
**Rule:** Parse `config.json` once in Lua at compositor reload. Pass the fixed ceiling string directly into the `wpctl set-volume ... -l <ceiling>` keybind string.

### Pitfall 5: GNU Stow Collision on Upstream Regular Files
**Discovered via `ls -l ~/.config/quickshell/ii/services/Audio.qml`.**  
Upstream files created by the installer are regular files, not symlinks. GNU Stow refuses to stow if a regular file already exists at the target path.  
**Rule:** Check if target exists as a regular file; if so, move it to `.qml.bak` before running `stow --verbose=5 --no-folding -d restow -t ~ quickshell`. `arch/dots-hyprland.sh verify --strict` explicitly allows `.qml.bak` as `[INFO] installer backup artifact` [VERIFIED: verify --strict run output].
