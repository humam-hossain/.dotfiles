  <action>
    Extend `.config/quickshell/services/ResourceUsage.qml` (service only):

    1. ADD disk properties (bytes as real numbers; ring uses ratio):
       - `diskTotal`, `diskAvail` (or free), `diskUsed` (derived), `diskUsedPercentage` (used/total, guard total&gt;0)
    2. ADD `Process` (id e.g. `diskProc`) with:
       - `environment: ({ LANG: "C", LC_ALL: "C" })`
       - Prefer argv form: `command: ["df", "-B1", "--output=size,used,avail,pcent", "/"]` OR bash -c only if argv fails on host — document choice in SUMMARY
       - `stdout: StdioCollector` parse first data line after header; reject non-numeric with Number() fallbacks (T-03-01 input validation)
    3. ADD `function formatBytes(bytes)` returning auto human string: if total ≥ 1 TiB-ish use TB with one decimal, else GB with one decimal (D-15). Share with RAM labels.
    4. ADD convenience strings for bar:
       - RAM: used/total e.g. `8.5/15.5 GB` via formatBytes on used and total (memory is currently KB from /proc — convert consistently)
       - Disk: free/total e.g. `formatBytes(diskAvail) + "/" + formatBytes(diskTotal)` without forcing `%` (D-10)
    5. Keep existing CPU/RAM/swap /proc parsing; do not remove swap props.

    Do not edit Resources.qml or Resource.qml in this plan.
  </action>

    - Source contains formatBytes or equivalent G/T capacity helper
    - Source does not reference `/home` as a monitored mount for bar disk

  <name>Task 2: Multi-rate poll (CPU ~1s, RAM ~3s, disk ~10s)</name>
  <files>.config/quickshell/services/ResourceUsage.qml</files>
  <read_first>
    - .config/quickshell/services/ResourceUsage.qml (after task 1)

    - .planning/phases/03-system-audio-modules/03-CONTEXT.md (D-08, D-14)
  </read_first>
  <action>
    Replace single-interval-all-metrics behavior with multi-rate polling:

    1. Drive a base timer at ~1s (or Config `resources.updateInterval` default 1000).
    2. On each tick: always refresh CPU from /proc/stat (D-08 CPU feel).
    3. Refresh RAM from /proc/meminfo every ~3s using Config `resources.memoryUpdateInterval` (default 3000) via elapsed counter or second timer.
    4. Launch/reload disk Process every ~10s using Config `resources.diskUpdateInterval` (default 10000) — not every CPU tick (T-03-03).
    5. Keep history updates consistent with which metric was refreshed (CPU history on CPU tick; memory history on memory tick).
    6. Fallbacks if Config keys missing: 1000 / 3000 / 10000.

    Do not dual-write config here (plan 03-02). Do not edit bar widgets.
  </action>
  <acceptance_criteria>
    - ResourceUsage.qml references memoryUpdateInterval and diskUpdateInterval (or hard-coded 3000/10000 with comment + Config optional chaining)
    - Disk Process is not started on every 1s path without a ≥10s gate (counter, separate timer, or interval check)
    - CPU path still reloads /proc/stat at ~1s rate
    - `timeout 4 quickshell 2>&amp;1 | rg 'Configuration Loaded|Error'` shows Configuration Loaded
  </acceptance_criteria>
  <verify>
