## Warnings

### WR-01: S6 legend-keying gate spans the whole canvas, so it cannot fail on legend regression

**File:** `scripts/phase54.3-weather-assert.sh:860-865`
**Issue:** The gate extracts `sed -n '/legendRow/,/axisIconStrip/p'` (WeatherGraph.qml lines ~597→1291) and asserts `grep -c 'root.activeMetric' >= 1`. That range contains the entire canvas `onPaint` — `getMetricY(root.activeMetric, …)` (:812), all five guideline branch conditions (:854/:880/:919/:947/:974), all five lower-tier branches (:1057–1138), and the scrub handler (:1343) — dozens of pre-existing `root.activeMetric` references. Reverting only the three legend entries to hardcoded temp strings (the exact bug G-54.3-2 reports) keeps this gate green. The gate name claims legend keying; it proves file-level presence, the same weakness class as prior WR-02.
**Fix:** Bound the range to the legend subtree and require all six call sites:
```bash
legend_keyed="$(sed -n '/id: legendRow/,/id: graphArea/p' "$GRAPH_SRC" | grep -c 'root.activeMetric' || true)"
if [[ "$legend_keyed" -ge 6 ]]; then
  pass "S6: Legend entries key swatches and labels off the card metric (G-54.3-2)"
else
  fail "S6: Expected 6 legend keyings (3 labels + 3 colors), found ${legend_keyed} (G-54.3-2)"
fi
```

### WR-02: Zero-hex legend gate excludes the fallback hexes the legend delegates to at runtime

**File:** `scripts/phase54.3-weather-assert.sh:867-872` (gate); `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml:315-318,546-549,575-578` (source)
**Issue:** The gate scans only `/function legendSolidLabel/,/id: contentColumn/p` for `#[0-9a-fA-F]` and passes. But `legendSolidColor` (:546-549) and `legendBarColor` (:575-578) delegate `aqi`/`uv` to `root.getActiveMetricColor()`, whose UV tier branch contains static-hex fallbacks: `Appearance.m3colors.m3error || "#E53935"` (:316) and `Appearance.colors.colTertiary || "#FF9800"` (:318), both upstream of the gate's sed window (which starts at :497). Whenever an m3 token is absent on an AQI/UV card, the legend swatch resolves to a static hex — the precise T-54.3-18 violation — while the gate stays green.
**Fix:** Either eliminate the hex fallbacks (token-only):
```qml
if (uv >= 8)
    return Appearance.m3colors.m3error || Appearance.colors.colPrimary;
if (uv >= 6)
    return Appearance.colors.colTertiary || Appearance.colors.colPrimary;
```
or extend the gate's sed range to start at `function getActiveMetricColor` so the delegation target is covered.

### WR-03: AQI/UV legend swatches inherit hover-slot-dependent color and shift while scrubbing

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml:546-549,575-578` (delegation); `:304-320` (`getActiveMetricColor`)
**Issue:** `legendSolidColor`/`legendBarColor` for `aqi`/`uv` return `root.getActiveMetricColor()`, which reads `root.validHours[root.activeSlotIndex]` — the hover position, updated on every `onPositionChanged` (:1338, :1343). Scrubbing across an AQI card therefore re-tints the legend's solid/bar swatches as the hovered slot's EPA tier changes (likewise UV tier colors on the UV card). A legend that mutates under the cursor undermines the G-54.3-2 "legend explains the series" goal the user explicitly complained about; the pre-existing stroke flicker is not a precedent to extend. Null-safety holds (`(h && h.aqi) ? … : 1`), so this is behavior, not a crash.
**Fix:** Bind the legend to slot-independent tokens instead of delegating:
```qml
function legendSolidColor(metricKey) {
    switch (metricKey) {
    case "aqi":
        return Appearance.colors.colPrimary;
    case "uv":
        return Appearance.colors.colTertiary;
    ...
```
