# Phase 54.4 Plan 09: Real-screen StyledPopup clamp Summary

**StyledPopup now clamps against the hovered bar's real screen, through the hover target's window, with an elevation-inset-aware centre and a null-target guard. On DP-1 the weather popup gets lockedLeftMargin 1600 (it was pinned at <= 215). A Node vm test runs the real QML function body and proves the result.**

## Performance

- **Duration:** about 4 min
- **Started:** 2026-10-17T13:32:55Z
- **Completed:** 2026-10-17T13:36:48Z
- **Tasks:** 2 (Task 1 tracer, Task 2 auto)
- **Files modified:** 2

## Accomplishments

- Fixed gap 1 / CR-01. `updateLockedMargins()` used to read a `screen` property off root's attached QsWindow object. That object has no such property, so the clamp always used 1920 x 1080. It now resolves `root.hoverTarget?.QsWindow?.window?.screen ?? popupWindow.screen ?? null`, and it falls back to 1920 x 1080 only when no screen has a positive size.
- **DP-1 pill at x=2400 with a 1700px background:** lockedLeftMargin was 215 or less before. It is 1600 now, so the visible background centre is 1600 + 10 + 850 = 2460, which is the pill centre.
- Both branches now offset the target and the max bound by `elevationMargin` (10px), so the visible background stays 5px (hyprlandGapsOut) inside the screen at the far edge. The vertical branch follows the same rule against the real screen height.
- `if (!root.hoverTarget) return;` is now the first statement (IN-05). The re-clamp Connections can call this function during construction.
- The `PanelWindow` `screen` is bound to the hovered bar's screen, so all six StyledPopup consumers open on the bar's output. WeatherPopup's size math and the clamp read the same screen object.
- Harness S1 has 4 new static asserts. S2 has 18 `StyledPopup clamp` vm asserts, which run the awk-extracted function body. Section 2 is retitled "Popup sizing and placement math".
