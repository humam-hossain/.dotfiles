# Phase 54.4 Plan 10: Legend fit on one row Summary

**A new pure function, `GM.legendFit`, sizes the legend row. It tightens the gaps and swatch width in three tiers, measured against a TextMetrics label advance, and scales the row only when the popup is clamped below 900px. The Rain/Wind/Vis legend now fits the 258px minimum card at full size (249.69px, tier 2). Before this plan it was about 307px and clipped "Vis".**

## Accomplishments

- Closed gap 2 (WR-04). The legend stays one fixed 18px row (D-54.4-09). Every colour dot, line-style swatch and 12px name stays (D-54.4-25). Only spacing changes until the popup is clamped narrower than the 900px minimum.
- The fit binding reads `legendRow.width`, which the layout assigns, and `legendMetrics.advanceWidth`, a TextMetrics at the fixed base font. It never reads the row's own natural size, so it cannot form a binding loop (T-54.4-25).

## Decisions Made

- `legendFit` checks the entry list first. An empty list returns width 0. A non-positive or non-finite `available` returns tier 0 at scale 1, and its width is the tier 0 natural width.
- The probe looks for vendor `Appearance.qml` in this checkout and then in the main checkout, and falls back to 12. In this worktree the vendor submodule is empty, so the main-checkout copy (`smaller: 12`) is used.
- The font family is validated against `^[A-Za-z0-9 ._-]+$` before it is written into `probe.qml`, which hardens T-54.4-26.
- Following plan 09's precedent, REQUIREMENTS.md was not touched in this worktree. POPUP-01, POPUP-03 and POPUP-04 are listed in `requirements-completed` for the orchestrator's shared-ID gate.
