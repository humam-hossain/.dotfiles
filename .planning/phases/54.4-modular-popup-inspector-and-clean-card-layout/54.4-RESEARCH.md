# Phase 54.4: Modular Popup Inspector and Clean Card Layout - Research

**Researched:** 2026-10-16
**Domain:** Quickshell (Qt 6.12 QML) layer-shell popup layout + QtQuick Canvas 2D charting
**Confidence:** HIGH (codebase + empirical Qt probes); MEDIUM on a few Quickshell attached-property timing details

## Summary

This phase replaces the five stacked 54.3 `WeatherGraph` instances inside `WeatherPopup.qml` with three equal, side-by-side graph cards (Temp | Rain/Wind/Vis | Air/UV/Pressure). It also replaces the scrolling `StyledFlickable` (fixed `implicitWidth: 880`, 85% height cap) with a non-scrolling layout sized from new `Config.options.bar.weather.popupWidthPercent/HeightPercent` keys. All data the graphs need already exists in the 25-slot `Weather.timeline`. No new service work, no external packages, and no network changes are needed. This is a QML/Canvas restructure plus a test harness.

The highest-risk pieces are not drawing code but mechanics that were probed empirically this session:
1. A `CanvasGradient.addColorStop` offset outside `[0,1]` **throws**. That aborts the whole `onPaint` and leaves a blank graph.
2. Two stops at the **same** offset do not make a hard edge: the second replaces the first. Tier ramps need an epsilon offset.
3. `WeatherBaseCard` has `clip: true`, so a tooltip parented inside a graph card can never float over a neighbour card (D-54.4-08). Tooltips must live in a popup-level overlay layer.
4. Hover passes through a plain overlay `Rectangle` (verified with qmltestrunner), so an overlay tooltip layer does not break the graphs' `MouseArea` hover.
5. Canvas repaints automatically on resize (verified).

**Primary recommendation:**
- Keep one `WeatherGraph.qml` driven by `property string graphKind: "temp" | "rainwind" | "airuv"`.
- Move every pure computation into a new plain-JS module `WeatherGraphMath.js`, imported with `import "WeatherGraphMath.js" as GM`. This covers scales, tier words, ramp/tier gradient stops, the 12h clock, the pressure trend, label collision placement and popup size math. It also covers the per-kind *draw* functions, which take `ctx` as a parameter.
- The popup owns `hoverSlot` and a tooltip overlay layer.
- A new `scripts/phase54.4-weather-assert.sh` loads the JS module in Node `vm` and exercises it, including with a recording mock `ctx`. It asserts invariants, not string presence.

### Pattern 1: Single source of geometry
**What:** One set of readonly properties on `WeatherGraph`: `gutter` (bound from the popup), `rightPad`, `plotLeft`, `plotRight`, `slotW`, `plotTop`, `plotBottom`, and `function slotX(i)`. Canvas `onPaint`, the markers, the axis repeater, the `MouseArea` index math and the tooltip anchor all read these properties.
**Why:** 54.3 REVIEW IN-03 found the gutter constant duplicated in three places. The 54.3 UAT left-clip bug came from paint and label math disagreeing.
**Gutter (D-54.4-05):** The popup owns `readonly property real graphGutter`. Compute it as `Math.max(24, TextMetrics(widest temp label).width + 6)`, so `-12°` or `104°` (USCS) cannot clip. All three graphs bind to it.

### Pattern 2: Popup-owned synced hover (D-54.4-07)
```qml
// WeatherPopup.qml
property int hoverSlot: -1
WeatherGraph {
    graphKind: "temp"; hoverSlot: root.hoverSlot; popupActive: root.active
    onHoverRequested: idx => root.hoverSlot = idx   // -1 on exit
}
```
Inside `WeatherGraph`, `MouseArea.onPositionChanged` computes `idx` from `slotX` geometry and emits `hoverRequested(idx)`. `onExited` emits `-1`. The graph never writes its own index. Markers and the scrub line use `visible: root.hoverSlot >= 0 && !slotUnavailable(root.hoverSlot)`.

### Pattern 3: Tooltip overlay that escapes card clipping (D-54.4-08)
```qml
// WeatherPopup.qml, sibling AFTER the ColumnLayout inside contentRoot
Item {
    id: tooltipLayer
    anchors.fill: parent
    z: 10
    visible: root.hoverSlot >= 0
    GraphTooltip { graph: tempGraph }   // inline component
    GraphTooltip { graph: rainGraph }
    GraphTooltip { graph: airGraph }
}
component GraphTooltip: Rectangle {
    required property var graph
    // reactive arithmetic, NOT mapToItem (not reactive)
    readonly property real cardX: graphRow.x + graph.x
    readonly property real anchorX: cardX + graph.contentOffsetX + graph.slotX(root.hoverSlot)
    // prefer staying inside own card; overflow only if wider than card
    x: width <= graph.width
       ? Math.max(cardX, Math.min(cardX + graph.width - width, anchorX - width / 2))
       : Math.max(0, Math.min(tooltipLayer.width - width, anchorX - width / 2))
    // y: above graph.markerTopY (topmost marker at hoverSlot) else flip below; clamp to layer
}
```
Hover pass-through was verified: a plain `Rectangle` above a `hoverEnabled` `MouseArea` keeps `containsMouse === true` (qmltestrunner probe). Do **not** put a `MouseArea` or `HoverHandler` in the tooltips.

### Pattern 4: Ramp / tier gradient stroke with clamped, epsilon-separated stops

### Pattern 6: Greedy peak-label placement (D-54.4-10)
- Build candidates `{text, x, y, w: ctx.measureText(text).width, h: fontPx, priority, color}`. Sources: series peaks, the pressure hi/lo, the solar peak, and the mm values above bars.
- Sort by priority. Suggested order:
  1. Temp max
  2. Feels max
  3. Rain% max
  4. Wind/gust max
  5. UV max
  6. Pressure hi/lo
  7. Solar peak
  8. mm values
- For each label, try offsets in order: above `(0,-h-3)`, above-left, above-right, below `(0,+3)`. Accept the first rect that:
  - lies inside `[plotLeft, plotRight] × [plotTop−legendGap, plotBottom]`, and
  - intersects no already-placed label rect and no reserved rect (the Now/tick zone).
- If no candidate fits, drop the label. Never draw it overlapping.

This is pure and returns placements, so the harness can assert "no two placed rects intersect" on adversarial inputs, such as temp and feels peaks at the same hour.

### Anti-Patterns to Avoid
- **Tooltips as children of `WeatherBaseCard`:** they get clipped (`clip: true`; Qt: "an item will clip its own painting, as well as the painting of its children").
- **Unclamped `addColorStop`:** it throws `Error: CanvasGradient: parameter offset out of range` and kills the whole paint (verified).
- **Equal-offset stops for hard tier edges:** the second stop replaces the first (verified: pixels at y=20 came out purple `150,0,105` instead of red).
- **Repainting the canvas on hover:** keep the 54.3 zero-repaint invariant. Markers and the scrub line are QML items.
- **`echo "$big" | grep -q` in harnesses under `set -o pipefail`:** SIGPIPE makes it flaky. Verified: `phase54-weather-assert.sh` alternates 5 and 6 FAILs run to run, and "missing Canvas component" appears only intermittently. Use `grep -q pat "$FILE"` or `grep -q pat <<<"$var"`.

## Common Pitfalls

### Pitfall 1: Gradient stop offset out of range blanks the graph
**What goes wrong:** A temp ramp anchor (e.g. 20°C) lies below the day's plotted minimum (25°C), so its offset is > 1. `addColorStop` throws, `onPaint` aborts, and the card renders empty.
**How to avoid:** Clamp every offset with `clamp01`. Synthesize endpoint stops by interpolating the color at `vTop` and `vBottom`. Harness: run `smoothRampStops`/`tierStops` over random bounds and assert all offsets are in [0,1] and non-decreasing.
**Warning signs:** `qs log -c ii` shows `CanvasGradient: parameter offset out of range`.

### Pitfall 2: Hard tier edges silently blend
**What goes wrong:** `addColorStop(b, cA); addColorStop(b, cB)` produces a smooth blend, because the second stop replaces the first.
**How to avoid:** Place stops at `b` and `b+EPS` (EPS 0.001 verified crisp: y45 = `255,0,0`, y55 = `0,0,255`).

### Pitfall 3: Tooltip clipped or hidden behind neighbour card
**How to avoid:** Use the popup-level overlay with `z: 10` (Pattern 3). Keep `WeatherBaseCard` `clip: true`; the 54.3 S1 harness asserts it. Clamp tooltips inside `tooltipLayer`, because the PanelWindow surface ends at `popupBackground`.

### Pitfall 4: Stale horizontal clamp after late size resolution (POPUP-01)
**What goes wrong:** `StyledPopup.updateLockedMargins()` runs only on `onVisibleChanged` and `onActiveChanged` (`StyledPopup.qml:113-122`). Suppose content width first evaluates with fallback 1920 (960 wide) and then resolves to 3440 (1720 wide). `lockedLeftMargin` then stays computed for 960, and the popup can overflow the right screen edge.
**How to avoid:**
- Resolve the screen before open by falling back to `hoverTarget`'s window screen.
- Add `Connections { target: popupBackground; function onImplicitWidthChanged() { popupWindow.updateLockedMargins() } }` (plus height) in the restow `StyledPopup.qml`. This is harmless to other popups.

### Pitfall 5: Historical-unavailable slots poison scales and tiers
**What goes wrong:**
- `isHistoricalUnavailable` slots carry `pressureHpa: 0`, `visibilityKm: 0`, `epaIndex: 0`, `uvIndex: 0` and `tempC: null` [VERIFIED: `services/Weather.qml:401-441`].
- Unfiltered, the pressure "exact min..max" becomes 0..1013, visibility 0 reads as "Fog", and the ribbon tries an index-0 color.
- Separately, `parseInt(...) || 0` also maps a missing API value to 0 on *available* slots (`Weather.qml:548-551`).
**How to avoid:**
- Every scale, tier and ribbon helper skips `isHistoricalUnavailable` slots.
- Treat `epaIndex` outside 1..6 as "no ribbon segment".
- Render tooltip text "No data" for unavailable slots.
- Keep the existing "Past data unavailable" hatch (D-54.3-18 is not superseded). Use shorter text in narrow cards.

### Pitfall 6: Pressure trend threshold vs integer hPa
**What goes wrong:** `pressureHpa` is `parseInt(r.pressure, 10)` [VERIFIED: `Weather.qml:549`], so the smallest non-zero Δ is 1 hPa = 0.000987 atm, which is **< 0.001**. A literal implementation of D-54.4-34 therefore reports a 1 hPa change as "Steady", which contradicts its own "(~1 hPa)" gloss.
**How to avoid:** Compute the trend in hPa: `|ΔhPa| < 1` (i.e. ΔhPa == 0) → Steady. Or confirm the literal-atm reading with the user (Open Question 2).

### Pitfall 7: Flat-scale division by zero
**What goes wrong:** Pressure fitted to the exact min..max (D-54.4-31) on a day with constant pressure gives a range of 0, so `(v-min)/0` is NaN and the spline disappears. The same applies to a wind/gust/vis max of 0 and a solar max of 0 at night-only windows.
**How to avoid:** If range == 0, draw at the vertical center, or at the bottom for zero-anchored scales. The harness should feed constant series.

### Pitfall 8: 12-hour clock edge cases
`hourNum` 0 → "12AM" and 12 → "12PM", never "0AM"/"0PM". Index 12 → "Now" (D-54.4-06). For the `Weather.hourly` fallback (no `hourNum`), derive the hour from `time` (`"300"` → 3), as the existing `formatTemporalLabel` does (`WeatherGraph.qml:359-361`).

### Pitfall 9: Old harnesses go red when superseded decisions are removed
**What goes wrong:**
- `phase54.3-weather-assert.sh` (currently FAIL=0, 124 PASS) asserts superseded contracts: 5 locked `activeMetric` bindings (S6), `plotLowerBottom = height - 46` (S3), legend strings "Actual temp" / "Rain chance", `colTertiary`/`colSecondary` tokens, `const plotLeft = 34;` ×2, and `formatTemporalLabel`.
- `phase54-weather-assert.sh` S1 asserts `implicitWidth: (440|880)` and `StyledFlickable` (lines 233-241). It is already red at baseline: 5-6 FAILs, including a missing `.bak` and SIGPIPE flakes.
- `phase34-verification-assert.sh:161-166` fails on **any** hex in `restow/quickshell`. It already has 34 hits, 16 of them in `WeatherGraph.qml`, and the fixed palettes add more.
**How to avoid:**
- Include a task that converts superseded asserts in 54 and 54.3 to `info "superseded by D-54.4-00"`. Do not delete them.
- Fix the `echo | grep -q` flake while there.
- Concentrate all fixed hex values in `WeatherGraphMath.js` and give the phase34 gate a documented single-file allow-list citing D-54.4-11. Or record the gate as pre-existing red. The planner chooses; confirm with the user.

### Pitfall 10: Rich-text injection from API strings
`StyledText` is a plain `Text` with no `textFormat`, so the default `Text.AutoText` applies [VERIFIED: vendor `StyledText.qml:4-22`]. Tooltip L1 shows API `weatherDesc`. Set `textFormat: Text.PlainText` on every tooltip and legend text bound to API data.

### Pitfall 11: Contrast of locked palette on the dark surface (D-54.4-11)
WCAG contrast was computed against the current `surface_container #1f2020` / `surface_container_high #292a2a` [VERIFIED: `~/.local/state/quickshell/user/generated/colors.json`]:

|-------|----------|---------|

| `#ab47bc` (Very Unhealthy) | 3.39 / **2.99** | Borderline |

| White, `#90caf9`, `#26c6da`, `#ffee58`, `#ffb300`, `#b0bec5` | ≥ 5.4 | OK |

### Pitfall 12: QsWindow attached object before reparent
The content item is declared as `StyledPopup`'s default `contentItem` and reparented into `popupBackground` (`StyledPopup.qml:14-15,163`). Until the window loads, `QsWindow.window` is likely null, so size bindings must use `?.` with fallbacks. Docs: `itemPosition` / `itemRect` / `mapFromItem` "Does not update reactively" [CITED: quickshell.org/docs/v0.2.1/types/Quickshell/QsWindow].
