## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] hoverMouse.lastIdx reset when the popup clears the slot**
- **Found during:** Task 1 (previous executor)
- **Issue:** `hoverMouse.lastIdx` is the dedupe guard for the index. If the popup closes while the pointer is on hour N, the popup resets hoverSlot to -1 but lastIdx stays N. After reopening, hovering the same hour would emit nothing, and no tooltip would appear.
- **Fix:** WeatherGraph.qml has `onHoverSlotChanged: { if (root.hoverSlot < 0) hoverMouse.lastIdx = -1; }`. It only reads hoverSlot, so the zero-write assert still holds.
- **Files modified:** restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml
- **Verification:** S5 "WeatherGraph.qml never assigns hoverSlot" passes. The handler is outside the hoverMouse block and calls no repaint.
- **Commit:** 1c9f4ce9

**2. [Rule 3 - Blocking] Reset assert tolerant of qmlformat line wrapping**
- **Found during:** Task 3
- **Issue:** The planned literal `if (!root.active) root.hoverSlot = -1` is split across two lines by qmlformat, so a single-line grep could never match.
- **Fix:** The assert collapses whitespace in WeatherPopup.qml and matches `function onActiveChanged() { if (!root.active) root.hoverSlot = -1;`.
- **Files modified:** scripts/phase54.4-weather-assert.sh
- **Commit:** fc330653
