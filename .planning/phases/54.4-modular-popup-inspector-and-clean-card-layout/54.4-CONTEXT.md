# Phase 54.4: Modular Popup Inspector and Clean Card Layout - Context

**Gathered:** 2026-10-16
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase redesigns the **hourly graphs** of `WeatherPopup` and sizes the popup.

It replaces the five stacked 54.3 `WeatherGraph` instances (temp, wind, aqi, baro, uv) with **three compact graphs side by side**:
- Graph 1: Temperature.
- Graph 2: Rain, Wind & Visibility.
- Graph 3: Air, UV & Pressure.

The graphs sit below the current-conditions section in a popup sized as a percentage of the screen, with no scrolling. This absorbs backlog **999.1** (redesign 5 stacked graphs into 2–3 compact graphs, no scrolling).

**Scope change vs ROADMAP goal (user decision):** this phase covers the hourly graphs only. The roadmap goal's non-graph items move to a later phase. The recommendation is to insert **Phase 54.5** for them. Run `/gsd-insert-phase` or edit ROADMAP.md before planning 54.5. The moved items are:
- Hero location/observation header redesign
- Daily stat pills (Min/Avg/Max, Sun hours, UV max)
- Astronomy sun/moon card
- Multi-day forecast strip
- The fate of the Atmospheric/Wind/AQI cards

In 54.4 the top section keeps the existing `WeatherAlertBanner` and `WeatherHeroCard` unchanged.

</domain>

## Implementation Decisions

### Superseded Phase 54.3 decisions
- **D-54.4-00:** The following 54.3 decisions are superseded by this phase. Planner and executor must treat them as void:
  - D-54.3-08 (uniform dual-tier on every card)
  - D-54.3-09 (rain bars in the temp card; only its dashed feels-like part survives)
  - D-54.3-10..14 (per-tab / per-metric charts)
  - D-54.3-13 (hPa display; the graph uses atm)
  - D-54.3-16 (temp `colPrimary` and rain theme tokens; replaced by fixed palettes)
  - D-54.3-19 (tooltip readouts)
  - D-54.3-20 (relative "+4h/-4h" time tags)
  - D-54.3-26 (24h axis labels)

  The locked 54.3 `windGraph`, `aqiGraph`, `baroGraph`, `uvGraph` instances in `WeatherPopup.qml` are removed. — **Reversibility:** costly — `WeatherGraph.qml` (1376 lines) is restructured around three graph kinds instead of five `activeMetric` modes.

### Popup layout and sizing
- **D-54.4-01:** Non-graph content is on top and the graphs are below.
  - Top section, this phase: `WeatherAlertBanner` (when present) plus `WeatherHeroCard`.
  - `WeatherAtmosphericCard`, `WeatherWindCard`, `WeatherAqiCard`, `WeatherAstronomyCard` are **hidden, not deleted**, until the later phase.
  - `WeatherWindCard` compass code must not be touched.
- **D-54.4-02:** The three graphs sit **side by side horizontally** in this order: left Graph 1 Temp, middle Graph 2 Rain/Wind/Vis, right Graph 3 Air/UV/Pressure. All three cards have **equal width and equal height**.
- **D-54.4-03:** Popup size is computed from the popup's own screen (`QsWindow.window.screen`).
  - Add config keys `popupWidthPercent: 50` and `popupHeightPercent: 50` under `Config.options.bar.weather` (`modules/common/Config.qml`, the `bar.weather` JsonObject).
  - Enforce a minimum popup width of ~900px so each graph stays at least ~280px wide.
  - Clamp the popup to the screen.
  - This replaces the fixed `implicitWidth: 880` and the 85% max height.
  - The popup must not scroll.
- **D-54.4-04:** **No drag-to-resize** in this phase; it is deferred. Reasons:
  - A layer-shell `PanelWindow` has no native resize, so a custom grip is needed.
  - The popup closes on hover-out during a drag.
  - The centered anchor grows the popup on both sides.
  - Writing `config.json` on every frame causes churn.
  - The Canvas repaint cost is high.
- **D-54.4-05:** Every graph card reserves the **same left gutter** (the temp y-label width, ~24px), so plot areas line up hour for hour across all three cards.
- **D-54.4-06:** Every graph has its **own x-axis**, identical across the three graphs.
  - 7 ticks (`axisStride` 4 over the 25-slot timeline, indices 0,4,…,24).
  - Each tick has two rows: the condition icon, and the short 12-hour clock time ("3AM", "11PM").
  - The center tick (index 12) reads "Now".
  - Relative "+4h/-4h" labels are removed. There is no wind-speed row.
- **D-54.4-07:** **Synced hover.** Hovering an hour on any graph draws the scrub line and point markers for that hour on all three graphs, and shows **all three tooltips at once**. The user accepted that the tooltips cover the graphs.
- **D-54.4-08:** Tooltips may float above neighbouring cards. They must not be clipped to their own card.
- **D-54.4-09:** Every graph card has a **legend row** at the top: series names in their colors, with a swatch that shows the line style. This gives all three cards the same structure, so plot tops align.
- **D-54.4-10:** Peak labels (each series' max value written at its high point in the series color) must be nudged so they don't collide. Narrow cards make overlap likely.
- **D-54.4-11:** All fixed colors must have contrast on a dark background. The popup is **always dark**. Graph palettes are fixed weather colors, not theme tokens.
- **D-54.4-12:** Tooltip rule: each graph's tooltip shows the values drawn in that graph, as compact grouped lines with an outline icon per topic.

### Graph 1 — Temperature
- **D-54.4-13:** Temperature is a smooth curve using the existing monotone cubic (Fritsch–Carlson) spline (`computeMonotoneSplineControlPoints`, `WeatherGraph.qml:40`).
- **D-54.4-14:** Temperature line color is a fixed ramp: blue ≤20°C, amber ~28°C, red ≥34°C. It is applied as a vertical `createLinearGradient` stroke with stops pinned to the temperature Y positions.
- **D-54.4-15:** Feels-like is a **dashed spline**: no band, no fill between the curves.
- **D-54.4-16:** Y-axis:
  - A gridline every 1°C, always.
  - Labels every 1°C when rows are at least ~12px apart, otherwise auto-thinned to every 2°C.
  - This is the only graph with y-axis labels.
- **D-54.4-17:** Series excluded from the canvas:
  - Dew point: tooltip only.
  - Heat index: not shown. `HeatIndexC == FeelsLikeC` in every slot.
  - Wind chill: not shown. It is ≈ tempC in this climate.
  - Rain: no rain bars in the temp graph. 100% bars would collide with the curves, and mm values would be too tiny to read.
- **D-54.4-18:** Legend: "━ Temp" with a solid ramp swatch, and "┄ Feels" with a dashed swatch.
- **D-54.4-19:** Tooltip, 2 lines:
  - L1 `3PM · <cond icon> Sunny · Humid`
  - L2 `<thermo> 34° (35°) · Dew 18°`, with feels-like in brackets and no "Feels" label.
- **D-54.4-20:** The comfort word is **computed from `dewPointC`**, not taken from the API: <16 Comfortable, 16–20 Humid, 21–23 Muggy, ≥24 Oppressive. It goes after the condition text on L1.

### Graph 2 — Rain, Wind & Visibility
- **D-54.4-21:** Series:
  - Rain probability: spline.
  - Wind speed: solid spline.
  - Gust: dashed spline.
  - Visibility: dotted spline.
  - Rain mm: bars, drawn **only when `precipMM > 0`**.
  - Wind direction: tooltip only.
- **D-54.4-22:** Graph 2 has no y-axis labels or units. Scales:
  - Rain % has its own 0–100 scale, using the full card height.
  - Wind, gust and visibility share a second invisible scale fitted to 0..max of those three.
  - mm bars have their own height scale.
- **D-54.4-23:** Palette (fixed):
  - Rain % uses a vertical-gradient ramp: <30% `#90caf9`, 30–60% `#42a5f5`, >60% `#2979ff`.
  - mm bars are teal `#26c6da` at ~60% opacity.
  - Wind is solid white `#ffffff` at ~90%; gust is dashed white.
  - Visibility uses a dotted ramp: ≥10 km `#66bb6a`, 4–10 `#ffee58`, 1–4 `#ffa726`, <1 `#ef5350`.
- **D-54.4-24:** The mm value is always written **above** its bar. Bars are ~7px wide in a ~300px card, so the value cannot fit inside. This supersedes the earlier inside-the-bar rule.
- **D-54.4-25:** Legend uses short names with color dots: `Rain%`, `mm`, `Wind`, `Gust`, `Vis`.
- **D-54.4-26:** Tooltip, 4 lines:
  - L1 `3PM · <icon> Sunny`
  - L2 `<drop> 40% · 3.2 mm`
  - L3 `<air> 14 km/h · G22 · NNW 340°`
  - L4 `<visibility> 10 km Good`. The word comes from the visibility tier: Good ≥10, Moderate 4–10, Poor 1–4, Fog <1.

### Graph 3 — Air, UV & Pressure
- **D-54.4-27:** Series:
  - **EPA tier ribbon:** a thin strip along the bottom of the plot, colored per hour by the API `epaIndex`.
  - **UV index:** spline, full height.
  - **Solar radiation** (`shortRad`): bars.
  - **Pressure:** spline, in atm.
  - PM2.5 and PM10 are **not plotted**. Their values far exceed the range of the other series. They appear in the tooltip only.
  - `diffRad` and DEFRA are not plotted.
- **D-54.4-28:** Ribbon colors are dark-tuned EPA colors: Good `#66bb6a`, Moderate `#ffee58`, Unhealthy for Sensitive `#ffa726`, Unhealthy `#ef5350`, Very Unhealthy `#ab47bc`, Hazardous `#c2185b`.
- **D-54.4-29:** Solar bars:
  - Own scale, capped to the **lower ~40%** of the plot height, sitting above the ribbon.
  - Amber `#ffb300` at ~45% opacity.
  - The peak W/m² value is written above the tallest bar.
  - The UV line uses the full height, so its peak clears the bar tops.
- **D-54.4-30:** The UV line uses the WHO risk ramp through a vertical gradient: green <3, yellow 3–5, orange 6–7, red 8–10, violet 11+. The user accepted the hue overlap with the AQI ribbon after being warned.
- **D-54.4-31:** Pressure:
  - Shown in **atm**: hPa / 1013.25, 3 decimals.
  - Own invisible scale fitted to the **exact** day min..max. The line fills the full height even for a 0.005 atm change; the user accepted the exaggeration after being warned.
  - Labeled at its high and low points in atm.
  - Drawn as a dashed light grey line `#b0bec5` at ~80%.
- **D-54.4-32:** Legend: `UV`, `Solar`, `AQI`, `Pressure`.
- **D-54.4-33:** Tooltip, 5 lines:
  - L1 `3PM · <icon> Sunny`
  - L2 `<sun> UV 7 High · 855 W/m²`. The UV word is the WHO tier: Low 0–2, Moderate 3–5, High 6–7, Very High 8–10, Extreme 11+.
  - L3 `<air> AQI Moderate · PM2.5 34 · PM10 41`
  - L4 `CO 210 · NO₂ 12 · O₃ 88 · SO₂ 4` (µg/m³)
  - L5 `<gauge> 0.998 atm ↘ Falling`
- **D-54.4-34:** The pressure trend compares the slot with the slot 3 hours earlier. It reads **Steady** when |Δ| < 0.001 atm (~1 hPa), otherwise **Rising ↗** or **Falling ↘**. Edge case (Claude's default, not user-confirmed): a slot with no slot 3h earlier uses the nearest available earlier slot.

### Claude's Discretion
- How to restructure `WeatherGraph.qml`. Options: one component with a `graphKind` of `temp`/`rainwind`/`airuv`, or three thin wrapper components over shared drawing helpers. Constraint: the synced hover state (the shared `activeSlotIndex`) is owned by the popup, not by each graph.
- The exact pixel heights for the legend, plot and x-axis inside the 50% height budget.
- The exact layout algorithm that keeps peak labels from colliding.
- Which outline icons are used for the tooltip topics, chosen from the existing icon set.
- The fallback behavior when the timeline has fewer than 25 slots. This keeps the existing `Weather.hourly` fallback in `WeatherGraph.qml:15`.

## Existing Code Insights

### Reusable Assets
- `computeMonotoneSplineControlPoints(points)` (`WeatherGraph.qml:40`): Fritsch–Carlson spline, reused for every spline series.
- `createLinearGradient` vertical stroke (`WeatherGraph.qml:~1005`): the pattern for the temp, rain %, visibility and UV ramps.
- `ctx.setLineDash` patterns, already used for dashed and dotted lines (`[3,3]`, `[2,3]`, `[4,3]`).
- `calcTempBounds`, `calcWindMax`, `calcBaroBounds`, `calcUvMax`: starting points for the per-series invisible scales.
- `formatTemporalLabel` (`WeatherGraph.qml:339`): to be rewritten for 12-hour clock time plus "Now".
- The axis tick loop (`WeatherGraph.qml:~1159`) and the axis icon repeater (`~1315`): the existing `axisStride` mechanics.
- `Config.options` + `JsonAdapter` / `writeAdapter()` (`Config.qml:11,60`): config persistence for the size keys.

### Established Patterns
- Service data: `Weather.timeline` has 25 slots (-12h..NOW..+12h, `isNow` at index 12). The `time:"24"` daily-summary slot is skipped in `Weather.qml`.
- Slot fields available:
  - Temperature: tempC, feelsLikeC, dewPointC, heatIndexC, windChillC.
  - Rain and sky: rainProb, precipMM, humidity, cloudCover, snowProb, thunderProb.
  - Wind: speedKmph, gustKmph, degree, dir16.
  - Air: epaIndex, defraIndex, pm2_5, pm10, co, no2, o3, so2.
  - Other: pressureHpa, visibilityKm, uvIndex, shortRad, diffRad.
- Today's real ranges: temp 25–34 (feels-like up to 36); wind 6–17, gust up to 33; rain ≤17%; precip 0.0 mm; pressure 1008–1013 hPa (0.995–1.000 atm); visibility 8–10 km; EPA 2–4; UV 0–7; shortRad 0–855 W/m².
- Popup hosting: `StyledPopup` is a `LazyLoader` → `PanelWindow` with a 1000ms hover intent delay. It closes on hover-out.

### Integration Points
- `WeatherPopup.qml`:
  - Replace the `StyledFlickable` (fixed 880 width, 85% height) with a non-scrolling layout sized from the config percentages and the screen.
  - Add a `RowLayout` with the three graph cards.
  - Hide the four bottom cards.
- `Config.qml` `bar.weather` JsonObject: add `popupWidthPercent` and `popupHeightPercent`.
- `GlobalStates.activeInspectorCount` handling in `WeatherPopup.qml` stays unchanged.

<specifics>
## Specific Ideas

- The user wants visual cues and decides one metric at a time. Every encoding above was chosen from ASCII mockups.
- Reference weather apps mentioned as inspiration: Breezy Weather, Apple Weather, Google Weather, yr.no.
- On a 1920×1080 screen the default 50%×50% popup is 960×540. Each graph is ~300px wide (~285px plot, ~11.5px per hour), and ~370px per graph is left below the top section.
