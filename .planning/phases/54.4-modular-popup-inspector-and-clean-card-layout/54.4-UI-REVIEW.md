## Top 3 Priority Fixes

1. **Three simultaneous tooltips can overlap each other** (WARNING; WeatherPopup.qml:206-216). A wide tooltip "floats over the neighbours" with no check against the other two tooltips' rects. Near the card edges, text sits on top of text and the hovered values become unreadable. Fix: compute the three rects in one pass and push colliding ones vertically. Or pin all three tooltips to one shared row above the graphRow.
2. **Canvas text bypasses the theme typography** (WARNING; WeatherGraphMath.js:74-75,1324; WeatherPopup.qml:72-73). `Y_LABEL_FONT = "10px sans-serif"`, `LABEL_FONT = "bold 10px sans-serif"` and `"italic 9px sans-serif"` render in a different family and size from the 12px `Appearance.font.family.main` legend and axis. The 9px "No data" text is below legible size on a 3440x1440 display. Fix: pass `Appearance.font.family.main` and a pixel size of at least 11 through `theme()` into GM, and use them in the gutter TextMetrics as well.
3. **No overflow path when content exceeds the height budget** (WARNING; WeatherPopup.qml:56-62, review WR-05). `minContentH` grows with the alert banner, and with no scroll fallback, the graphs shrink to their `Layout.minimumHeight: 120` or get clipped. Fix: cap the alert banner height with an elided or expandable body, or let the popup grow up to the screen clamp before the graphs shrink.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- WARNING: GM.tooltipLines (WeatherGraphMath.js:1701) and the canvas hatch label (:1324-1330) both say "No data". It does not tell the user why: these are past hours with no history. Use "No history for this hour".
- WARNING: `G22` for gust (D-54.4-26 L3) and the bare `mm` legend label (D-54.4-25) are opaque to a first-time reader. "Gust 22" costs 3 characters, and "Rain mm" disambiguates.
- Positive: the comfort, visibility, UV and pressure tier words (Humid, Good, High, Falling) carry meaning, not just numbers. The centre axis tick says "Now", not a relative offset.
- INFO: the axis icon fallback `"cloud"` (WeatherGraph.qml:355) shows a cloud for a slot with no glyph. That is misleading, and a neutral glyph or blank would be better.

### Pillar 2: Visuals (3/4)
- Positive: equal cards, a fixed 18px legend row and a shared gutter give aligned plot tops and an aligned hour grid (D-54.4-05/09). The "Now" tick is the single colPrimary focal point.
- WARNING: there is no collision handling between the three tooltips (WR-01). The user accepted that tooltips cover graphs, but not that they cover each other.
- WARNING: `placeLabels` reserves no space for the EPA ribbon or the solar/mm bars (WR-08, WeatherGraphMath.js ~1577). Peak labels can sit on the bars.
- WARNING: point markers use the border colour `colLayer2` (WeatherGraph.qml:300), while the cards sit on a layer1/base card. Check the ring contrast against the card fill.
- INFO: the four hidden cards are still instantiated with `visible: false` (WeatherPopup.qml:95-129), so they still bind and compute every update.

### Pillar 3: Color (3/4)
- Positive: all 20+ fixed hex values live only in WeatherGraphMath.js (lines 22-67); the QML files have none (D-54.4-11). colPrimary is used only on the Now tick (WeatherGraph.qml:363) and the `now` theme slot. Accent usage is restrained.
- WARNING: EPA Very Unhealthy `#ab47bc` and Hazardous `#c2185b` are below 3:1 on the dark surface (PA-3, open sign-off). These are the tiers where legibility matters most. Lighten them to around `#ce93d8` and `#f06292`.
- WARNING: the UV ramp and the EPA ribbon reuse identical hex values `#66bb6a`, `#ffee58`, `#ffa726` and `#ef5350` (lines 52 and 59) in the same plot. The user accepted the overlap, but there is still no shape cue to tell them apart.
- WARNING: the legend label colour for Temp/Feels is a single amber `#ffb300` (line 1102-1103), while the line is a blue-amber-red ramp. On cool days the label colour does not match the drawn line.
- INFO: `THEME_FALLBACK` (line 1205) duplicates theme colours as hex. This is acceptable as a guard.

### Pillar 4: Typography (2/4)
- Sizes in use: canvas 9px and 10px; legend, axis and tooltip at `Appearance.font.pixelSize.smaller`; icons at 14 (axis and tooltip). Legend text is also scaled by `legendFit.scale` below 900px (WeatherGraph.qml:109-110), so its effective size varies by card width. That is at least 4 sizes inside a single card, with mixed families.
- WARNING: three different font families are in use. The canvas uses `sans-serif` (GM:74-75, 1324), the gutter TextMetrics uses `sans-serif` at 10px (WeatherPopup.qml:72-73), and the QML text uses `Appearance.font.family.main`. The gutter width is measured with the canvas font, so it is correct for the y-labels. But y-labels and peak labels look different from every other label in the card.
- WARNING: italic 9px "No data" is the smallest text in the shell.
- WARNING: `scale` on a Row (WeatherGraph.qml:110) shrinks the text rasterisation as well. Below the minimum width, legend labels can drop under 10px effective size. Dropping the dots, or wrapping, would keep the size fixed.
- Weights: Bold (tooltip lead, Now tick, canvas peak labels) and Normal. Fine.

### Pillar 5: Spacing (3/4)
- Positive: a 12px rhythm for contentColumn and graphRow gaps (WeatherPopup.qml:80,97,115,136). Tooltip offset rules are consistent (8 above, 14 below).
- WARNING: magic numbers have no shared token: `plotTop: 16`, `plotRight: width - 8` (WeatherGraph.qml:29-31), legend 18, axis 32, tooltip padding 20/12 with x:10 and y:6 (WeatherPopup.qml:202-231), and `+ 6` gutter padding with `+ 240` minimum graph height (:61,65). Horizontal and vertical tooltip padding are unequal (10 vs 6).
- WARNING: `plotRight` reserves 8px on the right, but there is no matching left inset beyond the gutter. The last-column mm label is cut off (the plan 06 trade-off is still pending sign-off).
- INFO: the axis tick Column has `spacing: 0`, so the icon and the time label touch at 14px icon size.

### Pillar 6: Experience Design (2/4)
- WARNING: interaction is pointer-hover only (`MouseArea hoverEnabled`, `acceptedButtons: Qt.NoButton`, WeatherGraph.qml:305-328). There is no keyboard scrub and no click-to-pin. Because the popup closes on hover-out, a reading cannot be held while the user moves the pointer.
- WARNING: there is no loading or empty state for a card. When `Weather.timeline` and `Weather.hourly` are both empty, `validHours` is [] and the card shows an empty plot and axis with no message. Only the per-hour "No data" exists.
- WARNING: in the `Weather.hourly` fallback, missing fields map to 0 (WR-09). That shows 0°C and "Fog", which are wrong values presented as real ones.
- WARNING: no overflow fallback with a long alert (WR-05). See fix 3.
- Positive: hover clears on exit and on popup close (WeatherPopup.qml:41-47, WeatherGraph.qml:324-327, 384-387). Repaint is gated to the open popup, and paint errors are caught and logged once. The CR-01 screen clamp is now fixed in StyledPopup.qml:69,93.
- Unverified: synced hover, the tooltip float and centring on DP-1 are still human checks (VERIFICATION "Human Verification Required" 1-4).
