## Warnings

### WR-01: Three simultaneous tooltips overlap each other when one is wider than its card

**Status:** open (carried forward; `WeatherPopup.qml` not re-reviewed)

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherPopup.qml:184-216`

**Issue:** `tooltipLayer` shows one tooltip per graph whenever `hoverSlot >= 0`, so three tooltips appear at once. When `tip.width > tip.modelData.width`, `x` is only clamped to the whole layer (`Math.max(0, Math.min(tooltipLayer.width - tip.width, want))`). It can then float over a neighbouring card, where that card's own tooltip is already drawn.

At the 900px minimum outer width each card is about 278px wide. Realistic airuv line 3 (`"AQI Unhealthy for Sensitive · PM2.5 35 · PM10 50"`) or a long `desc` header at 12px exceeds that. For late slots the airuv tooltip is clamped to the layer's right edge and its left edge overlaps the rain card's tooltip, so the text is drawn on top of other text.

**Fix:** Either show the tooltip only for the card under the cursor (record the source graph id with `hoverRequested`), or bound each tooltip to its own card and wrap its text:
```qml
// in tipBody / text rows
Layout.maximumWidth: tip.modelData.width - 20
wrapMode: Text.WordWrap
```
and drop the "float over neighbours" branch.

### WR-03: The fixed palette ignores the light theme; wind and gust are pure white

**Status:** open

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraphMath.js:42`, `:1111-1112`, `:67`; `WeatherGraph.qml:240`

**Issue:** `WIND_COLOR = "#ffffff"` (alpha 0.9) is used for:
- the wind and gust lines
- their markers
- their peak labels
- the legend dot and the legend label text (`color: entry.modelData.color`)

In a light Material scheme, `colLayer2` is near white, so these elements disappear. `PRESSURE_COLOR "#b0bec5"` and the yellow tiers (`#ffee58`) are also near-invisible on light surfaces. The PA-3 contrast checks in `phase54.4-weather-assert.sh` only test against the dark surfaces `#1f2020` and `#292a2a`.

Alternatively, keep separate light and dark palettes selected by `Appearance.m3colors.darkmode`, and add light-surface rows to the contrast check.

### WR-05: Removing the scroll container lets content become unreachable when the alert drawer or banner is tall

**Status:** open (carried forward; `WeatherPopup.qml` not re-reviewed)

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherPopup.qml:56-62`, `WeatherGraphMath.js:126-129`

**Issue:** `height = Math.min(maxH, Math.max(minContentH, ...))`. If `alertBanner` grows past the cap (its advisory drawer expands with `WordWrap` text, `WeatherAlertBanner.qml:143-160`), `minContentH` can exceed `maxH`:

`alertBanner.implicitHeight + heroCard.implicitHeight + 24 + 240 > maxH`

The height is then capped at `maxH`, but the `ColumnLayout` children still demand their minimum sizes (`graphArea` has `Layout.minimumHeight: 120`). The content overflows the bottom of `contentRoot` and the layer-shell window, with no way to scroll to it. The popup height also changes on every frame of the Revealer animation. **Fix:** Cap the drawer height inside `WeatherAlertBanner`, for example `Layout.maximumHeight` with its own small `Flickable` limited to the alert text. Alternatively, have `popupContentSize` report `overflow: minContentH > maxH` and shrink the graph row's minimum.

### WR-06: Popup size math ignores the vertical-bar geometry

**Status:** open. 0277af6a gave the vertical branch clamp parity but did not change `popupContentSize`.

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraphMath.js:125-126`, `WeatherPopup.qml:56-62`, `StyledPopup.qml:110`

**Issue:** `maxW = sw - 2*edgeGap - chrome` assumes the popup can use the full screen width. In vertical-bar mode, `StyledPopup` places it at `lockedLeftMargin = Appearance.sizes.verticalBarWidth` and does not clamp the horizontal extent at all. At `popupWidthPercent` near 100 the popup therefore extends `verticalBarWidth - edgeGap` px past the right edge. `maxH` also always subtracts `barHeight`, which does not exist in vertical mode. `sanePercent` allows up to 100, so this is reachable from `config.json`.

**Fix:** Pass the bar orientation in `opts`:
```js
var barW = isNum(o.barWidth) ? o.barWidth : 0;   // verticalBarWidth when vertical, else 0
var maxW = sw - barW - 2 * edgeGap - chrome;
var maxH = sh - barHeight - 2 * edgeGap - chrome; // pass barHeight: 0 when vertical
```
and pass `barWidth`/`barHeight` from `Config.options.bar.vertical` in `WeatherPopup.qml`.

### WR-07: Assert harness fails open and its QML gate checks syntax only, so it cannot catch the load-time bug class seen before

**Status:** open. 54.4-09 and 54.4-10 did not change this.

**File:** `scripts/phase54.4-weather-assert.sh:367-372` (`run_node_section`), `:449-452` (`measure_legend_labels`), the `qmlformat` gate, and the `top_children` grep in S5

**Issue:**

**Fix:** Make a missing `node` a `fail`, or require `--allow-missing-node`. Add a real type check, such as `qmllint` with the Quickshell import path that fails on `[missing-property]`, `[incompatible-type]` and `[unresolved-type]`. Alternatively, add a short headless load (`QT_QPA_PLATFORM=offscreen qml6 ...`) of a stub that instantiates `WeatherGraph`. The new legend probe shows `qml6` offscreen works on this host.

### WR-08: Peak labels can be drawn over the EPA ribbon and over bars, contrary to D-54.4-27/29

**Status:** open

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraphMath.js:1649-1654`

**Issue:** `drawKind` always calls `placeLabels(..., { bottom: geom.plotBottom }, [])`, so nothing is ever reserved.

For airuv, the series are drawn above `airuvRibbonTop(geom) = plotBottom - 6`. A "below" pressure-low label at marker y in `(plotBottom-19, plotBottom-13]` passes the bounds test but covers the ribbon. No bar rects are reserved either, so rain/wind/vis/UV labels can sit on top of mm or solar bars.

**Fix:**
```js
var reserved = [];
if (kind === "airuv") reserved.push({ x: geom.plotLeft, y: airuvRibbonTop(geom), w: geom.plotRight - geom.plotLeft, h: RIBBON_H });
// optionally push mmBarRects / solarBarRects too (excluding each bar's own bar-top label)
drawLabels(ctx, placeLabels(cands, bounds, reserved));
```

### WR-09: Missing raw fields are turned into real-looking readings (0°C, 0 km "Fog", UV 0)

**Status:** open

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraphMath.js:160-225` (`normalizeRawHour`), `:141-149`

**Issue:** In the `Weather.hourly` fallback path:
- A missing or unparsable `tempC`/`FeelsLikeC` becomes `0`.
- A missing `visibility` becomes `0`. It is then drawn as a red "Fog" segment, and peaks and tooltips read "0 km Fog".
- UV, wind and humidity also default to `0` through `_int`/`_float`.

`seriesRuns` only breaks a run on non-finite values, so these zeros are plotted as real data. This contradicts the module's own rule ("A missing value breaks the run").

**Fix:** Return `null` for unparsable values in the graph normaliser (`function _intOrNull(v) { var n = parseInt(v, 10); return isNaN(n) ? null : n; }`) and let `isNum` drop them.

### WR-10: Narrow legend tiers clip a colour out of the Vis swatch on the default 1920x1080 screen; the harness claims every swatch is kept

**Status:** new (db9e7724)

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml:147-152`, `:189-206` (dotted), `:171-187` (dashed), `:217-233` (ribbon); `WeatherGraphMath.js:1139-1143` (`LEGEND_TIERS`), `:1112` (Vis entry); `scripts/phase54.4-weather-assert.sh` S4 (`"every dot, swatch and name kept"`)

**Issue:** `swatch` now has `width: legendRow.fit.swatchW` and `clip: true`. Its sub-patterns still use the fixed geometry from the 14px tier:

| Pattern | Geometry | Positions |
|---|---|---|
| dotted | 4 dots, 2px each, spacing 2 | x = 0, 4, 8, 12 |
| dashed | 3 segments, 3px each, spacing 2 | x = 0, 5, 10 |
| ribbon | 3 blocks, 4px each, spacing 1 | x = 0, 5, 10 |

The rainwind "Vis" entry is `style: "dotted"` with `colors: VIS_COLORS` (`#ef5350, #ffa726, #ffee58, #66bb6a`), and `partColor(index, 4)` gives each dot its own tier colour. The entry's dot and label use `color: VIS_COLORS[3]` (`#66bb6a`, green).

- At tier 1 (`swatchW: 12`), the fourth dot sits at x = 12..14. That is entirely outside the clip, so the green dot disappears. Tier 1 is the tier rainwind uses on the 1920x1080 default (harness sweep: `rainwind at 1920x1080 (278px): tier 1`). At tier 2 (`swatchW: 10`, the 900px minimum, 1280x720) it is gone as well.
- On the most common screen, the Vis swatch therefore shows red, orange and yellow only. Its colour dot and its "Vis" label are green, a colour the swatch no longer contains. This legend misleads.
- The same mechanism removes the third Gust dash at tier 2 and cuts the third AQI ribbon block (orange, "Unhealthy for Sensitive") to 2px at tier 1. At tier 2 that block is removed completely, which happens when the airuv legend area is below 192px.
- PA-G5 accepted "dotted three dots", but the plan did not account for the fact that the dropped dot carries the entry's own colour.
- The S4 assert message `"rainwind at 258px uses tier 2 at scale 1 (... every dot, swatch and name kept)"` is false. The only width checked is `width * scale`; nothing checks the swatch contents.

**Fix:** Derive the pattern geometry from the swatch width so every part stays visible at every tier, instead of clipping:
```qml
// dotted: four dots spread across the swatch
Row {
    visible: entry.modelData.style === "dotted"
    anchors.verticalCenter: parent.verticalCenter
    spacing: Math.max(0, (swatch.width - 4 * 2) / 3)
    ...
}
// dashed: three segments, gap 2
delegate: Rectangle { width: Math.max(1, (swatch.width - 2 * 2) / 3); height: 2; ... }
// ribbon: three blocks, gap 1
delegate: Rectangle { width: Math.max(1, (swatch.width - 2 * 1) / 3); height: 4; ... }
```
Then drop `clip: true`, or keep it only as a safety net. Add a GM-level assert that each pattern's extent at every `LEGEND_TIERS[k].swatchW` is no more than `swatchW`, and fix the S4 message.

### IN-06: The canvas is not repainted on theme change; units ignore `useUSCS`

### IN-07: The below-minimum legend fallback scales native-rendered text

**Status:** new (db9e7724)

**File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml:109-110`, `:236-242`

**Issue:** When no tier fits, `legendRow.scale` drops below 1 (0.781 for rainwind on a 720px-wide logical screen). The labels are `StyledText` with `renderType: Text.NativeRendering`. Qt documents that native-rendered text looks poor under scale transforms, because glyphs are rasterised at the unscaled size and then resampled. The legend on a portrait output (HDMI-A-2) will look blurry or jagged. This only applies below the 900px minimum.

**Fix:** In the fallback tier, override `renderType: Text.QtRendering` on the legend labels (`renderType: legendRow.fit.scale < 1 ? Text.QtRendering : Text.NativeRendering`). Alternatively, add a fourth tier that drops `swatchW` and the gaps further before scaling.

### IN-08: Harness sweep and live-font probe model the layout and font with literal constants instead of reading them from source

**Status:** new (db9e7724, 12a06ee6)

**File:** `scripts/phase54.4-weather-assert.sh`: `measure_legend_labels` (`font.variableAxes: ({"wght": 450, "wdth": 100})`, the `property string main:` sed); the S4 sweep (`chrome: 40, edgeGap: 5, barHeight: 40`, `(content - 24) / 3 - 20`) and `minAvail = Math.floor((G.MIN_OUTER_W - 40 - 2 * 12) / 3) - 20`

**Issue:** The "not clipped" and "keeps scale 1" asserts are only valid while several hand-copied values still match the source:
- `graphRow.spacing: 12` (WeatherPopup.qml)
- `anchors.margins: 10` (WeatherBaseCard.qml)
- `chrome = elevationMargin * 2 + 20`
- `Appearance.font.variableAxes.main`

The probe also takes the first `property string main:` in `Config.qml`. That is `fonts.main` today, but nothing ties the match to the `fonts` object. If any of these changes, the sweep keeps passing while the real legend clips. The runtime is safe, because `fit` reads the real `legendRow.width`, but the gate no longer tests reality. This is the same fail-open class as WR-07.

**Fix:** Extract the constants from the sources with guarded greps, and `fail` when an extraction is empty (`spacing: 12` within `id: graphRow`, `anchors.margins` in `WeatherBaseCard.qml`, `wght`/`wdth` in the vendor `Appearance.qml` `variableAxes.main`). Anchor the font sed to the `property JsonObject fonts` block.

### IN-09: The SIGINT/TERM trap returns, so Ctrl-C does not stop the harness

**Status:** new. This existed before the phase, but the 20s `timeout ... qml6` probe makes it easier to hit.

**File:** `scripts/phase54.4-weather-assert.sh:87-97`

**Issue:** `trap cleanup EXIT INT TERM` runs `cleanup`, which deletes the `TMP_DIRS` and then `return`s. In a non-interactive bash script, a returning INT handler resumes execution:
1. A Ctrl-C during `measure_legend_labels` kills `qml6`.
2. The probe dir is deleted.
3. The probe records a FINDING, and the remaining sections keep running.
4. The script ends with whatever exit code it reaches, so an interrupted run can report success.

**Fix:** Use separate handlers:
```bash
trap cleanup EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
```
The EXIT trap still cleans up.
