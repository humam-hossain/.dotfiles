<objective>
Close verification gap 1 (SC1, POPUP-01, review CR-01 critical): the weather popup opens several hundred px left of the weather pill on the 3440px DP-1 output.

Root cause: `StyledPopup.updateLockedMargins()` takes the screen size from a `screen` property on root's attached `QsWindow` object. `QsWindowAttached` has no such property (`/usr/lib/qt6/qml/Quickshell/_Window/quickshell-window.qmltypes` lists only window, contentItem, itemPosition, itemRect and mapFromItem). The read is always undefined, so the clamp always runs against a 1920 x 1080 fallback. With the new 1700px background, maxX = 1920 - 1700 - 5 = 215.

Fix: resolve the screen through the hover target's attached window, then the popup window, then 1920 x 1080. Account for the 10px elevation inset of the visible background. Guard a null hover target. Bind the PanelWindow to the bar's screen. Then prove the placement in Node vm by running the real QML function body.

Purpose: POPUP-01 requires the popup to be anchored under its pill and clamped to the screen. The re-clamp hook added in plan 01 fires, but it calls a clamp that never sees the real screen.

Output: a fixed `StyledPopup.qml` and new S1/S2 asserts in `scripts/phase54.4-weather-assert.sh`.
</objective>

## Planner Assumptions (recorded, reversible)

- **PA-G1 (visible-background inset):** the clamp and the centring both account for `Appearance.sizes.elevationMargin`. On the anchored edge, `popupBackground` starts 10px inside the PanelWindow. Without the inset the background sits 10px right of the pill centre, and a right-edge clamp lets it run 5px past the screen. `minX` stays `hyprlandGapsOut` so no layer-shell margin is ever negative. The visible left inset at the clamp is therefore 15px, and the right inset is 5px.
- **PA-G2 (mapping source):** the target point is mapped through the hover target's own attached window, `root.hoverTarget.QsWindow?.mapFromItem(root.hoverTarget, …)`. That is the same attached object the screen comes from, and the hover target is always a QQuickItem in the bar window. When root's attached window resolves, the result is the same.
- **PA-G3 (screen binding):** the verifier listed binding the PanelWindow screen as optional. It is adopted here for all six consumers, so popup placement is deterministic per bar output and WeatherPopup's `contentRoot.QsWindow.window.screen` returns the bar's screen.
