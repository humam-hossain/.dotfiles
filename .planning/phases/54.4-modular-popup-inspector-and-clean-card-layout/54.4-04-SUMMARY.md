## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The 54.3 leaf-symlink assert failed only because it ran from a linked worktree.**
- **Found during:** Task 1
- **Issue:** `readlink -f` of the live `WeatherGraph.qml` resolves to the main checkout, but the assert compared it against `$REPO_ROOT`, which is the worktree. It would FAIL in every parallel-executor run, although nothing in the code had regressed.
- **Fix:** Added the same MAIN_ROOT / IN_LINKED_WORKTREE detection the phase54.4 harness uses. The assert also passes when the run is from a linked worktree and the link targets `$MAIN_ROOT/<rel>`. It still FAILs for any other target or for a regular file.
- **Files modified:** scripts/phase54.3-weather-assert.sh
- **Verification:** `--quick` passes, with the message "(linked worktree run)".
- **Committed in:** `21872c7e`

**2. [Rule 1 - Bug] A chained `grep -A 25 | grep -q` was SIGPIPE-prone in the phase54 harness.**
- **Found during:** Task 2
- **Issue:** Converting the leading `echo |` to a here-string would still have left `grep -A 25 ... | grep -q`. That pipe can flake under pipefail the same way.
- **Fix:** `grep -q 'requestPaint' <<<"$(grep -A 25 'onPositionChanged:' <<<"$graph_code")"`. The pattern, flags and message are unchanged.
- **Committed in:** `27f252a6`
