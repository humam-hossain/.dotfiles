## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Live user files → Backup archive (`$HOME/.dotfiles-backup.<epoch>/`) | Upstream stubs and conflicting files moved out of `$HOME` into backup storage |
| Git repository (`stow/`, `restow/`) → Live user `$HOME` | Symbolic links created into personal dotfiles packages |
| Repository capture baselines (`capture/`) → Live `$HOME` | Baseline configuration files copied directly into user configuration trees |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-23-05 | Tampering | De-stubbing Engine | high | mitigate | Archive all conflicting regular files to `$HOME/.dotfiles-backup.<epoch>/` with SHA-256 `MANIFEST.txt` before unlinking; strictly forbid `stow --adopt` (per D-16) |
| T-23-06 | Tampering | Guarded Paths | high | mitigate | Cross-reference conflicting files against `guard-paths.tsv` and skip any matching path; never delete or unlink guarded theme outputs (per D-17) |
| T-23-07 | Tampering | GNU Stow Directory Folding | medium | mitigate | Pre-create sensitive parent directories (`gtk-3.0`, `gtk-4.0`, `hypr/custom`, `systemd/user`) with `mkdir -p` before running stow with `--no-folding` (per D-14) |
| T-23-08 | Denial of Service | Capture Baseline Seed | medium | mitigate | Validate syntax of all `.json` files via `jq empty` before deployment; write to `${target}.tmp.$$` and rename atomically (per D-19) |
