<objective>
Perform every live-side operation in this phase, in one place, in the main worktree, after every
repo-side move has landed.

This plan exists because of where GNU Stow points. Plans 18-04, 18-06 and 18-08 each have more than
two tasks and no decision checkpoint, so each dispatches to a subagent; with worktree isolation
enabled — the default — that subagent runs in a per-agent worktree that is removed when the wave
completes. A `stow` run from inside one creates links resolving into that worktree, and every one of
them dangles the moment it is torn down. The operator's Hyprland session, kitty, zsh, dolphin and
qBittorrent configuration would all resolve to nothing at once.

The obvious repair — resolve the main worktree root and stow from there — does not work inside those
plans either, and this was measured rather than assumed: a package created by `git mv` inside a
worktree exists only in that worktree until the wave merges, so the main root has no such package to
stow. The only correct structure is to separate the repo-side placement from the live-side link, and
that is what this plan is.

Doing it this way is also safer than the per-plan alternative it replaces. All live-desktop mutation
is concentrated in one deliberate pass, after the map, the moves, the removal, the retargeting and
every assert section have landed and been reviewed — and the live configuration keeps working from
its existing plain files the entire time until then.

D-51's sequence completes here: map, move, re-stow, verify.

Purpose: link what the phase moved, unfold what is still folded, and prove both.
Output: no repo change — live symlinks, a green `verify`, and a green phase gate.
</objective>
