## Historical Cache & Rollover Architecture

| Option | Description | Selected |
|--------|-------------|----------|
| Unified envelope in weather.json | Embed a `history` array directly into the existing `weather.json` payload; Weather.qml reads a single atomic file with zero multi-file race conditions. | ✓ |
| Separate history.json cache file | Store historical hourly data in a dedicated `$XDG_RUNTIME_DIR/weather/history.json` file. | |
| Rolling hourly snapshot database | Maintain a small rolling JSON log file in `~/.local/state/weather/`. | |

**User's choice:** Unified envelope in weather.json  
**Notes:** Single file ensures atomic updates via `os.replace` without multi-file synchronization issues in QML.

| Option | Description | Selected |
|--------|-------------|----------|
| Dynamic date transition check on fetch | When wwo-fetcher.py fetches fresh data, if the calendar date has advanced, it promotes yesterday's `weather[0]` into `history` and retains up to 24h of past hourly slots. | ✓ |
| Continuous rolling merge on every fetch | On every fetch execution, merge past hours into a rolling 24-hour historical window. | |
| Dedicated systemd midnight timer trigger | Add a separate systemd timer specifically firing at 00:00 to perform cache rollover. | |

**User's choice:** Dynamic date transition check on fetch  
**Notes:** 0 extra API cost; handles system sleep, reboots, and multi-hour gaps automatically.

| Option | Description | Selected |
|--------|-------------|----------|
| 24 hours of history (Yesterday's full 24 hourly slots) | Retains complete previous day forecast/observations (~15-20 KB JSON); guarantees 100% coverage for the [-12h] past window even at 00:05 AM. | ✓ |
| Rolling 48 hours of history | Retains two full previous days (~35-40 KB JSON). | |
| Strict 12 hours trimmed window | Retains only the exact 12 past hourly slots required by the timeline. | |

**User's choice:** 24 hours of history (Yesterday's full 24 hourly slots)  
**Notes:** Optimal balance of historical coverage and minimal storage/memory footprint.

| Option | Description | Selected |
|--------|-------------|----------|
| Unconditionally preserve history during error/offline states | Ensure error envelopes copy `history` from previous cache alongside `data`, allowing Weather.qml to render the full 25-point timeline seamlessly in stale mode. | ✓ |
| Drop history when stale | Clear history in error states and fall back to single current condition reading. | |

**User's choice:** Unconditionally preserve history during error/offline states  
**Notes:** Offline resilience matches Phase 51 principles.

| Option | Description | Selected |
|--------|-------------|----------|
| Top-level peer key `"history"` containing yesterday's WWO day object | Keeps raw `data` completely untouched for 100% backward compatibility with Phase 51/52/53 consumers. | ✓ |
| Flattened hourly array `"history": [ { ... } ]` | Pre-flatten the hourly slots into a single chronological array. | |
| Embed directly inside `"data.history"` | Modify the inner WWO payload tree to inject `history` under `data`. | |

**User's choice:** Top-level peer key `"history"` containing yesterday's WWO day object  
**Notes:** Array of day objects `history: [ yesterdayDayObject ]` preserves raw compatibility.

| Option | Description | Selected |
|--------|-------------|----------|

## Live Condition vs Hourly Forecast Alignment

| Pure hourly forecast slot | Leave index 12 as the forecast prediction; keep live `current_condition` completely decoupled. | |

**User's choice:** Populate NOW slot with live observations  
**Notes:** Guarantees center hairline matches status bar pill and hero card temperature exactly.

| Option | Description | Selected |
|--------|-------------|----------|

**User's choice:** Hybrid blend

**Notes:** Mathematically sound; avoids artificial data distortion.
