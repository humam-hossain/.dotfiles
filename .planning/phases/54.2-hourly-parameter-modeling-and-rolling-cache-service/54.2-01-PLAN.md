### ASVS L1 Security & STRIDE Threat Register
- **Trust Boundaries**: Background process boundary, tmpfs filesystem (`$XDG_RUNTIME_DIR/weather/`), persistent storage (`$XDG_STATE_HOME/weather/`), external API endpoint.
- **T-54.2-01: Root Privilege Execution (ASVS V1 - Principle of Least Privilege)**:
  - *Threat*: Fetcher executing with root privileges altering permissions or ownership of user cache files.
  - *Mitigation*: Service runs strictly under `systemd --user`. Assert harness enforces `EUID != 0`.
- **T-54.2-02: Partial File Read / Race Conditions in Quickshell (ASVS V11 - Data Integrity)**:
  - *Threat*: Quickshell reading `weather.json` while `wwo-fetcher.py` is writing, leading to JSON parse exceptions or UI flicker.
  - *Mitigation*: POSIX atomic replace via unique PID temporary file + `fsync` + `os.replace` on tmpfs per D-54.2-16. Single unified envelope embeds `"history"` directly per D-54.2-09.
- **T-54.2-03: Multi-Day Stale Telemetry Masquerading as Live/Yesterday Weather (ASVS V11 - Data Authenticity)**:
  - *Threat*: Machine sleeping or powered off for 3 days retains 3-day-old telemetry in `"history"`, misleading the operator into believing it was yesterday's weather.
  - *Mitigation*: Strict downtime invalidation: if `day_diff > 1` or `(now_date - cached_date).days > 1`, set `history = []` per D-54.2-15.
- **T-54.2-04: API Quota Exhaustion (ASVS V11 - Availability)**:
  - *Threat*: Attempting to fetch historical data via dedicated API calls consuming free-tier quota (500 calls/day).
  - *Mitigation*: 0-cost local rollover: promote existing `weather[0]` day object in memory without making extra API calls per D-54.2-10.
- **T-54.2-05: Secret Leakage (ASVS V2/V3 - Confidentiality)**:
  - *Threat*: WWO API key leaking into stdout, logs, or error envelopes.
  - *Mitigation*: Strictly omit API keys from stdout and JSON envelopes. Error envelopes record only sanitized error strings.
</threat_model>
