# Phase 54.2: Hourly Parameter Modeling and Rolling Cache Service - Context

**Gathered:** 2026-10-11T19:57:00+06:00  
**Status:** Ready for planning  

<domain>
## Phase Boundary

Build and deliver the continuous `[-12h .. NOW .. +12h]` rolling timeline model, 0-cost midnight cache rollover in `wwo-fetcher.py`, and structured typed QML dataset representations in `Weather.qml` across all 6 meteorological parameter groups (Thermal, Moisture, Wind, AQI, Atmosphere, Solar).

This backend/service phase models the data contract that powers the interactive multi-metric Canvas graph (`WeatherGraph.qml` in Phase 54.3) and modular popup inspector (`WeatherPopup.qml` in Phase 54.4).

**In scope:**
- Extend `stow/weather/.config/weather/wwo-fetcher.py` to support 0-cost midnight historical cache rollover: promote previous day's `weather[0]` into top-level `"history": [ yesterdayDayObject ]` in `weather.json` and persistent `last_known_weather.json`.
- Invalidate historical cache cleanly when machine downtime exceeds 1 calendar day (`cached_date < yesterday`) to prevent misleading multi-day-old telemetry.
- Unconditionally preserve historical cache in `wwo-fetcher.py` during error/offline/stale cache rewrites.
- Extend `restow/quickshell/.config/quickshell/ii/services/Weather.qml` with a continuous 25-point rolling timeline `Weather.timeline` anchored to current wall clock hour `[-12h .. NOW .. +12h]`.
- Top-of-hour listener in `Weather.qml` triggered via minute timer tick, advancing the 25-point timeline window synchronously as the system clock rolls over (`:00`).
- Strict local system timezone alignment for timeline slot indexing and formatting via Qt/JS `Date`.
- Pre-computed timeline geometry & bounds metadata per slot (`index: 0..24`, `normalizedX: index / 24.0` with NOW at 0.5, `isPast`, `isNow`, `isFuture`, `dayOffset`, `isDayBoundary`, `isDaytime`) and top-level bounds (`tempBounds: { min, max }`, `rainBounds: { maxProb, maxMM }`).
- Cold-boot placeholder fallback: preserve fixed 25 slots with `isHistoricalUnavailable: true` when yesterday's history is not yet populated.
- Grouped domain sub-objects on each slot: `slot.thermal`, `slot.moisture`, `slot.wind`, `slot.aqi`, `slot.atmosphere`, `slot.solar` with strict JavaScript numeric parsing (`Number()`, `parseInt()`, `parseFloat()`).
- Cached/memoized numeric series accessor `Weather.getSeries(metricPath)` returning `number[25]` for high-performance Canvas 2D spline and bar plotting.
- Reconcile center NOW slot (index 12): populate primary telemetry (temp, feels-like, wind, humidity, pressure, glyph) directly from live `current_condition`, blended with forecast `chanceofrain` for precipitation probability.
- Preserve 100% backward compatibility for existing `Weather.hourly`, `Weather.current`, and legacy `Weather.data` facades.
- Verification test harness `scripts/phase54.2-weather-assert.sh` verifying Python cache rollover, QML timeline models, and zero git churn in `vendor/dots-hyprland`.

**Out of scope:**
- Canvas 2D spline graph rendering and mouse scrub interactions (dedicated Phase 54.3).
- Popup card visual styling and multi-day forecast strip assembly (dedicated Phase 54.4).
- Modifying `BarContent.qml` or upstream vendor files in `vendor/dots-hyprland`.
- Direct live network queries inside QML (strict Phase 51 architecture preserved).

<decisions>
## Implementation Decisions

### 1. Timeline Window & NOW Resolution
- **D-54.2-01:** Floor to current completed hour. At 14:35, NOW snaps to 14:00 (index 12). Past spans [02:00 .. 13:00] (12 slots), NOW is 14:00, and Future spans [15:00 .. 02:00 tomorrow] (12 slots), forming an exact 25-point hourly grid. — **Reversibility:** reversible
- **D-54.2-02:** Preserve 25-point fixed array with placeholder fallback. On cold boot or missing historical cache, the array always has length 25; unpopulated past slots carry null/fallback values with `isHistoricalUnavailable: true`, guaranteeing graph layout and center hairline never jump or shift. — **Reversibility:** costly — changing array length dynamically breaks fixed-width Canvas coordinate assumptions
- **D-54.2-03:** 24h clock with date boundary metadata. Slot time labels are formatted as `"HH:00"` (e.g. `"02:00"`, `"14:00"`) with explicit `"Now"` label at center index 12, plus `dayOffset` (-1, 0, +1) and `isDayBoundary` booleans for midnight boundary chips. — **Reversibility:** reversible
- **D-54.2-04:** Top-of-hour event trigger via minute timer. `Weather.qml` checks wall clock hour on a 60-second tick (or calculates delay to next exact hour); when the hour rolls over (e.g., 14:59 to 15:00), it slides the 25-point window immediately without waiting for `wwo-fetcher.py`. — **Reversibility:** reversible
- **D-54.2-05:** Strict system local timezone anchoring. Timeline indexing and slot timestamps anchor strictly to machine local timezone via Qt/JS `Date`, matching system tray clock and status bar times. — **Reversibility:** reversible
- **D-54.2-06:** Pre-index multi-day slots by ISO datetime key `"YYYY-MM-DDTHH:00"`. `Weather.qml` normalizes hourly slots from yesterday (`history`), today (`weather[0]`), and tomorrow (`weather[1]`) into a local datetime map for instant O(1) slot resolution across day boundaries. — **Reversibility:** reversible
- **D-54.2-07:** Expose pre-computed geometry & bounds metadata. Each slot includes `index`, `normalizedX` (0.0 to 1.0, with NOW at 0.5), `isPast`, `isNow`, `isFuture`; `Weather` exposes top-level `tempBounds: { min, max }` and `rainBounds: { maxProb, maxMM }` for zero-overhead Canvas rendering. — **Reversibility:** reversible
- **D-54.2-08:** Explicit `isDaytime` boolean on each slot. Derived from WWO `isdaytime` and astronomy sunrise/sunset times, enabling Canvas to draw day/night background bands and correct day/night condition icons. — **Reversibility:** reversible

### 2. Historical Cache & Rollover Architecture
- **D-54.2-09:** Unified envelope in `weather.json`. `wwo-fetcher.py` embeds a top-level `"history"` key directly into `weather.json` and `last_known_weather.json`; `Weather.qml` reads a single atomic file with zero multi-file race conditions or extra `FileView` instances. — **Reversibility:** costly — splitting into separate files requires rewiring QML watchers and assert scripts
- **D-54.2-10:** Dynamic date transition check on fetch. When `wwo-fetcher.py` fetches fresh data, if the calendar date has advanced, it promotes previous `weather[0]` into `history` and retains up to 24h of past hourly slots before saving. Works automatically across reboots, sleep, and system pauses at 0 additional API cost. — **Reversibility:** reversible
- **D-54.2-11:** 24 hours of history retention. Retains complete previous day forecast/observations (~15–20 KB JSON); guarantees 100% coverage for the `[-12h]` past window even at 00:05 AM immediately following midnight rollover. — **Reversibility:** reversible
- **D-54.2-12:** Unconditional history preservation during error/offline states. Error envelopes copy `history` from previous cache alongside `data`, allowing `Weather.qml` to render the full 25-point timeline seamlessly in stale mode without data loss. — **Reversibility:** reversible
- **D-54.2-13:** Top-level peer key `"history"` schema. Structure as an array of day objects: `"history": [ { "date": "YYYY-MM-DD", "hourly": [...] } ]`. Keeps raw `data` untouched for 100% backward compatibility with Phase 51/52/53 consumers. — **Reversibility:** reversible
- **D-54.2-14:** Cold-boot restoration of both `data` and `history`. When `ensure_fallback_cache` runs on cold boot, copy both `data` and `history` from persistent mirror to tmpfs with `is_stale: true`, so Quickshell boots instantly with a complete 25-point timeline before network initializes. — **Reversibility:** reversible
- **D-54.2-15:** Multi-day downtime invalidation. If machine was offline for multiple calendar days (`cached_date < yesterday`), set `history: []` to prevent misleading 3-day-old telemetry from masquerading as yesterday's weather; timeline uses standard placeholder fallbacks. — **Reversibility:** reversible
- **D-54.2-16:** POSIX atomic replace mechanism. Retain `os.replace` + `fsync` logic in `wwo-fetcher.py`; writing data and history in a single atomic file guarantees zero partial reads or desyncs between live and past telemetry in Quickshell. — **Reversibility:** reversible

### 3. QML Dataset Modeling & Metric Group Contracts
- **D-54.2-17:** Grouped domain sub-objects on each slot. Each timeline item contains typed sub-objects: `slot.thermal`, `slot.moisture`, `slot.wind`, `slot.aqi`, `slot.atmosphere`, `slot.solar`, cleanly matching modular card components. — **Reversibility:** reversible
- **D-54.2-18:** Strict numeric normalization in `Weather.qml`. Parse all telemetry metrics to native JS numbers (`Number()`, `parseInt()`, `parseFloat()`) with safe fallbacks (0 or null); eliminates repetitive type casting and subtle string concatenation bugs in Canvas graph calculations. — **Reversibility:** reversible
- **D-54.2-19:** Cached series getter `Weather.getSeries(metricPath)`. Provides `getSeries("thermal.tempC")` or `getSeries("moisture.rainProb")` returning an array of 25 numbers with memoization; flexible across any of the 6 metric groups without property bloat. — **Reversibility:** reversible
- **D-54.2-20:** Preserve `Weather.hourly` alongside new `Weather.timeline`. Keep `Weather.hourly` intact for existing Phase 54.1 status pill and legacy bindings, introducing `Weather.timeline` for the 25-point rolling model to guarantee zero regressions. — **Reversibility:** reversible

### 4. Live Condition vs Hourly Forecast Alignment
- **D-54.2-21:** Populate NOW slot with live observations. Index 12 takes its primary metrics (temperature, feels-like, wind, glyph, humidity, pressure, visibility) directly from live `current_condition`; ensures the center hairline on the graph matches the status bar pill and hero card temperature exactly. — **Reversibility:** reversible
- **D-54.2-22:** Hybrid precipitation blend at NOW. Use actual observed `precipMM` from `current_condition` combined with `chanceofrain` from the current hour's forecast slot, ensuring the precipitation bar at NOW displays both live rainfall and forecast probability without missing data. — **Reversibility:** reversible
- **D-54.2-23:** Direct true values; Fritsch-Carlson spline in WeatherGraph. Feed true live readings at NOW without artificial smoothing; Monotone Cubic Spline mathematically prevents overshoot or oscillations across discrete data points. — **Reversibility:** reversible
- **D-54.2-24:** Explicit `isNow: true` with dual labels. Flag `isNow: true` on index 12 with `timeLabel: "Now"`, `fullTimeLabel: "Now (14:00)"`, and `observationTime` from `current_condition` for instant identification in tooltips and scrub inspectors. — **Reversibility:** reversible
