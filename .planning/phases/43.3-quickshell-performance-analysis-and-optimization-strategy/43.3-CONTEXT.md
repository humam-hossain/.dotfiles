<decisions>
## Implementation Decisions

### Syscall Churn Resolution (`ResourceUsage.qml`)
- **D-01 (Rollout Timing & Empirical Verification):** Insert dedicated Phase 43.4 (*Quickshell Targeted Optimization & Empirical Verification*) immediately following Phase 43.3. Phase 43.4 will implement the timer fix and sensor gating, then re-run the benchmark suite (`scripts/profile-quickshell.sh`), capturing both the clean upstream baseline and customized shell side-by-side in `BENCHMARK.md` to empirically prove the syscall and CPU reductions. — **Reversibility:** reversible.
- **D-02 (Demand-Gated Adaptive Polling):** Configure `ResourceUsage.qml` using a declarative timer initialized with `interval: isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)` and trigger immediate startup data acquisition via `Component.onCompleted`. Completely eliminate the `interval: 1` imperative assignment bug. — **Reversibility:** reversible.
- **D-03 (History Array GC Optimization):** Gate history array updates (`cpuUsageHistory`, `memoryUsageHistory`, `swapUsageHistory`) so they only append when the resource inspector/overlay is actually active, preventing continuous JavaScript heap array spread copying (`[...]`) during idle. — **Reversibility:** reversible.
- **D-04 (Retire Legacy Resources Pill Ahead of Phase 44):** Remove the legacy `Resources` pill from `BarContent.qml` (and `VerticalBarContent.qml`) in Phase 43.4. Leave `ResourceUsage.qml` as a dormant/lightweight singleton, cleanly clearing the top status bar left zone for Phase 44's `MemoryStoragePill.qml`. — **Reversibility:** reversible.

### Telemetry Sweeping Architecture (`HardwareTelemetry.qml`)
- **D-05 (Two-Tier Demand-Gated Sweeping):** Split sensor polling into two tiers:
  - *Tier 1 (Idle 3000ms):* Polls strictly the 3 visible pill metrics (`overallCpuLoad` via `/proc/stat`, `packageTemp` via coretemp hwmon, `gpuLoad` via drm sysfs).
  - *Tier 2 (Active 1000ms):* Sweeps the remaining 28 sensors (14 per-core temps, 2 NVMe, 6 motherboard, frequencies) strictly when the pop-up inspector is open (`fastPollingRequests > 0`). — **Reversibility:** reversible.
- **D-06 (Zero-Latency First Frame on Popup Open):** On `fastPollingRequests` incrementing from 0 to 1, trigger an immediate synchronous sweep of Tier 2 sensors so all 20 core/thread meters populate instantly with 0ms blank delay. — **Reversibility:** reversible.
- **D-07 (Timer Cadence):** Maintain 3000ms idle interval (minimal background wakeups, ~1 read/s) accelerating to 1000ms active interval when inspecting. — **Reversibility:** reversible.
- **D-08 (Unified Telemetry Consolidation):** Consolidate telemetry data paths to avoid duplicate procfs reads (e.g. `/proc/stat` and `/proc/meminfo`) across separate singletons. — **Reversibility:** reversible.

### Pop-up Scenegraph & Rendering Overhead (`CpuGpuPopup.qml` & `CpuGpuPill.qml`)
- **D-09 (Full 20-Thread Meter Layout Retained):** Preserve the rich 20-thread layout in `CpuGpuPopup.qml` (12 P-threads, 8 E-threads) while eliminating rendering overhead via binding guards and animation throttling. — **Reversibility:** reversible.
- **D-10 (Strict Critical Pulse Gating):** Enforce strict condition gating (`running: root.isCritical`) on the critical alert breathing pulse animation in `CpuGpuPill.qml` and `CpuGpuPopup.qml`. The `SequentialAnimation` must be completely stopped and detached from the QtQuick scenegraph frame clock during normal operation. — **Reversibility:** reversible.
- **D-11 (1% Integer Deadband Quantization):** Quantize progress meter and gauge value updates to whole integer percentages to eliminate redundant animations and Canvas redraws on micro-fractional floating-point fluctuations. — **Reversibility:** reversible.
- **D-12 (Popup Inactivity Binding Guards):** Guard all inner item bindings, layout passes, and NumberAnimations in `CpuGpuPopup.qml` on `root.active` so background telemetry changes generate zero UI evaluation or scenegraph overhead while the popup is closed. — **Reversibility:** reversible.

## Existing Code Insights

### Reusable Assets
- `fastPollingRequests` reference counter in `HardwareTelemetry.qml`: Built-in lifecycle bridge for triggering active Tier 2 sweeping.

- Declarative `Timer` initialization combined with `Component.onCompleted` for instant first-frame data without scheduler recursion.
- Demand-gated sweeping: Tier 1 background monitoring of essential pill stats vs Tier 2 on-demand full sensor acquisition.
- `StyledPopup.active` gating to prevent inactive window scenegraph evaluation.

- `BarContent.qml`: Removal of `Resources` pill in Phase 43.4 clears the left zone for Phase 44's `MemoryStoragePill.qml`.
- `HardwareTelemetry.qml`: Core provider for CPU, GPU, temperature, and frequency telemetry across both pill and popup.
