<threat_model>
### ASVS L1 Security & Threat Mitigation
- **T-52-01: Malformed JSON / Input Validation (ASVS V5.1 - Input Validation)**:
  - *Threat*: Truncated, partial, or corrupted JSON in cache crashing the QML JavaScript engine or causing unhandled exceptions on desktop shell load.
  - *Mitigation*: Wrap `JSON.parse()` in a defensive `try / catch` block. If parsing fails, fall back to the persistent disk mirror (`last_known_weather.json`) or retain safe placeholder defaults. Validate array and object presence before property traversal using optional chaining.
- **T-52-02: Cache Tampering / Unauthorized Modification (ASVS V11 - Integrity)**:
  - *Threat*: Non-root local user tampering with weather JSON cache to inject malicious strings into UI.
  - *Mitigation*: Cache directory resides in `$XDG_RUNTIME_DIR/weather/` owned by the operator user (`0700`). QML only binds string properties as text primitives into `StyledText` and `MaterialSymbol`, strictly avoiding `eval()` or unvalidated DOM injection.
- **T-52-03: Denial of Service / CPU Spikes (ASVS V10 - Availability & Resource Efficiency)**:
  - *Threat*: Spawning child subshells or tight polling loops saturating CPU and draining battery.
  - *Mitigation*: Zero `Process` or `bash` execution in `Weather.qml`. Observe filesystem inotify events via `Quickshell.Io.FileView` with `watchChanges: true` and a slow 60-second fallback timer (measured CPU impact $\le 0.01\%$).
- **T-52-04: Secret Leakage (ASVS V2/V3 - Least Privilege)**:
  - *Threat*: Accidental exposure of API tokens or credentials in the UI runtime.
  - *Mitigation*: `Weather.qml` only reads public meteorological telemetry fields from the runtime cache file. It has no access to `~/.config/weather/.env` or `WWO_API_KEY`.
</threat_model>
