Replace Task 1's placeholder call site with the real classifier, and delete the not-yet-implemented `[INFO]`.

Write it as ONE decision point. Whether that is a `case` inline in the sweep loop or a helper function is discretionary; what is not discretionary is that there is exactly one place where an entry's verdict is decided. Five independent rules scattered through the loop is the shape this decision was taken to avoid.

The nine arms, in this order:

1. Symlink into the repo at a path the repo declares — skip silently. The repo-side pass owns it, and it has already reported on it. This arm is what keeps every managed path to exactly one line per run; get its key shape wrong and a clean tree turns into 94 false stale-link failures.
2. Symlink into the repo at a path the repo does not declare — `[FAIL]` naming both the link and its target.
3. Symlink that dangles, with its target resolving under the repo — `[FAIL]` naming the link and the raw target. This is `PITFALLS.md` A-6, repo unavailable at login.
4. Symlink outside the repo that resolves — silent.
5. Symlink that dangles with its target outside the repo — `[INFO]`. Measured: two links on a healthy machine dangle this way whenever Steam is not running, so this arm is the difference between a clean tree and a permanently noisy one.
6. Regular file whose name ends in one of the four installer-artifact shapes (`.old`, `.new`, `.bak`, `.bak.` plus anything) — `[INFO]` naming it as an installer backup artifact.
7. Other regular file in a package-owned directory, meaning any managed directory at depth two or more below `$HOME` — `[INFO]` naming it as an unclaimed upstream stub. Naming is all this phase does with them; deciding which belong in a tree is later work.
8. Other regular file in a shared root, meaning `$HOME` itself or `$HOME/.config` — silent.
9. Directory, or any other file type — silent.

Arm ordering is load-bearing at exactly one place: arm 6 must be tested BEFORE arm 8's shared-root exemption.
