The mechanism, stated as fact rather than as inference. The atomic-write class resolves the symlink chain before writing, so its temp file is created in the resolved directory — inside the repo. During the write itself the file has no directory entry at all, which is why a naive probe that holds a write open and looks for a name reports "never observable" and gives the wrong answer. At commit time, when the target already exists, the hard-link-to-final-name attempt fails with an already-exists error, the writer materialises the file under the target's name plus a six-random-character suffix in that same directory, and renames it over the target. The named window is two syscalls wide.

The measurement and its method, per D-40: a burst of writes driven through a stowed link with a concurrent polling loop; roughly 11 hits in 2000 polls during a 3000-write burst, about half a percent; every observed name matching the six-character template. State the method so the number is reproducible rather than merely quoted.

The decision and its reasoning, per D-41: no rule ships. The measurement observed an artifact, which satisfies the first half of D-41's condition, but the second half fails — the suffix is random, so the only matching pattern is an enormous over-match that would also swallow ordinary filenames, and that is precisely the unanchored shape `.gitignore`'s own prose block declares deliberate for a different set of patterns and must not be confused with. The artifact also cannot persist: it exists only between the link and the rename, and the writer removes it on failure. The one artifact that could outlive a process is the lock file the real KDE config writer produces, and that is already covered by an existing pattern shipped for an unrelated reason.

The `verify` consequence, per D-42: no dedicated stray-temp-file check. A transient artifact makes a verdict non-deterministic, and a check that flaps between runs is worse than no check. The Phase 19 assert's before-and-after working-tree bracket already catches one that outlives a run, which is the only case a check could honestly claim.

Update A-6's Detection signal and Mitigation lines only if the new subsection makes them inaccurate. The existing dangling-link detection mandate is what plans `19-02` and `19-03` implemented, so it should now read as delivered rather than as pending.
