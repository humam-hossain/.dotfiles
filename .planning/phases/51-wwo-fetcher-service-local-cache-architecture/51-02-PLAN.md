<threat_model>
### ASVS L1 Security & Threat Mitigation
- **T-51-02: Quota Exhaustion / API Denial-of-Service (ASVS V10 - Rate Limiting & Resource Management)**:
  - *Threat*: High polling frequency or retry loops exhausting the 500 requests/day WWO free-tier quota, causing HTTP 429 quota bans for 24 hours.
  - *Mitigation*: Dynamic pacing calculates interval $(M_{\text{remaining}} / \max(1, 470 - \text{calls})) \ge 3.0$ min. Unforced execution throttles immediately if interval not elapsed. Absolute ceiling at 500 calls rejects even `--force` requests. State tracking persists across script executions in `~/.local/state/weather/quota.json` with UTC midnight rollover.
- **T-51-03: Partial Read Race Conditions in UI Consumer (ASVS V11 - Concurrency & Data Integrity)**:
  - *Threat*: Quickshell `FileView` reading `$XDG_RUNTIME_DIR/weather/weather.json` while the fetcher is partially writing it, causing JSON parse errors or UI crashes.
  - *Mitigation*: Atomic temporary file replacement via `os.replace` within the same tmpfs mount point (`weather.json.tmp.<pid>` -> `weather.json`), accompanied by `flush()` and `os.fsync()`.
- **T-51-04: Cold Boot ENOENT Crash in UI (ASVS V11 - Data Integrity & Availability)**:
  - *Threat*: Quickshell starting on a cold boot without an active cache, triggering file not found exceptions.
  - *Mitigation*: Automatic fallback skeleton JSON (`status: "offline"`, `data: null`) pre-seeded before network attempts, and persistent cache restoration from `~/.local/state/weather/last_known_weather.json`.
- **T-51-05: Network Outage Retry Storms (ASVS V10 - Availability & Resiliency)**:
  - *Threat*: Intermittent connection drops or DNS failures triggering tight retry loops that burn API quota.
  - *Mitigation*: Zero immediate retry loops. Failures record error details and set `is_stale: true` while preserving existing forecast data, exiting 0 to let the systemd 3m timer naturally retry next tick.
</threat_model>

       - If missing: write error envelope to cache, print error to stderr, and exit 1.

       - Endpoint: `https://api.worldweatheronline.com/premium/v1/weather.ashx`.
       - Parameters: `key=<api_key>`, `q=<city>`, `format=json`, `num_of_days=3`, `tp=1`, `fx=yes`, `cc=yes`, `fx24=yes`, `includelocation=yes`, `showlocaltime=yes`, `extra=isDayTime,utcDateTime,localObsTime`, `aqi=yes`, `alerts=yes`, `mca=yes`, `lang=en`.

           "status": "ok",
           "fetched_at": "<local ISO8601>",
           "fetched_epoch": <int UTC epoch>,
           "is_stale": false,
           "error": null,
           "quota": {
             "calls_today": <int>,
             "calls_remaining": <int>,

           },
           "data": <wwo_response_data>

       - Mirror persistent copy to `~/.local/state/weather/last_known_weather.json` via atomic replace.
    7. Offline Resilience & Error Trapping (D-51-05, D-51-07, D-51-08, WWO-04):
       - Cold boot without cache: write fallback skeleton (`status: "offline"`, `data: null`, `is_stale: true`) or restore `last_known_weather.json` with `is_stale: true`.
