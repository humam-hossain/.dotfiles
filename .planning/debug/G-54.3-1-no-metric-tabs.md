# Debug Session: G-54.3-1 (Reject Metric Tabs & Selector)

**Status:** Diagnosed  
**Phase:** 54.3  
**Gap ID:** G-54.3-1  
**Severity:** Major  

## Symptoms
User reported: "nope there is no tab selector and i don't ant tabs either"
The user explicitly rejected tab-based navigation and wants a clean, unified weather graph without tab bars.

## Investigation
- `WeatherGraph.qml` lines 454-551 implemented a 6-pill `tabBarContainer` (`Temp`, `Rain`, `Wind`, `AQI`, `Baro`, `UV`) with an animated highlight rectangle.
- Other cards in `WeatherPopup.qml` already cover these domains (`WeatherAtmosphericCard`, `WeatherWindCard`, `WeatherAqiCard`, `WeatherAstronomyCard`). Multiplexing them into the hourly graph duplicate functionality and clutters the interface.
- Furthermore, `contentColumn` used `anchors.fill: parent` inside `WeatherBaseCard`'s `cardContent` item, which conflicts with layout constraints and caused layout rendering issues.

## Root Cause
Phase 54.3 introduced an unwanted metric selector tab bar architecture that the user does not want, duplicating metrics that belong to dedicated popup cards and adding UI complexity.

## Files Involved
- `restow/quickshell/.config/quickshell/ii/modules/ii/bar/weather/WeatherGraph.qml`: Tab selector container and activeMetric multiplexing code.

## Suggested Fix Direction
Remove `tabBarContainer` and `activeMetric` state logic. Return `WeatherGraph.qml` to a single, high-clarity timeline graph focused on temperature (actual & feels-like) and precipitation.
