## Architecture Patterns

### Pattern 1: Declarative Polling Timer & History Gating (`ResourceUsage.qml`)

**Problem:** In `ResourceUsage.qml:74-113`, `Timer` was declared with `interval: 1` and dynamically reassigned to `3000` inside `onTriggered`. In QtQuick, reassigning `interval` on an already active repeating timer does not immediately adjust the internal event timer in QJSEngine, causing the timer to fire at 60–100Hz continuously (~3,120 read syscalls/s). Furthermore, `updateHistories()` allocated new arrays via `[...history, val]` on every tick regardless of whether any chart was visible. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-ANALYSIS.md:30-52]

**Solution:**
1. Declare a top-level property `property bool isInspectorActive: false`.
2. Initialize `interval` declaratively to `root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)`.
3. Remove the dynamic `interval = ...` reassignment inside `onTriggered`.
4. Trigger the initial virtual file read via `Component.onCompleted`.
5. Gate `updateHistories()` on `root.isInspectorActive`.

```qml
// restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml
Singleton {
    id: root
    
    property bool isInspectorActive: false
    // ...
    Timer {
        id: pollTimer
        interval: root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)
        running: true
        repeat: true
        onTriggered: {
            fileMeminfo.reload();
            fileStat.reload();
            root.parseMeminfo();
            root.parseCpuStat();
            if (root.isInspectorActive) {
                root.updateHistories();
            }
        }
    }
    
    Component.onCompleted: {
        fileMeminfo.reload();
        fileStat.reload();
        root.parseMeminfo();
        root.parseCpuStat();
    }
}
```

### Pattern 2: Two-Tier Demand-Gated Sensor Sweeping (`HardwareTelemetry.qml`)

**Problem:** `HardwareTelemetry.qml` defines 31 `FileView` instances. The status bar pill only displays `overallCpuLoad`, `packageTemp`, and `gpuLoad`. Sweeping all 31 files on every 3000ms tick during idle generates unnecessary disk I/O, context switches, and regex execution. [VERIFIED: restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml:73-174, 396-489]

**Solution:** Segregate polling into two demand-gated tiers:
- **Tier 1 (`pollTier1()`):** Sweeps strictly the 3 files necessary for the status bar pill:
  1. `/proc/stat` (`fileProcStat`) $\rightarrow$ `overallCpuLoad`
  2. Coretemp package temp (`filePackageTemp`) $\rightarrow$ `packageTemp`
  3. Intel iGPU RC6 residency sysfs (`fileGpuRc6`) $\rightarrow$ `gpuLoad`
- **Tier 2 (`pollTier2()`):** Sweeps the remaining 28 sensors strictly when `fastPollingRequests > 0`:
  1. `/proc/cpuinfo` $\rightarrow$ cluster frequencies (`pCoreFrequencyMhz`, `eCoreFrequencyMhz`)
  2. EPP & governor sysfs (`fileEpp`, `fileGov`)
  3. Intel iGPU frequencies & throttle sysfs (`fileGpuFreq`, `fileGpuCurFreq`, `fileGpuThrottle`)
  4. Coretemp per-core temps (6 P-cores, 8 E-cores) $\rightarrow$ `pCoreTempAvg`, `eCoreTempAvg`
  5. NVMe temps (2 files)
  6. Motherboard platform sensors (6 files)

```javascript
// restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml
function pollAll() {
    pollTier1();
    if (root.fastPollingRequests > 0) {
        pollTier2();
    }
}

function pollTier1() {
    try { updateCpuLoadTier1(); } catch (e) { console.warn("updateCpuLoadTier1 error:", e); }
    try { updateGpuRc6Tier1(); } catch (e) { console.warn("updateGpuRc6Tier1 error:", e); }
    try { updatePackageTempTier1(); } catch (e) { console.warn("updatePackageTempTier1 error:", e); }
}

function pollTier2() {
    try { updateCpuLoadTier2(); } catch (e) { console.warn("updateCpuLoadTier2 error:", e); }
    try { updateFrequencies(); } catch (e) { console.warn("updateFrequencies error:", e); }
    try { updateGovernors(); } catch (e) { console.warn("updateGovernors error:", e); }
    try { updateGpuMetricsTier2(); } catch (e) { console.warn("updateGpuMetricsTier2 error:", e); }
    try { updateThermalsTier2(); } catch (e) { console.warn("updateThermalsTier2 error:", e); }
}
```

### Pattern 3: Zero-Latency First Frame Synchronization (D-06)

**Problem:** In a tiered demand-gated architecture, Tier 2 sensors are dormant during idle. If `HardwareTelemetry` waits for the next 1000ms timer tick when the user opens the popup inspector, the popup renders frame 0 with stale (or empty `0`) metrics for up to 1000ms. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-DECISIONS.md:86-94]

**Solution:** In `HardwareTelemetry.qml`, observe `fastPollingRequests`. When `fastPollingRequests` increments from 0 to 1, immediately execute `pollTier2()` synchronously. This guarantees that all popup metrics populate on frame 0 with 0ms visual delay.

```qml
// restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml
onFastPollingRequestsChanged: {
    if (fastPollingRequests === 1) {
        // Immediate synchronous Tier 2 sweep for frame 0 UI fidelity
        root.pollTier2();
    }
}
```

### Pattern 5: Cluster Summary Layout in `CpuGpuPopup.qml` (D-09)

**Problem:** In `CpuGpuPopup.qml:103-180, 244-278`, 20 individual `ThreadMeter` items were instantiated (12 P-threads, 8 E-threads). Each item contained 4 `StyledText` items and 2 `Rectangle`s. Updating 20 meters every 1000ms caused:
- 20 progress bar width re-evaluations
- 20 load percentage string allocations
- 20 frequency string allocations
- 14 core temperature string allocations
- 20 color function re-evaluations
- A 20-thread regex loop across `/proc/cpuinfo` in `HardwareTelemetry.qml`
This pushed Intel UHD 770 iGPU load from 12.00% to 26.41% (+14.41% GPU rendering load). [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-ANALYSIS.md:82-96]

**Solution (REFINED D-09):**
Replace the 20 individual `ThreadMeter` items with 3 clean, high-level cluster summary meters:
1. **Overall CPU:** Load %, Combined Average Frequency (MHz), Package Temp (°C).
2. **P-Core Performance Cluster:** Aggregate P-core utilization (8 P-cores / 16 threads), Average P-Core Frequency (MHz), Average P-Core Temp (°C).
3. **E-Core Efficiency Cluster:** Aggregate E-core utilization (4 E-cores / 4 threads), Average E-Core Frequency (MHz), Average E-Core Temp (°C).

*Architecture Benefit:* Reduces scenegraph items from 120+ down to ~15, eliminates the 20-thread regex loop, and provides superior human legibility for the Alder Lake hybrid architecture.

### Pattern 6: Strict Critical Pulse Animation Gating (D-10)

**Problem:** In `CpuGpuPopup.qml:187-207`, `popupCriticalPulse` declared:
`running: (HardwareTelemetry.overallCpuLoad || 0.0) >= 0.90 || (HardwareTelemetry.packageTemp || 0) >= 80 || (HardwareTelemetry.gpuLoad || 0.0) >= 0.90`
Notice that it was **not** gated on `root.active`! If system metrics became critical while the popup was closed, the 60 FPS animation ticker fired continuously in the background, waking the GPU. In `CpuGpuPill.qml:83-106, 177-197`, animations run whenever `root.cpuCritical` or `root.gpuCritical` are true. [VERIFIED: restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml:187-207; restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPill.qml:83-106, 177-197]

**Solution:**
In `CpuGpuPopup.qml`:
```qml
SequentialAnimation {
    id: popupCriticalPulse
    running: root.active && root.isCritical
    loops: Animation.Infinite
    onRunningChanged: {
        if (!running) root.criticalPulseOpacity = 1.0;
    }
    // ...
}
```
In `CpuGpuPill.qml`: Ensure animations only run when `root.cpuCritical` or `root.gpuCritical` are strictly evaluated and reset opacity to `1.0` on stop.

### Pattern 7: 1% Integer Deadband Quantization (D-11)

**Problem:** Continuous micro-fractional floating-point fluctuations (e.g. 0.14234 $\rightarrow$ 0.14281) cause constant QML property re-evaluations and trigger unnecessary OpenGL/Vulkan scenegraph vertex re-tessellations for progress rings and bars. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-DECISIONS.md:146-155]

**Solution:** Apply 1% integer deadband quantization to progress values:
```qml
readonly property real quantizedCpuLoad: Math.round((HardwareTelemetry.overallCpuLoad || 0.0) * 100) / 100
readonly property real quantizedGpuLoad: Math.round((HardwareTelemetry.gpuLoad || 0.0) * 100) / 100
```
In `CpuGpuPill.qml`:
`value: root.quantizedCpuLoad` and `value: root.quantizedGpuLoad`.
In `CpuGpuPopup.qml`:
`value: Math.round((val || 0.0) * 100) / 100`.

### Pattern 8: Popup Inactivity Binding Guards (D-12)

**Problem:** When `CpuGpuPopup.qml` is closed, properties bound to `HardwareTelemetry` still evaluate if expressions do not guard against inactive state. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-DECISIONS.md:158-167]

**Solution:** Guard inner item bindings and animations on `root.active`:
```qml
value: root.active ? (HardwareTelemetry.overallCpuLoad || 0.0) : 0.0
```

## Don't Hand-Roll

| Problem | Anti-Pattern | Recommended Solution |
|---|---|---|
| **Virtual File I/O** | Hand-rolling `Process { command: ["cat", ... ] }` or `XMLHttpRequest` | Use Quickshell's native C++ `Quickshell.Io.FileView` with `reload()` and `blockLoading: true`. Native FileViews are significantly lighter and avoid child process fork/exec overhead. [VERIFIED: restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml:73-86] |
| **Cadence Switching** | Modifying `Timer.interval` dynamically inside `onTriggered` | Use declarative property binding `interval: root.fastPolling ? 1000 : 3000`. Let QtQuick manage timer interval reconfiguration cleanly upon state transitions. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-ANALYSIS.md:33-45] |
| **History Ring Buffers** | Hand-rolling JavaScript array spread copies `arr = [...arr, val]` every tick | Gate history array accumulation on inspector visibility (`isInspectorActive`). Heap-allocated array reallocations trigger relentless V8/QJSEngine garbage collection. [VERIFIED: .planning/phases/43.3-quickshell-performance-analysis-and-optimization-strategy/43.3-DECISIONS.md:48-57] |
| **External Telemetry Bridge** | Hand-rolling an external Python HTTP/socket daemon for CPU/GPU data | Retain in-engine Quickshell `FileView`s with two-tier demand gating. External daemons add JSON serialization, socket context switches, and external process memory footprints. [VERIFIED: .planning/phases/43.4-quickshell-targeted-optimization-and-empirical-verification/43.4-CONTEXT.md:72] |
| **Popup State Gating** | Checking raw window visibility flags or polling cursor position | Leverage existing `root.active` state in `StyledPopup.qml` and `fastPollingRequests` counter in `HardwareTelemetry.qml`. [VERIFIED: restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml:15-27] |

## Common Pitfalls

### Pitfall 1: Breaking Existing Assertions (`scripts/phase43-cpu-gpu-assert.sh`)
- **Mechanism:** `scripts/phase43-cpu-gpu-assert.sh` lines 341–352 and 402–407 assert:
  1. `grep -q "P-Cores (12T)" "$POPUP_QML"`
  2. `grep -q "E-Cores (8T)" "$POPUP_QML"`
  3. `grep -A 40 "component ThreadMeter:" "$POPUP_QML" | grep -q "Rectangle"`
- **Consequence:** If `CpuGpuPopup.qml` deletes `ThreadMeter` or changes cluster titles without synchronizing `scripts/phase43-cpu-gpu-assert.sh`, the assertion suite will exit with failures.
- **Prevention:** Update `scripts/phase43-cpu-gpu-assert.sh` in the same phase to validate the refined cluster summary layout (or ensure the component maintains backward-compatible aliases) so both `./scripts/phase43-perf-assert.sh --quick` and `./scripts/phase43-cpu-gpu-assert.sh --quick` pass with 0 failures and 0 findings. [VERIFIED: scripts/phase43-cpu-gpu-assert.sh:341-352, 402-407]

### Pitfall 2: Refcount Leak in `fastPollingRequests`
- **Mechanism:** If `HardwareTelemetry.fastPollingRequests++` is called on popup open, but a rapid hover/unhover or window destruction bypasses the decrement, `fastPollingRequests` remains $> 0$ indefinitely, locking the telemetry engine in active 1000ms mode.
- **Prevention:** Ensure `CpuGpuPopup.qml` maintains both `onActiveChanged` paired increment/decrement and `Component.onDestruction: if (active) HardwareTelemetry.fastPollingRequests--;`. [VERIFIED: restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml:15-27]

### Pitfall 3: Sub-tick Stale UI on Popup Opening (Frame 0 Stutter)
- **Mechanism:** When the popup opens, `pollTimer` interval shifts from 3000ms to 1000ms. If Tier 2 metrics are only gathered on timer ticks, the popup will display 0% or empty strings until the next tick (up to 1000ms delay).
- **Prevention:** D-06 mandates an immediate synchronous Tier 2 sweep when `fastPollingRequests === 1` in `HardwareTelemetry.qml` (`onFastPollingRequestsChanged`). [VERIFIED: .planning/phases/43.4-quickshell-targeted-optimization-and-empirical-verification/43.4-CONTEXT.md:57]

### Pitfall 4: Sub-pixel GPU Scenegraph Re-Tessellation Churn
- **Mechanism:** Progress bar widths and circular progress rings mapped directly to unquantized floating-point ratios (e.g. `0.2341258`) force the QtQuick scenegraph renderer to continuously calculate sub-pixel geometry deltas on every tick.
- **Prevention:** Apply 1% integer deadband quantization (`Math.round(val * 100) / 100`) across all progress bar bindings (D-11). [VERIFIED: .planning/phases/43.4-quickshell-targeted-optimization-and-empirical-verification/43.4-CONTEXT.md:68]

### Pitfall 5: Dirty Git Working Tree After Benchmark Run
- **Mechanism:** Running `./scripts/profile-quickshell.sh` overwrites `BENCHMARK.md` and `benchmark-latest.json`. If untracked temporary files or unstowed `.bak` stubs are left behind, `./arch/dots-hyprland.sh verify --strict` fails.
- **Prevention:** Ensure `profile-quickshell.sh` cleanly restores Stow leaf symlinks and cleans up temporary files in its exit trap. Verify git porcelain status with `git status --porcelain`. [VERIFIED: scripts/phase43-perf-assert.sh:380-406]

## Code Examples

### Example 1: `ResourceUsage.qml` Declarative Polling & Gated History

```qml
// restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml
pragma Singleton
pragma ComponentBehavior: Bound

import qs.modules.common
import QtQuick
import Quickshell
import Quickshell.Io

Singleton {
    id: root

    property bool isInspectorActive: false

    // Core Memory Properties
    property real memoryTotal: 1
    property real memoryFree: 0
    property real memoryAvailable: 0
    property real memoryBuffers: 0
    property real memoryCached: 0
    property real memoryUsed: Math.max(0, memoryTotal - (memoryAvailable > 0 ? memoryAvailable : memoryFree))
    property real memoryUsedPercentage: memoryTotal > 0 ? (memoryUsed / memoryTotal) : 0

    // Swap Properties
    property real swapTotal: 1
    property real swapFree: 0
    property real swapUsed: Math.max(0, swapTotal - swapFree)
    property real swapUsedPercentage: swapTotal > 0 ? (swapUsed / swapTotal) : 0

    // CPU Properties
    property real cpuUsage: 0
    property var previousCpuStats

    readonly property int historyLength: Config?.options?.resources?.historyLength ?? 60
    property list<real> cpuUsageHistory: []
    property list<real> memoryUsageHistory: []
    property list<real> swapUsageHistory: []

    function updateHistories() {
        if (!root.isInspectorActive) return;
        memoryUsageHistory = [...memoryUsageHistory, memoryUsedPercentage];
        if (memoryUsageHistory.length > historyLength) memoryUsageHistory.shift();
        swapUsageHistory = [...swapUsageHistory, swapUsedPercentage];
        if (swapUsageHistory.length > historyLength) swapUsageHistory.shift();
        cpuUsageHistory = [...cpuUsageHistory, cpuUsage];
        if (cpuUsageHistory.length > historyLength) cpuUsageHistory.shift();
    }

    function pollMetrics() {
        fileMeminfo.reload();
        fileStat.reload();

        const textMeminfo = fileMeminfo.text();
        memoryTotal = Number(textMeminfo.match(/MemTotal:\s*(\d+)/)?.[1] ?? 1);
        memoryAvailable = Number(textMeminfo.match(/MemAvailable:\s*(\d+)/)?.[1] ?? 0);
        memoryFree = memoryAvailable;
        memoryBuffers = Number(textMeminfo.match(/Buffers:\s*(\d+)/)?.[1] ?? 0);
        memoryCached = Number(textMeminfo.match(/^Cached:\s*(\d+)/m)?.[1] ?? 0);
        swapTotal = Number(textMeminfo.match(/SwapTotal:\s*(\d+)/)?.[1] ?? 1);
        swapFree = Number(textMeminfo.match(/SwapFree:\s*(\d+)/)?.[1] ?? 0);

        const textStat = fileStat.text();
        const cpuLine = textStat.match(/^cpu\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)\s+(\d+)/);
        if (cpuLine) {
            const stats = cpuLine.slice(1).map(Number);
            const total = stats.reduce((a, b) => a + b, 0);
            const idle = stats[3];
            if (previousCpuStats) {
                const totalDiff = total - previousCpuStats.total;
                const idleDiff = idle - previousCpuStats.idle;
                cpuUsage = totalDiff > 0 ? (1 - idleDiff / totalDiff) : 0;
            }
            previousCpuStats = { total, idle };
        }

        if (root.isInspectorActive) {
            root.updateHistories();
        }
    }

    Timer {
        id: pollTimer
        interval: root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)
        running: true
        repeat: true
        onTriggered: root.pollMetrics()
    }

    Component.onCompleted: {
        root.pollMetrics();
    }

    FileView { id: fileMeminfo; path: "/proc/meminfo"; printErrors: false; blockLoading: true }
    FileView { id: fileStat; path: "/proc/stat"; printErrors: false; blockLoading: true }
}
```

### Example 2: `HardwareTelemetry.qml` Two-Tier Gating & Zero-Latency Synchronization

```qml
// restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml (excerpt)
Singleton {
    id: root

    property int fastPollingRequests: 0
    readonly property bool fastPolling: fastPollingRequests > 0 || overallCpuLoad > 0.50

    onFastPollingRequestsChanged: {
        if (fastPollingRequests === 1) {
            // Immediate synchronous Tier 2 sweep for zero-latency frame 0 (D-06)
            root.pollTier2();
        }
    }

    Timer {
        id: pollTimer
        interval: root.fastPolling ? 1000 : 3000
        repeat: true
        running: true
        onTriggered: root.pollAll()
    }

    function pollAll() {
        pollTier1();
        if (root.fastPollingRequests > 0) {
            pollTier2();
        }
    }

    function pollTier1() {
        try { updateCpuLoadTier1(); } catch (e) { console.warn("updateCpuLoadTier1 error:", e); }
        try { updatePackageTempTier1(); } catch (e) { console.warn("updatePackageTempTier1 error:", e); }
        try { updateGpuRc6Tier1(); } catch (e) { console.warn("updateGpuRc6Tier1 error:", e); }
    }

    function pollTier2() {
        try { updateCpuLoadTier2(); } catch (e) { console.warn("updateCpuLoadTier2 error:", e); }
        try { updateFrequencies(); } catch (e) { console.warn("updateFrequencies error:", e); }
        try { updateGovernors(); } catch (e) { console.warn("updateGovernors error:", e); }
        try { updateGpuMetricsTier2(); } catch (e) { console.warn("updateGpuMetricsTier2 error:", e); }
        try { updateThermalsTier2(); } catch (e) { console.warn("updateThermalsTier2 error:", e); }
    }

    // Tier 1: Reads strictly /proc/stat overall "cpu" line
    function updateCpuLoadTier1() {
        fileProcStat.reload();
        const text = fileProcStat.text();
        if (!text) return;
        const line = text.slice(0, text.indexOf("\n")).trim();
        if (!line.startsWith("cpu ")) return;
        const parts = line.split(/\s+/);
        const total = parts.slice(1, 9).reduce((acc, val) => acc + (parseFloat(val) || 0), 0);
        const idle = (parseFloat(parts[4]) || 0) + (parseFloat(parts[5]) || 0);
        const active = total - idle;
        const prev = prevCpuTicks["cpu"];
        if (prev) {
            const dTotal = total - prev.total;
            const dActive = active - prev.active;
            overallCpuLoad = dTotal > 0 ? Math.max(0.0, Math.min(1.0, dActive / dTotal)) : 0.0;
        }
        prevCpuTicks["cpu"] = { total: total, active: active };
    }
}
```
