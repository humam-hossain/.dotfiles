## Implementation Decisions

### Service Optimization & Idle Churn Elimination
- **D-01 (Rollout Timing & Empirical Verification):** Implement targeted QML optimizations in Phase 43.4 and perform an immediate side-by-side empirical benchmark run (`scripts/profile-quickshell.sh`) to record verified before/after numbers in `BENCHMARK.md`. — **Reversibility:** reversible.
- **D-02 (Declarative Timer Initialization):** Replace `interval: 1` in `ResourceUsage.qml` with a declarative timer initialized to `interval: isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)`. Trigger the initial data fetch via `Component.onCompleted`. Eliminates ~3,120 read syscalls/s and drops idle CPU by ~3–4%. — **Reversibility:** reversible.
- **D-03 (History Array GC Optimization):** Gate array updates in `ResourceUsage.qml` on `isInspectorActive`. Skip array copying (`[...]`) during idle, preventing continuous V8/QJSEngine garbage collection churn. — **Reversibility:** reversible.
- **D-04 (Retire Legacy Resources Pill Ahead of Phase 44):** Remove `Resources.qml` from `BarContent.qml` and `VerticalBarContent.qml`. Leaves `ResourceUsage.qml` dormant and clears the Left Zone of the status bar for Phase 44's `MemoryStoragePill.qml`. — **Reversibility:** reversible.

### Two-Tier Sensor Sweeping (`HardwareTelemetry.qml`)
- **D-05 (Two-Tier Demand-Gated Sweeping):** Segregate sensor polling into two tiers:
  - *Tier 1 (Idle, 3000ms):* Polls strictly the 3 visible pill metrics (`overallCpuLoad` via `/proc/stat`, `packageTemp` via coretemp, `gpuLoad` via drm sysfs).
  - *Tier 2 (Active, 1000ms):* Sweeps cluster temperatures, motherboard, NVMe, and frequencies strictly when the popup inspector is open (`fastPollingRequests > 0`). Drops idle file reads from 31 to 3 per cycle. — **Reversibility:** reversible.
- **D-06 (Zero-Latency First Frame on Popup Open):** On `fastPollingRequests` incrementing from 0 to 1, trigger an immediate synchronous sweep of Tier 2 sensors so the popup displays fresh telemetry on frame 0 with 0ms visual delay. — **Reversibility:** reversible.
- **D-07 (Timer Cadence Specification):** Maintain 3000ms idle interval (minimal background wakeups, ~1 read/s) accelerating to 1000ms active interval when inspecting. — **Reversibility:** reversible.
- **D-08 (Unified Telemetry Consolidation):** Consolidate CPU `/proc/stat` parsing into `HardwareTelemetry.qml`, eliminating redundant reads in other singletons. — **Reversibility:** reversible.

### UI & Pop-up Scenegraph Optimization (`CpuGpuPopup.qml` & `CpuGpuPill.qml`)
- **D-09 (REFINED - Cluster Summary Layout):** Replace the 20 individual `ThreadMeter` items in `CpuGpuPopup.qml` with 3 clean, high-level cluster summary meters:
  1. *Overall CPU:* Combined utilization percentage, average clock frequency, package temperature.
  2. *P-Core Performance Cluster:* 8 P-cores / 16 threads aggregate utilization, average P-core clock frequency, average P-core temperature.
  3. *E-Core Efficiency Cluster:* 4 E-cores / 4 threads aggregate utilization, average E-core clock frequency, average E-core temperature.
  *Benefits:* Slashes scenegraph items from 120+ down to ~15, eliminates the 20-thread regex loop across `/proc/cpuinfo`, and provides much higher human legibility on the i7-12700K hybrid architecture. (Supersedes previous proposal to retain 20 individual thread bars). — **Reversibility:** reversible.
- **D-10 (Strict Critical Pulse Gating):** Enforce strict condition gating (`running: root.active && root.isCritical`) on the critical alert pulse animation in `CpuGpuPill.qml` and `CpuGpuPopup.qml`. Stops the 60 FPS frame clock completely when metrics are normal, eliminating background GPU wakeups. — **Reversibility:** reversible.
- **D-11 (1% Integer Deadband Quantization):** Quantize progress meter widths and values using `Math.round(val * 100) / 100`. Eliminates sub-pixel floating-point jitter and avoids triggering unnecessary OpenGL/Vulkan scenegraph re-tessellations on the Intel UHD 770. — **Reversibility:** reversible.
- **D-12 (Popup Inactivity Binding Guards):** Guard all inner item bindings, layout passes, and NumberAnimations in `CpuGpuPopup.qml` on `root.active` so telemetry changes generate zero UI evaluation while the popup is closed. — **Reversibility:** reversible.

### Operator Decisions & Guidance
- **External Daemon vs Native QML:** Evaluated during discussion. Native C++ FileViews inside Quickshell with demand-gated tiers are substantially faster, consume less RAM, and introduce no IPC/network overhead compared to an external Python HTTP/socket daemon. Retaining in-engine telemetry.
- **Popup Core Granularity:** Explicitly confirmed that individual 20-core tracking in the popup is unnecessary; P-core cluster, E-core cluster, and average load provide optimal clarity and performance.

</decisions>

## Existing Code Insights

### Reusable Assets & State Bridges
- `fastPollingRequests` in `HardwareTelemetry.qml`: Integer counter tracking open popup inspectors. Incremented on popup open, decremented on close. Perfect trigger for Tier 1 $\leftrightarrow$ Tier 2 transitions.
- `pCoreTempAvg` & `eCoreTempAvg` in `HardwareTelemetry.qml`: Pre-existing cluster temperature averages calculated from coretemp hwmon files.
- `overallCpuLoad` in `HardwareTelemetry.qml`: System-wide CPU utilization calculated from `/proc/stat`.

### Key Code Patterns to Apply
- **Declarative Timer + Startup Trigger:**
  ```qml
  Timer {
      interval: root.fastPolling ? 1000 : 3000
      running: true
      repeat: true
      onTriggered: root.pollTier1()
  }
  Component.onCompleted: root.pollTier1()
  ```
- **Tiered Sweeping Function Split:**
  ```javascript
  function pollTier1() {
      fileStat.reload();
      filePackageTemp.reload();
      fileGpuRc6.reload();
      // compute pill metrics
  }
  function pollTier2() {
      // sweep core temperatures, frequencies, NVMe, motherboard
  }
  ```
- **Scenegraph Quantization:**
  ```qml
  readonly property real quantizedLoad: Math.round(rawLoad * 100) / 100
  ```
- **Animation Gating:**
  ```qml
  SequentialAnimation {
      running: root.active && root.isCritical
      // ...
  }
  ```
