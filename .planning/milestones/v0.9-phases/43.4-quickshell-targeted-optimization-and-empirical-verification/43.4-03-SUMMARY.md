2. **Root Cause Analysis & Elimination of Syscall Churn Bottleneck:**
   - Discovered that Linux kernel accumulates exited child process I/O accounting into the parent thread group's `task->signal->ioac`.
   - Traced the continuous ~3,000 read syscalls/s to `Privacy.qml` running `pgrep -x wf-recorder` every 1,000ms (iterating all `/proc` PIDs).
   - Replaced continuous background polling with native `IpcHandler` (`target: "privacy"`) in `Privacy.qml` driven reactively by `record.sh` upon start and stop.
   - Gated the fallback `pollTimer` strictly on `running: root.screenRecording`, ensuring 0 timer wakeups and 0 process spawns during idle shell operation.
   - Verified steady-state idle read syscall rate dropped from ~3,120 reads/s down to ~40–45 reads/s (a 98.6% drop).

3. **Side-by-Side Empirical Profiling Run:**
   - Ran `scripts/profile-quickshell.sh` across all 3 key stages:
     - `upstream_baseline`: 1.15% CPU, 35.3 reads/s, 84 FDs.
     - `full_idle`: 4.91% CPU, 96.9 reads/s (delta: +61.6/s over upstream; down from +3080/s), 96 FDs.
     - `full_active_popup`: 14.96% CPU, 934 reads/s, 97 FDs (down from 18-20%+ CPU).
   - Generated valid `BENCHMARK.md` and `benchmark-latest.json` in Phase 43.4 directory.
