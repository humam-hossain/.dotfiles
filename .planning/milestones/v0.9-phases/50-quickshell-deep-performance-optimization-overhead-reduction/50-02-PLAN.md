<objective>
Eliminate all recurring and initialization subshell forks (`bash -c`, `lscpu`, `df` via shell) across telemetry singletons (`ResourceUsage.qml`, `StorageUsage.qml`, `NetworkUsage.qml`), implement direct kernel sysfs/procfs `FileView` observers for network attributes, cap `PingService` XHR polling, and resolve scene graph layout feedback loops in `NetworkPingPopup.qml` to eliminate the Intel UHD 770 1550 MHz GPU boost lock (OPT-03, D-50-02, D-50-07, D-50-08).

Purpose: Remove heavy process forks and context switch spikes on recurring telemetry paths while stabilizing Wayland surface geometry in `popup_netping` to allow the GPU frequency governor to stay at quiescent idle (0 MHz active).
Output: Zero `bash -c` executions across Quickshell services, kernel-native network state tracking, bounded XHR polling, and stabilized fixed-height card geometry in `NetworkPingPopup.qml`.
</objective>

<threat_model>
ASVS L1 Threat Model & Mitigations:
- **T-50-03: Subprocess Command Injection via Unsanitized Shell Evaluation**
  - Threat: Passing parameters through `bash -c "..."` invites command injection vulnerabilities if interface names, mount paths, or file strings contain shell metacharacters (`;`, `&`, `|`, `` ` ``, `$()`).
  - ASVS L1 Mapping: V5.3.8 Command Injection Prevention.
  - Mitigation: All subprocess invocations eliminate the shell interpreter entirely, executing binaries directly via structured argument arrays (`["ip", "-j", "-4", "addr", "show"]`, `["timeout", "3", "df", "-k", "-P"]`).
- **T-50-04: Network Socket Starvation & Thread Pool Saturation**
  - Threat: Rapid firing of asynchronous `XMLHttpRequest` calls without in-flight tracking can saturate network sockets, leak file descriptors, and trigger daemon connection timeouts.
  - ASVS L1 Mapping: V13.1.1 Denial of Service & Resource Exhaustion Prevention.
  - Mitigation: `PingService.qml` guards calls with `isRequestInFlight: bool` and enforces a strict 2000ms XHR timeout, dropping duplicate overlapping requests.
- **T-50-05: Information Disclosure via Sensitive Procfs/Sysfs Access**
  - Threat: Arbitrary filesystem reading could expose protected kernel data or system configurations.
  - ASVS L1 Mapping: V4.1 Access Control Invariants.
  - Mitigation: `FileView` observers are strictly locked to public, unprivileged Linux kernel telemetry interfaces (`/proc/net/dev`, `/proc/net/route`, `/sys/class/net/`, `/sys/devices/system/cpu/cpu0/cpufreq/cpuinfo_max_freq`).
</threat_model>
