## 1. Executive Summary & Problem Statement

Phase 43.2 captured authentic, verified empirical baselines comparing pure upstream `dots-hyprland` against the custom overlay stack:

| State | CPU % (Avg) | CPU % (Peak) | RSS (MB) | Context Switches (Vol/s) | Syscall Reads/s | Syscall Writes/s | FDs | Intel iGPU % |
|---|---|---|---|---|---|---|---|---|

| **Full Custom Shell (Idle)** | 5.61% | 15.36% | 756.76 MB | 476.1/s | 3,120.9/s | 252.7/s | 79 | 12.00% |

### Core Findings
1. **Idle Churn (Overhead over Upstream):** Custom components add **+4.68% idle CPU**, **+439.4 voluntary context switches/s**, and **+3,097.3 read syscalls/s**. The shell is executing over **3,100 read syscalls every second** even when unhovered.
2. **Pop-up Interaction Cost (Overhead over Idle):** Opening the CPU/GPU pop-up inspector adds **+8.14% CPU** (pushing process load to 13.75%), **+648.8 context switches/s** (reaching 1,124.9/s), and **+14.41% Intel UHD 770 iGPU load** (reaching 26.41%).

## 2. Bottleneck Root-Cause Dissection

### Bottleneck Area 1: Relentless Idle Syscall Churn (`ResourceUsage.qml`)

- **File:** `restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml:74-113`
- **Root Cause Mechanism:**
  ```qml
  Timer {
      interval: 1
      running: true 
      repeat: true
      onTriggered: {
          fileMeminfo.reload();
          fileStat.reload();
          ...
          interval = Config?.options?.resources?.updateInterval ?? 3000;
      }
  }
  ```
  In QtQuick/QML, dynamically reassigning the `interval` property of a running repeating `Timer` inside its own `onTriggered` signal does not guarantee an immediate scheduler cadence change. If the underlying timer remains at `1ms` (or clamped to the frame tick ~10–16ms), the timer fires 60–100 times per second continuously.
- **Per-Tick Overhead:**
  - Reloads `/proc/meminfo` and `/proc/stat`.
  - Runs 6 regular expression matches (`MemTotal`, `MemAvailable`, `Buffers`, `Cached`, `SwapTotal`, `SwapFree`).
  - Re-allocates 3 dynamic JavaScript arrays (`cpuUsageHistory = [...memoryUsageHistory, ...]`).
- **Empirical Toll:** Contributes ~3,000 read syscalls/sec and ~400 context switches/sec in idle.

---

### Bottleneck Area 2: Broad-Spectrum Sensor Over-Polling (`HardwareTelemetry.qml`)

- **File:** `restow/quickshell/.config/quickshell/ii/services/HardwareTelemetry.qml:17-23, 73-140, 396-478`
- **Root Cause Mechanism:**
  - `HardwareTelemetry` defines **31 active FileViews**:
    - 1 `/proc/stat`
    - 1 `/proc/cpuinfo`
    - 2 CPU EPP & scaling governor files
    - 4 Intel iGPU DRM sysfs files
    - 1 CPU package temperature
    - 6 P-core temperatures (`temp2`, `temp6`, `temp10`, `temp14`, `temp18`, `temp22`)
    - 8 E-core temperatures (`temp26` .. `temp33`)
    - 2 NVMe temperatures (`hwmon1`, `hwmon2`)
    - 6 Motherboard WMI platform temperatures (`temp1` .. `temp6`)
  - **The Architectural Mismatch:**
    - The status bar pill (`CpuGpuPill.qml`) **only displays**:
      1. `overallCpuLoad`
      2. `packageTemp`
      3. `gpuLoad`
    - It **never displays** per-core temperatures, NVMe temperatures, motherboard temperatures, or individual thread frequencies.
    - Yet, `pollAll()` sweeps **all 31 files on every timer tick** (every 3 seconds in idle, and accelerating to every 1 second when active).
- **Fast-Polling Spike:**
  - When the pop-up opens, `fastPollingRequests` increments, accelerating the entire 31-file sweep to a 1000ms cadence.
  - Parsing `/proc/cpuinfo` for 20 thread frequencies via regex regex execution (`/cpu MHz\s*:\s*([0-9.]+)/g`) runs every 1 second.
- **Empirical Toll:** Contributes to the +8.14% CPU spike and +846.9 read syscalls/s when the inspector pop-up is opened.

### Bottleneck Area 3: Scenegraph Re-Render Overhead (`CpuGpuPopup.qml`)

- **File:** `restow/quickshell/.config/quickshell/ii/modules/ii/bar/CpuGpuPopup.qml:103-180`
- **Root Cause Mechanism:**
  - `CpuGpuPopup` instantiates **20 individual `ThreadMeter` items** (12 P-threads, 8 E-cores).
  - Each item contains 4 `StyledText` labels, an outer container, a background `Rectangle`, and a fill `Rectangle` with width calculations:
    `width: parent.width * Math.max(0.0, Math.min(1.0, tMeter.load))`
  - On every 1s telemetry update:
    - 20 progress bar widths change.
    - 20 load percentage strings change.
    - 20 frequency MHz strings change.
    - 14 temperature strings change.
    - Dynamic color functions (`root.getLoadColor`, `root.getTempColor`) re-evaluate across 20 components.
  - Multi-pass drop shadows (`StyledRectangularShadow`) in `StyledPopup.qml` add rendering load to the Intel UHD 770 compositing engine.
- **Empirical Toll:** Drives Intel UHD 770 iGPU load from **12.00% up to 26.41%** (+14.41% GPU rendering load).

---

### Bottleneck Area 4: Premature Background Polling (`StorageUsage.qml` & `Voice.qml`)

- **File:** `restow/quickshell/.config/quickshell/ii/services/StorageUsage.qml:54-60`
  - Runs a 1000ms timer reading and parsing `/proc/diskstats` on every second, even though no storage pill is currently mounted on the status bar (Phase 44).
- **File:** `restow/quickshell/.config/quickshell/ii/services/Voice.qml:253-259`
  - Runs a 500ms polling loop checking 6 tmpfs files in `/tmp/voice-mode/` when idle.

## 3. Optimization Architecture & Decision Matrix

| Optimization Area | Problem / Bottleneck | Proposed Solution | Expected Impact | Implementation Boundary |
|---|---|---|---|---|
| **OPT-01: ResourceUsage Timer** | `interval: 1` anomaly causing 60–100Hz `/proc/meminfo` churn (~3,100 reads/s) | Fix timer definition to `interval: 3000` (or `1000`), prevent array reallocations in history | Reduces idle reads from 3,120/s to <80/s; drops idle CPU by 3–4% | **Immediate (Phase 43.3 / Phase 44)** |
| **OPT-02: Demand-Gated Sensor Sweeping** | `HardwareTelemetry` reads 31 files every 3s even when pop-up is closed | **Tiered Polling:**<br>- **Tier 1 (Idle/Pill):** Only read `/proc/stat`, package temp, and iGPU RC6 (3 files).<br>- **Tier 2 (Pop-up Active):** Read 20 core temps, NVMe, motherboard, and frequencies *only* when pop-up is open. | Eliminates 28 sysfs file reads every 3s in idle; drops context switches by ~150/s | **Phase 43.3 / Phase 46** |
| **OPT-03: Thread Frequency Parsing** | Parsing full `/proc/cpuinfo` every 1s via regex in active UI mode | Only parse thread frequencies when pop-up is open; cache regex or read direct sysfs core nodes | Reduces pop-up CPU spike by 2–3% | **Phase 43.3 / Phase 46** |
| **OPT-04: StorageUsage Idle Gating** | 1000ms diskstats tracking running with no UI consumer | Back off `StorageUsage` timer to 5000ms when unhovered / no active popup | Saves ~60 reads/min in idle | **Phase 44 (Memory & Storage)** |
| **OPT-05: Pop-up Meter Scenegraph Throttling** | 20 individual `ThreadMeter` components updating width/text every 1s | Batch property updates, apply binding guards to avoid redundant re-renders | Reduces iGPU rendering load from 26% towards 15–18% | **Phase 43.3 / Phase 46** |
