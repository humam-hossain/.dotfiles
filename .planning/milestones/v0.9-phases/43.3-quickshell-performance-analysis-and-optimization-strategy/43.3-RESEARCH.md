## Technical Domain Investigation & Architecture Deep-Dive

### 1. Bottleneck Area 1: Idle Syscall Churn (`ResourceUsage.qml`)

#### Root Cause Mechanism
In `restow/quickshell/.config/quickshell/ii/services/ResourceUsage.qml:74-113` [VERIFIED], the timer is configured:
```qml
Timer {
    interval: 1
    running: true 
    repeat: true
    onTriggered: {
        fileMeminfo.reload();
        fileStat.reload();
        ...
        interval = Config?.options?.resources?.updateInterval ?? 3000;
    }
}
```
In QtQuick/QML, imperatively assigning `interval = 3000` inside `onTriggered` of an already-running repeating timer does not reliably rearm the underlying `QTimer` scheduler interval for subsequent ticks [CITED: https://doc.qt.io/qt-6/qml-qtqml-timer.html]. Under certain Qt event loop conditions, the timer continues firing at the initial 1ms interval (clamped by the system timer resolution or Wayland frame cadence to ~1–16ms, or 60–100+ wakeups/sec) [VERIFIED: BENCHMARK.md].

#### Per-Trigger Impact
On every trigger, `ResourceUsage.qml` executes:
- `fileMeminfo.reload()`: reads `/proc/meminfo` [VERIFIED: ResourceUsage.qml:80]
- `fileStat.reload()`: reads `/proc/stat` [VERIFIED: ResourceUsage.qml:81]
- 6 regular expression evaluations against `/proc/meminfo` text (`MemTotal`, `MemAvailable`, `Buffers`, `Cached`, `SwapTotal`, `SwapFree`) [VERIFIED: ResourceUsage.qml:85-91]
- 1 regular expression evaluation against `/proc/stat` text (`cpu\s+...`) [VERIFIED: ResourceUsage.qml:95]
- Dynamic heap reallocation via JavaScript array spread copying:
  ```javascript
  memoryUsageHistory = [...memoryUsageHistory, memoryUsedPercentage];
  swapUsageHistory = [...swapUsageHistory, swapUsedPercentage];
  cpuUsageHistory = [...cpuUsageHistory, cpuUsage];
  ```
  [VERIFIED: ResourceUsage.qml:48, 55, 62]

#### Architectural Resolution (D-02, D-03, D-04)
1. **Declarative Initialization:** Define `interval` declaratively:
   ```qml
   interval: isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)
   ```
   and trigger the initial data fetch via `Component.onCompleted: { root.updateData(); }` [VERIFIED: D-02]. This eliminates the `interval: 1` startup hack permanently.
2. **History Array Heap Gating:** Wrap `updateHistories()` with an `if (isInspectorActive)` guard [VERIFIED: D-03], preventing GC pressure in idle steady-state.
3. **Early Retirement of Legacy Pill (D-04):** `BarContent.qml:110-118` embeds `Resources.qml` (which binds directly to `ResourceUsage`). In Phase 43.4, removing `resourcesGroup` from `BarContent.qml` deactivates visual demand for `ResourceUsage`, leaving it dormant ahead of Phase 44's `MemoryStoragePill.qml`.

### 2. Bottleneck Area 2: Broad-Spectrum Sensor Over-Polling (`HardwareTelemetry.qml`)

#### Root Cause Mechanism
`HardwareTelemetry.qml` defines **31 active FileViews** [VERIFIED: `scripts/phase43-perf-assert.sh:372`]:
- 1 `/proc/stat` (`fileProcStat`)
- 1 `/proc/cpuinfo` (`fileCpuInfo`)
- 2 CPU governors (`fileEpp`, `fileGov`)
- 4 Intel iGPU sysfs files (`fileGpuRc6`, `fileGpuFreq`, `fileGpuCurFreq`, `fileGpuThrottle`)
- 1 CPU Package temperature (`filePackageTemp`)
- 6 Intel Coretemp P-core inputs (`fileCoreTemp2`, `6`, `10`, `14`, `18`, `22`)
- 8 Intel Coretemp E-core inputs (`fileCoreTemp26` .. `33`)
- 2 NVMe temperatures (`fileNvme1Temp`, `fileNvme2Temp`)
- 6 Motherboard WMI platform temperatures (`fileMoboTemp1` .. `6`)

#### The Architectural Mismatch
The status bar pill (`CpuGpuPill.qml`) only displays **3 metrics** [VERIFIED: `CpuGpuPill.qml:20-28`]:
1. `overallCpuLoad` (aggregated from `/proc/stat`)
2. `packageTemp` (from `coretemp/temp1_input`)
3. `gpuLoad` (from iGPU `rc6_residency_ms`)

Yet, `HardwareTelemetry.pollAll()` sweeps all 31 files on every cycle (every 3000ms idle, accelerating to 1000ms active) [VERIFIED: `HardwareTelemetry.qml:483-489`]. Furthermore, when active, `updateFrequencies()` executes a multi-match global regex (`/cpu MHz\s*:\s*([0-9.]+)/g`) across the entire `/proc/cpuinfo` buffer for all 20 threads every 1 second [VERIFIED: `HardwareTelemetry.qml:228-238`].

#### Two-Tier Demand-Gated Sweeping Architecture (D-05, D-06, D-07, D-08)
```
+-----------------------------------------------------------------------------------+
|                        TWO-TIER DEMAND-GATED TELEMETRY                            |
+-----------------------------------------------------------------------------------+
| Tier 1: Stationary Status Bar Pill (3000ms Cadence - IDLE)                        |
|   - /proc/stat (overall CPU load calculation only)                                |
|   - CPU package temp (hwmon / temp1_input)                                        |
|   - Intel iGPU RC6 residency (/sys/class/drm/card1/.../rc6_residency_ms)          |
|   Total FileViews: 3 files (down from 31 files)                                   |
+-----------------------------------------------------------------------------------+
                                         │
                 fastPollingRequests > 0 │ (Popup Opened)
                                         ▼
+-----------------------------------------------------------------------------------+
| Tier 2: Inspector Popup Active (1000ms Cadence - ACTIVE)                          |
|   - Instant synchronous sweep on fastPollingRequests 0 -> 1 (0ms blank lag, D-06) |
|   - 14 per-core temperatures (6 P-cores + 8 E-cores)                              |
|   - 2 NVMe storage drive temperatures                                             |
|   - 6 Motherboard WMI platform / VRM temperatures                                 |
|   - 20 thread frequencies via /proc/cpuinfo regex                                 |
|   - CPU scaling governor & EPP status                                             |
|   - Intel iGPU actual / current clock MHz and thermal throttle status            |
|   Total FileViews: 31 files (only while actively inspecting)                      |
+-----------------------------------------------------------------------------------+
```

### 3. Bottleneck Area 3: Pop-up Scenegraph & Rendering Overhead (`CpuGpuPopup.qml` & `CpuGpuPill.qml`)

#### Root Cause Mechanism
1. **Scenegraph Geometry Recalculation:** `CpuGpuPopup.qml` hosts 20 `ThreadMeter` items [VERIFIED: `CpuGpuPopup.qml:104-180`]. Each item contains:
   - 4 `StyledText` labels (`C#`, load %, MHz, core temp)
   - Background container and inner fill `Rectangle` with dynamic width: `width: parent.width * Math.max(0.0, Math.min(1.0, tMeter.load))` [VERIFIED: `CpuGpuPopup.qml:144`]
   - Dynamic color functions (`root.getLoadColor`, `root.getTempColor`) re-evaluating across all 20 threads.
2. **Micro-Fractional Floating-Point Fluctuations:** Raw CPU load from `/proc/stat` fluctuates at high precision (e.g. `0.234125` vs `0.234198`). Each micro-change invalidates QML binding properties, recalculating scenegraph node geometries and text layouts even though the human eye cannot perceive sub-1% changes [CITED: https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html].
3. **Critical Pulse Animation Gating Bug:** In `CpuGpuPopup.qml:187-207`, `popupCriticalPulse` has:
   ```qml
   running: (HardwareTelemetry.overallCpuLoad || 0.0) >= 0.90 || (HardwareTelemetry.packageTemp || 0) >= 80 || (HardwareTelemetry.gpuLoad || 0.0) >= 0.90
   ```
   [VERIFIED: `CpuGpuPopup.qml:188`]. Notice: **It lacks `root.active`!** If system CPU spikes to 90% in the background while the popup is closed, this infinite `SequentialAnimation` wakes up every frame, animating `criticalPulseOpacity` across an invisible scenegraph [VERIFIED].
4. **Scenegraph Inactivity Leaks:** When `root.active` is false, child QML items and layout passes continue responding to telemetry property updates unless explicitly guarded [VERIFIED: D-12].

#### Architectural Mitigations (D-09, D-10, D-11, D-12)
- **D-09:** Maintain the 20-thread layout to preserve user visual density.
- **D-10:** Condition `running` on `root.active && root.isCritical`. When closed or normal, the animation is disconnected from the frame clock.
- **D-11:** Apply 1% integer deadband quantization:
  ```javascript
  const quantizedLoad = Math.round(rawLoad * 100) / 100;
  ```
  Scenegraph bar widths only re-render when the integer percentage changes.
- **D-12:** Guard all inner item bindings and animations on `root.active`.

## Standard Stack, Patterns, and Pitfalls

### Standard Implementation Stack
- **Language / Framework:** QML / QtQuick (Qt 6, Quickshell `qs` engine) [VERIFIED: `arch/dots-hyprland.sh`]
- **Profiling Engine:** `scripts/profile-quickshell.sh` (Linux `/proc/$PID/stat`, `/proc/$PID/smaps_rollup`, `/proc/$PID/io`, `/sys/class/drm/card1/`) [VERIFIED]
- **Verification Harness:** `scripts/phase43-perf-assert.sh` (5-section automated assertion suite) [VERIFIED]
- **Repository Integrity:** GNU Stow leaf symlinks in `restow/quickshell/` checked via `./arch/dots-hyprland.sh verify --strict` [VERIFIED]

### Recommended Architectural Patterns

#### Pattern 1: Declarative Timer with OnCompleted Startup Fetch
*Problem:* Imperative `interval = 3000` assignment in `onTriggered` fails to re-arm running repeating timers in QtQuick.  
*Solution:*
```qml
Timer {
    id: pollTimer
    interval: root.isInspectorActive ? 1000 : (Config?.options?.resources?.updateInterval ?? 3000)
    repeat: true
    running: true
    onTriggered: root.pollData()
}
Component.onCompleted: {
    root.pollData();
}
```
[VERIFIED: D-02]

#### Pattern 2: Reference-Counted Demand Gating (`fastPollingRequests`)
*Problem:* Sensors are polled continuously even when the UI component displaying them is hidden.  
*Solution:* Use a reference counter on the singleton:
```qml
// In CpuGpuPopup.qml
onActiveChanged: {
    if (active) HardwareTelemetry.fastPollingRequests++;
    else HardwareTelemetry.fastPollingRequests--;
}
Component.onDestruction: {
    if (active) HardwareTelemetry.fastPollingRequests--;
}
```
And inside `HardwareTelemetry.qml`:
```qml
onFastPollingRequestsChanged: {
    if (fastPollingRequests === 1) {
        // Zero-latency first frame (D-06)
        pollTier2Sensors();
    }
}
```
[VERIFIED: D-05, D-06]

#### Pattern 3: Integer Deadband Quantization for Scenegraph Stability
*Problem:* High-precision floating point fluctuations trigger redundant scenegraph geometry recalculations and canvas repaints.  
*Solution:*
```javascript
function quantizePercent(val) {
    return Math.round(val * 100) / 100; // Clamps to 0.01 increments
}
```
[VERIFIED: D-11]

### Critical Anti-Patterns & Pitfalls to Avoid

| Anti-Pattern | Manifestation in Baseline | Mitigation Strategy |
|---|---|---|
| **Timer Interval Mutation in Callback** | `interval: 1` attempting inline `interval = 3000` caused 3,120 read syscalls/s. | Always initialize `interval` declaratively; use `Component.onCompleted` for first-tick data [VERIFIED: D-02]. |
| **All-Sensor Polling in Idle** | Reading 28 unviewed sysfs files every 3s in idle. | Strict two-tier sensor segregation: Tier 1 (3 files) vs Tier 2 (on-demand) [VERIFIED: D-05]. |
| **Unguarded Scenegraph Animations** | `popupCriticalPulse` running in background while popup closed. | Enforce `running: root.active && root.isCritical` on all popup animations [VERIFIED: D-10]. |
| **JavaScript Heap Spread Copying in Loop** | `[...history, val]` allocating new arrays on high-frequency ticks. | Gate history updates on inspector active state (`if (isInspectorActive)`) [VERIFIED: D-03]. |
| **Premature Production Source Edits** | Editing production QML during analysis/planning. | Maintain strict boundary: Phase 43.3 produces consensus and decision records; Phase 43.4 implements code [VERIFIED: CONTEXT.md]. |
