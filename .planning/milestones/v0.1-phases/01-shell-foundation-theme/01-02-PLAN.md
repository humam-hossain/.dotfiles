<objective>
Update the provisioning script to support AUR packages and automatically generate the static Material theme JSON via `materialyoucolor` during deployment.
</objective>

## Tasks

<task id="01-02-01">
<title>Update Provisioning for Theme Generation</title>
<read_first>
- arch/quickshell.sh
- .config/quickshell/scripts/colors/generate_colors_material.py
- ../dots-hyprland/dots/.config/quickshell/ii/scripts/colors/generate_colors_material.py
</read_first>
<action>
1. Modify `arch/quickshell.sh`'s `PACKAGES` array to include `python-materialyoucolor-git`.
2. Change the package installation command in `install_packages()` from `sudo pacman -Sy ...` to use `yay -Sy ...` so that AUR packages can be installed. Wait, `yay` cannot be run with `sudo`. Remove `sudo` before `pacman` and replace `pacman` with `yay`. The command should be `yay -Sy --noconfirm --needed "${PACKAGES[@]}"`.
3. Add a new function `generate_theme()` in `arch/quickshell.sh` that:
   - Creates the state directory: `mkdir -p "$HOME/.local/state/quickshell/user/generated"`
   - Runs the python script to generate colors: `python3 "$QS_DST/scripts/colors/generate_colors_material.py" --color "#7aa2f7" --mode dark --scheme vibrant --cache "$HOME/.local/state/quickshell/user/generated/colors.json"`
4. Call `generate_theme` in `main()` immediately after `symlink_config`.
</action>
<acceptance_criteria>
- `arch/quickshell.sh` uses `yay` without `sudo` for package installation.
- `python-materialyoucolor-git` is in the `PACKAGES` array.
- A `generate_theme` function exists and calls `generate_colors_material.py` with the `--cache` parameter.
- Running `arch/quickshell.sh` successfully creates `~/.local/state/quickshell/user/generated/colors.json`.
</acceptance_criteria>
<verify>
grep -q "yay -Sy" arch/quickshell.sh && grep -q "generate_colors_material.py" arch/quickshell.sh && echo "Provisioning updated"
</verify>
</task>
