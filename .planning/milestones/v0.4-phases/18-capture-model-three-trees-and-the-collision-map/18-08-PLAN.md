<objective>
Finish the tree split for the one package that straddles two trees, give the two hand-stowed packages
real call sites, and move the one authorised constant.

`starship.toml` is the clearest instance of the problem this phase exists to solve: the installer
writes through its symlink with a forced copy, so the repo copy is overwritten while the link
survives — and that loss is not hypothetical, it already happened and the repo has carried upstream's
bytes ever since. Splitting it into `restow/starship/` is what makes every package live wholly in one
tree, which is what makes CAP-01 true.

`qBittorrent` and `smartmontools` have no stow call site at all today — both were stowed by hand, so
a fresh machine never links either one. They also hold the last two folded directory symlinks that
Phase 17's audit found and handed here; this plan gives them their call sites, and plan 18-11 performs
the unfold itself, together with every other live-side operation in this phase.

Adding call sites moves the count a closed Phase 17 assert hard-codes. That constant is the one
authorised edit to that file: the property under test — every call site carrying the literal flag pair
in fixed order — is unchanged, and only the number of sites moved.

This plan is repo-side only: it moves one tracked file, adds three call sites and changes one constant.
It runs no GNU Stow invocation and creates no symlink under `$HOME`. One consequence is worth stating
plainly, because it is visible to the operator: moving `starship.toml` out of the `zsh` package leaves
the existing live link pointing at a path that no longer exists, so the prompt falls back to starship's
defaults until plan 18-11 re-links it. That is a cosmetic, self-correcting interim state, not drift.

Purpose: no package straddles two trees, and no package depends on having been stowed by hand.
Output: `restow/starship/`, three new call sites, and the one authorised constant moved.
</objective>
