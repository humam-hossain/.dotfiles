# restow/ — Installer-Overwrites Tree

Personal dotfile packages managed with GNU Stow where upstream `dots-hyprland` installer primitives collide with symlinks or overwrite content on installation.

## Purpose

Files in this tree represent personal configurations for paths that upstream `dots-hyprland` installs, synchronizes, or overwrites.

Whenever `dots-hyprland` installation runs (via `./arch/dots-hyprland.sh install` or `./arch/dots-hyprland.sh install-files`):
- Either the live symlink in `$HOME` is destroyed and replaced with a real file/directory, **OR**
- Upstream writes straight through the symlink into the repository working tree.

---

## 1. Contract

The upstream installer overwrites into this tree. Every package in `restow/` has a recovery tag determined by its collision outcome in `collision-map.tsv`:
- **`rsync-replace`**: The live symlink was destroyed and replaced with a regular file or directory; the repository copy is untouched. Recovery requires re-stowing the package to replace the real file with a symlink again.
- **`cp-through`**: The live symlink survived, but the installer wrote through it into the repository copy, overwriting personal changes with upstream defaults. Recovery requires discarding the repository modification via `git checkout`, then re-stowing.

### Vocabulary Caveat (D-09)
The tag name `rsync-replace` is fixed by `.planning/ROADMAP.md` for requirement CAP-01. It is used verbatim even though two primitives (`install_file__auto_backup` and the inline `hyprland.conf` rename in `3.files-legacy.sh:51-54`) destroy the symlink using `mv` rather than `rsync`. The tag classifies the **recovery action** (re-stowing), not the specific upstream command.

---

## 2. Recovery Commands

Recovery commands are specific to each package's tag and are enumerated in the table in Section 3 below.

- For **`rsync-replace`**:
  ```bash
  cd restow
  stow --verbose=5 --no-folding -t ~ <package-name>
  ```
- For **`cp-through`**:
  ```bash
  git checkout -- restow/<package-name>/<path>
  cd restow
  stow --verbose=5 --no-folding -t ~ <package-name>
  ```

No `restow-all` script ships in this repository, and the wrapper does not automatically re-stow post-install (D-10). The operator runs the appropriate recovery command after running a `dots-hyprland` install.

## 4. Membership Predicate

The predicate for membership in `restow/` is derived directly from `collision-map.tsv`:
- A package belongs in `restow/` if any file it installs sits at or under a destination row where `symlink_outcome` is `DESTROYED` or `repo_outcome` is `overwritten` (D-05, D-13).
- Prefix matching is enforced: because `rsync --delete` replaces entire directories, any file nested inside an overwritten directory belongs in `restow/` even if the file itself was not singled out by name.
- Only two trees are derived in `collision-map.tsv`: `stow` and `restow`.

## 5. Package Naming Notes (D-25, D-52)

### Duplicated Package Names (`hypr`)
Package naming is not strictly uniform across trees:
- The package name `hypr` exists in both `stow/` (`stow/hypr/`) and `restow/` (`restow/hypr/`).
- `stow/hypr/` contains `custom/` (preserved via `install_dir__ignore_existing`).
- `restow/hypr/` contains `hyprland/`, `hypridle.conf`, and `hyprlock.conf` (destroyed or overwritten by the installer).
- The parent tree (`stow/` vs `restow/`) decides the meaning and lifecycle of the package.

### `restow/starship/` (D-52)
- `restow/starship/` is named for the single file it contains (`.config/starship.toml`).
- Its repository content is currently byte-identical to upstream, accepted as a known loss in commit `2539238`. Phase 18 ships the capture and recovery mechanism; whether personal customizations are kept or merged is an operator choice.
- **Call-site boundary (Q-2):** `arch/zsh_powerlevel.sh` independently stows `stow/zsh` but does **not** stow `starship`. Prompt themes do not own starship configuration.

## 6. Stow Discipline & Banned Flags

All operations in this tree must use `--no-folding` and avoid `--adopt`. See [stow/README.md](../stow/README.md#5-the-banned-stow-flag-and-the-procedure-that-replaces-it) for the `--adopt` ban and the safe replacement procedure.
